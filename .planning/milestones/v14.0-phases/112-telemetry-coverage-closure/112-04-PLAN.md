<objective>
Wire `governor_decision` (D-04) and `message_routed` (D-13) into the runtime ingest dispatch, with
explicit-null normalization on every optional field from the first commit (D-14).

Purpose: this is the seam where TELE-02 failed. Phase 108 declared the `control_verb_swap` route
"code-complete and shipped" from code review; a live gate then found ZERO rows had ever reached
the table, because an explicit JSON `null` on one optional field made `isOptionalString()` return
false, the resolver returned `null`, and the insert was skipped SILENTLY - no exception, no
counter, ingest reporting `dropped: 0` throughout. `governor_decision`'s live data carries an
explicit `null` on `held_reason` in 424 of 646 held rows, 36% of all rows of that kind. The
normalization is not an edge case here, it is the majority shape.

Output: two pure resolver functions, two dispatch cases, and the test block that proves the three
wire shapes. Nothing in this plan is evidence the route works live - that is plan 07.
</objective>

<decided_shapes>
- Resolver names: `resolveGovernorDecisionEvent`, `resolveMessageRoutedEvent`. Both exported
  (the existing `resolveControlVerbSwapEvent` is exported so the test file can call it directly).
- Interfaces: `ResolvedGovernorDecisionEvent { emitter: string; priority: string; spoke: boolean;
  heldReason?: string; timestamp: number }` and `ResolvedMessageRoutedEvent { channel: string;
  profile: string; sender?: string; sessionId?: string; timestamp: number }`. Both declared
  immediately above their resolver, matching where `ResolvedControlVerbSwapEvent` sits.
- REQUIRED fields (a wrong type or absence refuses the whole event):
  `governor_decision` -> `emitter` non-empty string, `priority` non-empty string, `spoke` boolean.
  `message_routed` -> `channel` non-empty string, `profile` non-empty string.
- OPTIONAL fields (must pass `isOptionalString` then `normalizeOptional`):
  `governor_decision` -> `held_reason` / `heldReason`.
  `message_routed` -> `sender`, `session_id` / `sessionId`.
  `sender` and `sessionId` are optional here even though contract section 2.16 calls them required
  - a required field that arrives as an explicit `null` loses the entire row silently, which is
  the TELE-02 failure. Plan 02 already made the columns optional to match.
- snake/camel coalescing on every multi-word field, following `resolveControlVerbSwapEvent`'s
  `d.sessionId ?? d.session_id` idiom.
- `spoke` is a BOOLEAN, not a string - use a `typeof spoke !== "boolean"` check, not a truthiness
  test. A truthiness test would map an absent field to `false` and silently invent a "held"
  decision that never happened.
</decided_shapes>
