## Scope (read this before the tables below)

Per `112-CONTEXT.md`'s Integration Points (line 209): "this phase acquired UI work it did not
have when the roadmap was written." That UI work is narrow and singular:

- **In scope: one new surface for `governor_decision` (D-04).** This is the only Group B kind
  that unconditionally clears D-01's routing bar in this phase.
- **Conditional, NOT specced here: `message_routed` (D-05).** Its build — and therefore any UI
  for it — is gated on a rows/day measurement not yet taken. If that measurement lands the kind
  in this phase, it does **not** automatically inherit the contract below: `message_routed`'s
  fields (routing target/decision metadata, contract §2.16) are structurally different from
  `governor_decision`'s (spoke/held outcome), so a route-and-surface build there needs its own
  short design pass, not a reskin of this component. Flag this explicitly to the planner rather
  than silently extending this spec's component to cover it.
- **No UI: the TELE-03 disposition record (D-10/D-11).** It is a machine-readable const +
  test, checked into CodePulse code, mirroring `RETENTION_DAYS` (`convex/retention.ts:38`) —
  a config file, not a rendered surface. No page, no table, no admin view. If a future phase
  wants an operator-facing view of dispositions, that is new scope, not implied by TELE-03.
- **No UI: TELE-01.** Doc-only edits in `astridr-repo/docs/astridr-contract.md`. Different repo,
  no CodePulse build, excluded per the orchestrator's scope guidance.
- **No UI: Group A kinds.** Provably never emitted; TELE-01 fixes the contract doc, not a UI.

## Spacing Scale

Declared values (must be multiples of 4) — these are the existing Tailwind utility values
already in use across the surfaces this component imitates (`DeliveryHistory.tsx`,
`SwapHistoryList.tsx`, `Settings.tsx`'s notifications tab):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside a badge (`px-1.5`≈6px is the one named exception below) |
| sm | 8px | Row internal gaps (`gap-2`), compact element spacing |
| md | 16px | Card padding (`p-4`), section vertical rhythm (`space-y-4`) |
| lg | 24px | Tab-content vertical rhythm (`space-y-6`) |
| xl | 32px | Not used by this component |
| 2xl | 48px | Gap between stacked `SectionErrorBoundary`-wrapped cards (`mt-12`, `Settings.tsx:958-975`) |
| 3xl | 64px | Not used by this component |

Exceptions: `gap-1.5` / `px-1.5 py-0.5` (6px) — an already-established non-4px convention for
compact badge/icon-label spacing, reused unchanged from `SwapHistoryList.tsx:62` (`gap-1.5`) and
`InboxCard.tsx:108,142` (`px-1.5 py-0.5`, `RiskBadge`/`ProfileBadge`). Not a new exception
introduced by this phase. (Correction: `SwapHistoryList.tsx:96`'s own `Badge` actually uses
`px-1 py-0`, a *different*, smaller override on that one badge — not evidence for this 6px
exception. Dropped as a citation for this row; the 6px convention stands on the `InboxCard.tsx`
citations alone.)

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (table cells, row content) | 14px (`text-sm`) | 400 regular | 1.5 (default leading) |
| Label (timestamps, badges, captions, truncation note) | 12px (`text-xs`) | 400 regular | 1.4 |
| Heading (section eyebrow) | 16px (`text-base`), uppercase, tracking-wide | 600 semibold | 1.2 (`SectionHeader.tsx:12`) |
| Display | not applicable | — | — |

No display-scale numerals are needed — `governor_decision` is a low-volume audit log, not a
metric widget, so there is no hero-number treatment to spec. `Table`'s own default
(`table.tsx:13`) is `text-base`; this component overrides table body/meta cells down to
`text-sm`/`text-xs` the same way `DeliveryHistory.tsx:82-89` does, keeping the un-overridden
`TableHead` at its component default (`text-base`, `font-medium`, `table.tsx:71`).

**Weight cap (exactly 2, not 3):** `badge.tsx:8` bakes `font-medium` (500) into
`badgeVariants`'s base class, applied to every variant including `outline` (`badge.tsx:17-18`,
which adds no weight override) — so the Priority `Badge` this spec calls for would silently
inherit a *third* weight (500) alongside body/label 400 and heading 600 unless overridden.
`SwapHistoryList.tsx:96` confirms the failure mode: its own `Badge` override
(`className="text-xs uppercase px-1 py-0"`) changes size and padding but never touches weight, so
500 survives there. Fix: the Priority `Badge` in this component MUST carry an explicit
`font-normal` override (e.g. `<Badge variant="outline" className="font-normal">`) —
`badge.tsx:42`'s `cn(badgeVariants({ variant }), className)` applies the passed `className`
*after* the variant class, and this project's `cn()` is `twMerge(clsx(inputs))`
(`src/lib/utils.ts:4-6`), which resolves same-group Tailwind conflicts in favor of the
later-applied class — so `font-normal` genuinely wins here, it is not a class that loses the
specificity fight. With that override the component totals exactly 2 weights: 400
(body/label/Priority badge) and 600 (heading).

## Color

This project is **token-driven** (runtime theme switcher, `data-theme` attribute) — CLAUDE.md's
Styling section forbids hardcoded hex. The template's "hex" column is filled with the CSS custom
property each role resolves to instead.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--card)` / `bg-card border-border` | The card surface hosting this section (`Settings.tsx:939` pattern: `bg-card border border-border rounded-xl p-4`) |
| Secondary (30%) | `var(--muted)` / `var(--border)` | Table row hover (`hover:bg-muted/50`, `table.tsx:58`), hairline borders |
| Accent (10%) | `var(--status-ok)` | Reserved for: the "Spoke" outcome icon only (see below) |
| Destructive | `var(--destructive)` | Not used — this surface has no destructive action |

**Focal point:** the Status icon column is the table's visual anchor. It is the *only*
accent-colored element in the entire surface (`--status-ok` on `Check`, held rows deliberately
muted — see below), every column's font weight is otherwise uniform (400, per the Typography
cap above), and it is the leftmost column, so it is both the first thing the eye lands on and the
only thing carrying color. This is a deliberate choice, not an incidental one: an operator
scanning this table needs "did it speak or not" answered before any other field, and putting the
one spot of color there makes that scan a single glance rather than a row-by-row read.

Accent reserved for: **only** the `Check` icon on a `spoke:true` row (mirrors
`SwapHistoryList.tsx:90`'s `text-(--status-ok)` success icon). Explicitly NOT used for:
- **Priority** (`money`/`high`/`normal`/`low`) — rendered as plain text or a neutral `outline`
  Badge, never color-coded by level. Rationale: `InboxCard.tsx:122-126`'s held-item rule states a
  suppressed item's stripe is "never upgraded even for an underlying high-priority event" — the
  same principle applies here in reverse: a `held` decision must never visually read as an alarm
  just because its `priority` was `high` or `money`. Color-coding priority would fight that rule
  — and would also compete with the Status column for the eye's attention, undermining the single
  focal point above.
- **`held` (spoke:false) rows** — rendered with a muted/neutral icon (`EyeOff` or `Ban`,
  `text-muted-foreground`), NOT `--status-warn` or `--status-error`. A held decision is a working-
  as-designed suppression (`held_reason: "focus" | "quiet-hours"`, contract §2.40), not a failure
  — it must not borrow `DeliveryHistory.tsx:71-76`'s red "failed" treatment, which is reserved for
  genuine delivery failures. This is the same distinction `InboxCard.tsx:170-174`'s
  `heldReasonCopy` draws for the pre-existing `inbox` table's held items.

## Component Inventory

One new component, following the `control_verb_swap` routing + surfacing precedent
(`convex/runtimeIngest.ts:1022`, `SwapHistoryList.tsx`) end to end, but hosted and shaped like
`DeliveryHistory.tsx` — the closer analog for a **global** (no `profileId` scoping — the
`governor_decision` contract fields at §2.40 carry no profile field, unlike `controlVerbSwaps`)
read-only decision table.

### `GovernorDecisionLog` (new component, exact filename Claude's discretion)

- **Host:** `Settings.tsx`, `notifications` tab, immediately after the existing
  `<DeliveryHistory />` block (`Settings.tsx:970-975`) and before `<NotificationPreferences />`
  (`Settings.tsx:977-982`) — same card chrome: `<SectionErrorBoundary name="Governor Decisions">`
  wrapping a `<div className="bg-card border border-border rounded-xl p-4 mt-12">`. Rationale for
  this host over a per-profile mount (the `control_verb_swap` pattern): `governor_decision` has
  no `profileId`, so it cannot nest under `Settings.tsx`'s per-profile `AgentProfileRows` the way
  `SwapHistoryList` does — it needs a single global mount, and `notifications` is the existing tab
  already holding the fleet-wide decision/delivery history family (`DeliveryHistory`,
  `NotificationPreferences`).
- **Structure:** `SectionHeader` (title: "Governor Decisions") + shadcn `Table` — 5 columns:
  Status (icon, the focal point — see Color section), Emitter, Priority, Reason, When. Not
  `Tabs` (unlike `DeliveryHistory`, which tabs Email/PagerDuty) — there is exactly one decision
  stream, no sub-source split.
- **Row shape** (from contract §2.40's 4 fields, all required except `held_reason`):
  - Status: `Check` icon (`text-(--status-ok)`) + "Spoke" label when `spoke:true`; `EyeOff` icon
    (`text-muted-foreground`) + "Held" label when `spoke:false`.
  - Emitter: plain text, e.g. `reminder_nudge`, `watch_pulse` (§2.40's enumerated callers).
  - Priority: plain text or a neutral `outline` `Badge` — `<Badge variant="outline"
    className="font-normal">` (the `font-normal` override is REQUIRED, see Typography's weight
    cap above; without it this Badge silently inherits `font-medium`/500 from `badge.tsx:8` and
    breaks the 2-weight cap) — one of `money`/`high`/`normal`/`low`, never color-coded.
  - Reason: `held_reason` value (`"focus"` / `"quiet-hours"`) formatted as prose, same convention
    as `InboxCard.tsx:170-174`'s `heldReasonCopy` (e.g. "held during focus mode"); an em dash
    (`—`) when `spoke:true` (no reason applies).
  - When: `new Date(row.timestamp * 1000).toLocaleTimeString(...)` — **epoch seconds**, per
    `112-CONTEXT.md` D-03's confirmed unit (same conversion `SwapHistoryList.tsx:39-44` and
    `DeliveryHistory.tsx:86` already use for their own `timestamp`/`sentAt` fields).
- **Cap:** bounded list via a new indexed `.take()` query (mirrors `listByScope`/`listGlobal`'s
  `SWAP_HISTORY_CAP` pattern, `controlVerbSwapsFilters.ts:20` — value 20 there; this table's cap
  is the planner's call, same "Claude's Discretion" scope `112-CONTEXT.md` already grants for
  table/column/index naming). Never an unbounded `.collect()` — `events:countByType`
  (`convex/events.ts:310`) is the named anti-pattern to avoid (`112-CONTEXT.md:177`).
- **Truncation caption:** when the list is at cap, an honest `atCap` statement below the table,
  same convention as `SwapHistoryList.tsx:107-111` ("Showing the last N…") — never silently drop
  rows past the cap without saying so.

### States

- **Loading** (`useQuery(...)` returns `undefined`): skeleton block, `h-32 w-full animate-pulse
  rounded-md bg-muted`, identical to `DeliveryHistory.tsx:31-38`'s loading branch (which already
  covers the header via `SectionHeader` staying visible above the skeleton).
- **Empty** (`rows.length === 0`, after loading resolves): centered empty-state block matching
  `DeliveryHistory.tsx:19-29`'s `renderEmptyState()` shape —
  - Heading: **"No governor decisions yet"**
  - Body: **"Decision history appears here once the interrupt governor evaluates its first
    proactive event (reminder, watch pulse, heartbeat, or a similar automated nudge)."**
- **Error:** handled entirely by `SectionErrorBoundary` — no bespoke error UI in the component
  itself. Renders `"Governor Decisions failed to load"` + the caught error's message + a Retry
  button, per `SectionErrorBoundary.tsx:36-59`'s existing fallback. This is the honest
  loading/empty/error triad the constraints require — none of the three states is skipped.
