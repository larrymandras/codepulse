<interfaces>
Contract this plan establishes for every downstream consumer (plans `118-05`, `118-09`, `118-10`):

Each row returned by `list` / `listTrash` is the raw `media` document plus these derived fields:
- `thumbnailUrl: string | null` — resolved server-side. On the `convex-storage` branch this is
  `await ctx.storage.getUrl(row.thumbStorageId)`; on the `local-static-origin` branch it is the
  static server base URL concatenated with `row.thumbRelPath`. `null` when neither field is
  populated or the blob is missing. The UI renders the `ImageOff` placeholder on `null` — it never
  branches on which transport produced the string.
- `hasProvenance: boolean` — `false` when ALL of `prompt`, `model`, `provider` are absent (D-07's
  own definition of a provenance-absent row, matching the `Missing Provenance` filter chip).

The provenance-absent sentinel is the exact string `No provenance recorded` (UI-SPEC's Copywriting
Contract). Where it is produced is a design choice this plan must make and document — see Task 1.

Storage API shape to copy from `convex/avatars.ts:63-85` (the only existing `ctx.storage` usage in
this repo): `ctx.storage.generateUploadUrl()` in a mutation, `ctx.storage.getUrl(storageId)` in a
query.
</interfaces>

  calling it on an already-deleted row is a no-op that returns success, never a second timestamp
  overwriting the original (which would silently extend the 30-day grace period). Add a comment
  stating that this mutation does NOT delete the thumbnail blob — D-08 requires the blob to survive
  until the janitor, precisely so Restore stays whole.
- **`restore`** — args `{ id: v.id("media") }`. Clears `deletedAt` (patch to `undefined`).
  Idempotent on a row that is not deleted.

three are deliberately public because the UI-SPEC's card overlay and Sheet footer invoke them
directly from the browser with `useMutation`, and the alternative (a bearer-gated HTTP route) would
require inventing a browser-side bearer flow that nothing in this repo does anywhere. State the
trust argument explicitly: this is a LOWER-trust surface than ingest — flipping a boolean or setting
a timestamp on an existing row, versus creating new provenance-bearing content — on a
single-operator, tailnet-bounded instance per CLAUDE.md's SEED-008 decision.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → public Convex `mutation` namespace | Every public mutation is callable with no credential by anything that can route to the host (CLAUDE.md, measured 2026-08-11). Three functions are deliberately placed on this side of the boundary. |
| `media` row data → rendered UI | Row fields are agent- and filename-derived free text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-02 | Elevation of Privilege | `toggleStar` / `softDelete` / `restore` as public mutations | accept, scoped | Deliberately public per RESEARCH Pitfall 4 — the UI-SPEC's single-click card actions require it and a browser-side bearer flow exists nowhere in this repo. Scoped by construction: each patches exactly ONE named field on an EXISTING row, none can create a row, none can write provenance, none can delete a blob or a row. The destructive one (`softDelete`) is reversible by design with a 30-day grace. This matches CLAUDE.md's SEED-008 decision that the tailnet is the auth boundary; hardening one module's mutations in isolation is the shape SEED-008 explicitly rejected. |
| T-118-15 | Tampering | `softDelete` called repeatedly to extend the grace period | mitigate | `softDelete` is idempotent — an already-set `deletedAt` is never overwritten, so repeated calls cannot push the janitor's 30-day deadline forward indefinitely. Asserted by a control test (patch NOT called). |
| T-118-16 | Information Disclosure | `absPath` returned to the browser | accept | `absPath` is a host filesystem path returned as a copyable string only; the browser cannot fetch it and D-02 forbids any origin that would serve it. On a single-operator tailnet-bounded instance the path is not sensitive. Documented with an inline comment so no later plan turns it into a fetchable URL. |
| T-118-05 | Tampering (stored XSS) | `recipeMd` returned verbatim by `listModels` | mitigate | The query performs no HTML generation and no transformation; the rendering constraint (plain `<pre>`, `font-mono`, never `dangerouslySetInnerHTML`) is enforced in plan `118-10` and cross-referenced from a comment on this query. |
| T-118-08 | Denial of Service | unbounded reads in the gallery queries | mitigate | Every query is `.take(...)`-bounded at 500; `grep -c "\.collect()"` returning 0 is an acceptance criterion. This is the same defect class that hit this repo twice at Convex's ~4,096-read ceiling. |
| T-118-SC | Tampering | npm/pip/cargo installs | accept | No packages installed. |
</threat_model>
