connected and what tools it currently exposes. Record the enumeration verbatim — tool names as they
appear, not paraphrased.

Two rules govern this enumeration, both drawn from this project's standing lessons:

1. **Pair the enumeration with a known-present control.** In the same run, enumerate the tool
   surface of an MCP server that is known to be connected and functional (any other configured MCP
   server will do). If the control's tools enumerate correctly and OpenArt's do not, the negative is
   about OpenArt. If the control ALSO enumerates empty, the negative is about the enumeration method
   and proves nothing — say so and do not report OpenArt as absent.

2. **Never hand-construct an identifier.** Do not guess a tool name, a server slug, or an endpoint.
   Read the names off the authoritative surface. A well-formed rejection from a real service reads
   exactly like a policy verdict; a guessed identifier can never distinguish "not entitled" from
   "no such name."

Write `.planning/phases/118-studio-media-gallery/118-OPENART-EVIDENCE.md` with:
- `## Method` — exactly how the enumeration was performed and what the control server was.
- `## Pre-auth surface` — the verbatim tool list observed before authentication (expected:
  `authenticate` / `complete_authentication` only).
- `## Control` — the control server's name and its enumerated tool count, proving the method works.
- `## Verdict (pre-auth)` — one of `AUTH_REQUIRED` (only auth tools visible, proceed to Task 2),
  `GENERATION_TOOLS_ALREADY_VISIBLE` (skip Task 2's auth step), or `SERVER_NOT_CONNECTED`
  (OpenArt MCP is not configured in this environment at all — record it and go straight to Task 3's
  fallback branch).

Do not attempt an OAuth flow in this task. Do not paste any token, code, or callback URL into the
evidence file at any point.
