## Trust Boundaries

|----------|-------------|
| host shell → live production container | `docker exec` / `docker inspect` / `docker stats` run against the live self-hosted `convex-backend`. Read-only in this plan, but the boundary is real: a mutating command here reaches production directly. |
| production runtime → committed repository file | `docker` and `gh` output is pasted verbatim into a git-tracked evidence file. Anything the production process prints can become a permanent public-repo artifact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-110-02-01 | Information Disclosure | `110-MEMORY-EVIDENCE.md` | mitigate | This is the phase's one genuine security risk. Production `docker`/CLI transcripts carry secrets: `npx convex env list` prints full `NAME=VALUE` against a self-hosted backend, and `docker inspect`'s `Config.Env` holds `INSTANCE_SECRET`. Mitigated concretely: `npx convex env list` is forbidden by name in Task 1; env vars must pass through a `cut -d= -f1` name-only filter; the file opens with the `108-ENGINE-05-EVIDENCE.md` redaction preamble; and Task 2's acceptance criteria include a credential-shape scan of the finished file before it is committed. |
| T-110-02-02 | Denial of Service | live `convex-backend` container | mitigate | Probing a memory-starved single-node SQLite instance can itself take the dashboard down — an unbounded read is what caused the 2026-08-10 `SystemTimeoutError`. Mitigated by restricting Task 1 to `docker exec grep` against a static binary file, `docker inspect`, and a single `--no-stream` stats sample. No Convex query, no table read, no restart, no env change. |
| T-110-02-03 | Tampering | live instance configuration | mitigate | D-10 forbids enabling any discovered knob without a measured full-cycle comparison. | T-110-02-04 | Repudiation | upstream issue citations | mitigate | An issue's status is a claim that decays. Task 1 requires `state`, `state_reason` and the linked PR's merge state to be re-derived at write-up time with the command and date recorded, so a future reader can tell when the citation was true rather than inferring it. |
