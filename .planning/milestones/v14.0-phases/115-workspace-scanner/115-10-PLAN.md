**PowerShell constraints, each from a recorded incident in this environment:**
- Elevation check MUST use `IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)`. The string
  form `IsInRole('Administrator')` returns `False` even in a genuinely elevated shell, which silently
  blocks the script and, combined with self-elevation, causes an infinite UAC-relaunch loop.
- ASCII-only, UTF-8 **without** BOM. A UTF-8 em-dash parses as a curly quote under PS 5.1 and produces
  "missing terminator". Use only ASCII punctuation inside the `.ps1` files.
- Never redirect native stderr under `$ErrorActionPreference = 'Stop'` — the first progress line becomes a
  terminating error. Wrap native calls as `cmd /c "... 2>&1"` and check `$LASTEXITCODE`.
- Never assign to PowerShell automatic variables (`$HOME`, `$input`, `$PID`, `$args`). The assignment
  errors, but every downstream check then silently runs against an empty value and fabricates PASS/FAIL
  evidence.
- Use `[IO.File]::ReadAllText` / `[IO.File]::WriteAllText` for any in-place file edit. PS 5.1's
  `Get-Content` reads BOM-less UTF-8 as ANSI and mojibakes every non-ASCII character on a round-trip.
- Hand Larry a script FILE to run in an elevated shell, never a long one-liner: console paste-wrapping

  Also note the `!` prefix runs **Bash**, not PowerShell, and cannot satisfy a UAC prompt — so do not hand
  him a `!`-prefixed elevated command.

  console child it execs pops a visible window. `hooks/workspaceScan.mjs` was built to shell out to
  nothing (plan 115-07 greps for `execSync` and requires `0`), which keeps this a non-issue — do not
  introduce one.
