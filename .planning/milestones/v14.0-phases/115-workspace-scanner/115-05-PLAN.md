Four consequences the research did not surface, each of which breaks a naive parser:

1. **Defaults contain BACKSLASHES** (`C:\Users\mandr\Mandras`) — and `notebooklm-mcp`'s uses forward
   slashes. Both separators appear in the same document, so normalization is mandatory, not defensive.
2. **A `${VAR:-default}` token can be a PREFIX of the source, not the whole source** —
   `${FORGE_REPO_PATH:-C:\Users\mandr\forge}\.claude\skills`. So substitution must be an in-place
   token replacement across the string, NOT "if the whole source is a token, take its default."
3. **`cli-gateway`'s defaults are `~`-relative and `./`/`../`-relative** — `~/.claude-alt`, `../codepulse`,
   `../Mandras`, `./`. **`.claude-alt` appears ONLY here, only as `~/.claude-alt`.** Without `~`
   expansion, `.claude-alt` classifies `local-only`, which contradicts D-09's own measured claim that
   `.claude-alt` is Ástríðr-reachable. `./` and `../` resolve against the COMPOSE FILE's own directory
   (`C:/Users/mandr/astridr-repo`), so `../codepulse` → `C:/Users/mandr/codepulse` and `../Mandras` →
   `C:/Users/mandr/Mandras`.
4. **Non-host sources must be skipped, not mistaken for paths** — named volumes
   (`supabase-db-data:/var/lib/postgresql/data`, `astridr-data:/home/...`) and container-internal posix
   paths (`/var/run/docker.sock`). A named volume has no leading `/`, `./`, `../`, `~` or drive letter.

**Env-var substitution constraint (binding).** Take the LITERAL DEFAULT from each `${VAR:-default}`
token; do **not** attempt live substitution, and specifically do **not** read `astridr-repo/.env` to
resolve overrides — this project's absolute rule is never to read `.env` files, and the env-file-guard
hook blocks it anyway. If a `${VAR}` token has no `:-default`, treat that mount source as
unresolvable and skip it. This is a documented, accepted imprecision: `access` reflects the compose
file's DECLARED defaults.

**Naming constraint (RESEARCH Pitfall 2).** The field is `access`, deliberately NOT `astridrCanRead`.
It reflects declared bind-mount coverage, not a live reachability probe: a mount can exist while the
container lacks read permission, or while a Docker/WSL hiccup has left the mount empty. No live probe
is in scope.

checked with `.has()`, and **the ABSENCE of a match is the failure path, not the presence of a bad
match**. That inversion is exactly what separates D-02 from the donor's `SECRET_RE`.
