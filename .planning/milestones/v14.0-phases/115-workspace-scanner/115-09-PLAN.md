**The only permitted deploy command:**

```
npx convex deploy --env-file C:\Users\mandr\convex-selfhost\selfhosted.envfile
```

`--env-file` is **mandatory**. `./CLAUDE.md:18`'s Commands section says `npx convex deploy --yes`, and
that line is stale for the self-hosted instance. `package.json:18`'s `"deploy"` script is literally
`npx convex deploy && npx vite build`. **A bare `npx convex deploy`, `npx convex deploy --yes`, and
`npm run deploy` are all FORBIDDEN here** — each can target the retired cloud deployment
`tidy-whale-981`, frozen 2026-07-15. Phase 112's own threat table names exactly this threat. If the
command prompts, add `-y` **alongside** `--env-file`, never instead of it.

**Verification is on the OUTPUT, not the exit code.** Exit 0 proves the CLI ran, not that it reached the
right backend. Read the deploy output and confirm it names the self-hosted instance
(`127.0.0.1:3210`, or the host the env file declares) and **not** `*.convex.cloud`. Phases 109, 117 and
119 all use this evidence shape (`109-LIVE-EVIDENCE.md`, `117-VERIFICATION.md`, `119-VERIFICATION.md`).

**Two commands that are FORBIDDEN in this plan, for secret-disclosure reasons:**
- `npx convex env list` — against the **self-hosted** backend it prints full `NAME=VALUE` pairs, not
  masked values. That behavior differs from the retired cloud deployment, and running it on a doc's
  say-so has already leaked three keys into a session transcript in this project. If you genuinely need
  the variable NAMES, pipe through a name-only filter (`| cut -d= -f1`) — but you do not need them here.
- `npx convex run <fn> --push` — `--push` DEPLOYS the working tree before running. A read-only existence
  probe with that flag becomes an unauthorized deploy. Use `npx convex run` without `--push`.

**The self-hosted read/write recipe**, when you need to query the live backend directly:
`--url http://127.0.0.1:3210` with an admin key from
`docker exec convex-backend ./generate_admin_key.sh`. Do **not** print the admin key.

**Reachability caveat.** Any probe of the live backend from this host cannot settle questions about
external reachability — loopback, the Docker bridge NAT and WSL are each special-cased. That is not this
plan's concern, but do not draw reachability conclusions from a loopback probe.
