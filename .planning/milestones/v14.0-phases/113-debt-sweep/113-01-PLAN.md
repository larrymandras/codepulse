<objective>
Ship the PRODUCER half of DEBT-05's both-sides guard: split plugin skills onto their own
`claude-code:plugin` origin (D-02) and make `hooks/skillScan.mjs` report, per sub-source, whether
it actually enumerated that source — then put that declaration on the `/scan` wire as
`scannedOrigins` + `scannedOriginsComplete` (D-03).

Purpose: today `collectClaudeCodeSkills` emits the global skills dir AND every installed plugin's
skills under the single `claude-code` origin (`hooks/skillScan.mjs:137,139-141`). When the plugin
manifest read fails, the snapshot still contains `claude-code`-origin rows from the personal dir,
so the origin looks "present" while ~57 plugin rows are missing — and the server's legacy prune
rule deletes them. That is the literal mechanism of the 185 → 131 → 185 oscillation. Research also
established that `scannedOrigins` is sent by NEITHER producer today, so this is not an incremental
change: it stands the manifest up on the wire for the first time.

Output: an origin-split, coverage-reporting `skillScan.mjs`; a `scanner.mjs` that ships the
manifest on both its call sites; and regression tests including the mandated failed-sub-source
control.
</objective>
