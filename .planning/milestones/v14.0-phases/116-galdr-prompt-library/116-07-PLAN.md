  201 -> { ok: true, promptId }

last-fetched copy, no log. A second copy of a prompt body reintroduces exactly the sync problem
the live-fetch design rejects. Losing `/galdr` while the backend is down is the accepted cost,
and it is the decision, not a gap to paper over.

SUBCOMMANDS — exactly these, because D-08 caps the surface:

never in the query string, which lands in server logs.

1. Bare `/galdr` — run `list`, then present the categories with their counts and the favorites.
   Nothing is fetched, nothing is injected, no usage is bumped.

2. `/galdr <slug or search terms> [key=value ...]`:
   a. Parse any trailing key=value pairs out of the arguments first; the remainder is the
      lookup query.
   b. Run `fetch <query>`.
   c. If `match` is null, present every candidate as a numbered line carrying title, category
      and usage count, then STOP and wait for an explicit pick. Do not fetch the top candidate,
      do not fetch the only candidate, do not guess. State the reason inline so a future editor
      does not "improve" it: an injected wrong prompt is indistinguishable from a right one
      until the output is already wrong (D-05).
   d. With a `match`, take its `variables` array AS GIVEN from the server. Do not re-derive the
      variable list by scanning the body — the server computed it with the same function the
      CodePulse UI uses, and a second implementation here is exactly the drift D-09 through
      D-12 forbid.
   e. Fill each variable from the parsed key=value args first. Then ask the user, in one
      message, for every variable still without a value. Do NOT infer a value from the
      surrounding conversation, from the current file, or from the repo — args and explicit
      answers only (D-09).
   f. If any variable is still without a value, including one the user answered with an empty
      or whitespace-only string, REFUSE to inject. Say so and name the specific missing
      variables. Do not inject a literal placeholder, do not substitute an empty string, and do
      not inject a partial body while offering to fix it afterwards (D-10).
   g. Only once every variable has a value: substitute them into the body, inject the result
      into context, then run `bump <slug>`. Usage is bumped on actual delivery, never on a
      listing and never on a look.

3. `/galdr-save <title>`:
   a. Assemble the prompt body from the current conversation, confirm it with the user, write
      it to a temporary file, and pass that path to `save --body-file`. Never pass a multi-line
      body on the command line.
   b. Ask for a category if one is not obvious; the server defaults to `uncategorized`.
   c. On exit code 4 (a 409 collision), report the existing prompt's title and its
      `existingUpdatedAt` back to the user and STOP. Nothing was overwritten and nothing was
      auto-suffixed. Offer two explicit next steps — a different title, or editing the existing
      prompt in CodePulse — and do not pick one for them (D-06).
   d. Delete the temporary body file afterwards.
