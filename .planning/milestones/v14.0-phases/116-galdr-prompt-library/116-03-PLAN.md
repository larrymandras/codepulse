Add the mutations to `convex/galdr.ts`, each as a named exported handler taking
`(ctx, args, now)` where `now` defaults to `Date.now()` at the registration wrapper, plus a
thin `mutation({...})` registration.

`appendVersion(ctx, promptId, body, now)` — private helper. Inserts one `promptVersions` row,
then immediately calls `pruneVersions`.

`pruneVersions(ctx, promptId)` — private helper implementing D-14. Query `promptVersions`
through the `by_promptId` index for that ONE promptId, `.order("desc")`, `.collect()`, then
delete every row from index `PROMPT_VERSION_CAP` onward. Two properties that must be true and
must be stated in a comment: the read is scoped to a single prompt so it can never become a
table scan no matter how large `promptVersions` grows globally; and the delete count per call
is bounded by how many versions that one prompt has, so this is architecturally incapable of
becoming the kind of mass delete that took the self-hosted instance down (repo CLAUDE.md).
Do NOT add `promptVersions` to `RETENTION_DAYS` — that prunes by `_creationTime` across the
whole table and would delete versions of actively-edited prompts as readily as abandoned
ones, which is the opposite of D-14.

`createPromptHandler(ctx, { title, body, category, tags? }, now)` — D-06.
- Derive `slug` with `slugify(title)`. The caller never supplies a slug; one derivation, one
  meaning of "produces an existing slug".
- If the derived slug is the empty string, throw `new ConvexError({ code: "EMPTY_SLUG", title })`.
- Query `prompts` by the `by_slug` index for that slug. This lookup must see archived rows
  too — an archived prompt still owns its slug, and silently reusing it would resurrect a
  confusing collision later. Comment that choice.
- If a row exists, throw `new ConvexError({ code: "SLUG_COLLISION", existingSlug,
  existingTitle, existingUpdatedAt, existingArchived })`. Use `ConvexError`, never a plain
  `Error`: Convex redacts plain error messages to "Server Error" client-side, and both the
  UI and the skill must be able to read `.data` to show the operator what they collided with.
  Nothing is overwritten and nothing is auto-suffixed.
- Otherwise insert the prompt with `usageCount: 0`, `createdAt: now`, `updatedAt: now`,
  `favorite: false`, `archived: false`, and immediately `appendVersion` the initial body
  (D-15: every body-changing write appends one snapshot, and creation is one).
- Return the new prompt id.
- The read-then-write is safe as a uniqueness check because Convex mutations are
  transactional/serializable — two concurrent saves for the same slug cannot both commit.
  State that in a comment; it is the only thing standing in for a unique index.

`updatePromptHandler(ctx, { promptId, title?, body?, category?, tags? }, now)` — D-15.
- Load the prompt; if absent, throw `ConvexError({ code: "NOT_FOUND" })`.
- The slug is IMMUTABLE after creation. A title edit changes the display title only; it does
  not re-slug and therefore cannot collide. Comment why: the slug is the identifier every
  Claude Code session and every "Copy as command" string already holds, so re-slugging on a
  title tweak would silently break live references. Renaming into a new slug is a
  create-plus-archive, not an update — out of scope this phase.
- Patch only the supplied fields, always setting `updatedAt: now`.
- Append a version snapshot ONLY when `body` was supplied AND differs from the stored body.
  A title-only or category-only edit appends nothing. A save that re-submits an identical
  body appends nothing — otherwise a no-op save would consume a version slot and evict a real
  one under the D-14 cap.

`restoreVersionHandler(ctx, { promptId, versionId }, now)` — D-15.
- Load the version; if it is missing or its `promptId` does not match, throw
  `ConvexError({ code: "NOT_FOUND" })` — never restore a version belonging to another prompt.
- Patch the prompt's `body` to the version's body and set `updatedAt: now`.
- Then `appendVersion` with that same body. Restore is append-only: the version trail moves
  forward, never rewinds, and the restored-from row is left exactly where it is.

`archivePromptHandler(ctx, { promptId }, now)` — D-16. Patch `archived: true` and
`updatedAt: now`. Touch no `promptVersions` row. There is no hard delete and no purge
mutation in this module — do not add one.

`toggleFavoriteHandler(ctx, { promptId }, now)` — patch `favorite` to the negation of the
current value (treating `undefined` as false) and set `updatedAt: now`. Does not touch
`usageCount`.

`recordUsageHandler(ctx, { slug }, now)` — the D-discretion usage semantics. Find the visible
prompt by `by_slug`; if there is no match, return without throwing (the same no-op-safe shape
as `recordSkillLaunch` at `convex/registry.ts:678-691`). Otherwise patch
`usageCount: (existing.usageCount ?? 0) + 1` and `lastUsedAt: now`. It must NOT change
`updatedAt` and must NOT append a version — a usage is not an edit, and letting it move
`updatedAt` would corrupt both the grid's recency ordering and the meaning of the version
trail. Comment that explicitly.

Register each as `export const createPrompt = mutation({ args: {...}, handler: (ctx, args) => createPromptHandler(ctx, args, Date.now()) })`
and so on, with `v.` validators on every arg.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| httpAction / React client → galdr mutations | Untrusted title, body, category cross here; `v.` validators plus these handlers are the only gate |
| galdr write path → self-hosted SQLite instance | Delete volume crosses here; the instance cannot absorb mass deletes while serving load |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-116-07 | Denial of Service | `promptVersions` unbounded growth / mass delete | mitigate | `pruneVersions` reads one `promptId` through `by_promptId` and deletes at most that prompt's excess; Task 3's isolation control proves a second prompt's rows survive. `promptVersions` is never added to `RETENTION_DAYS` |
