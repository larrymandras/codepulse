Create `convex/galdrVariables.ts`. It must import NOTHING — no `convex/values`, no
`./_generated/*`, no React. Pure string functions only, so both runtimes and vitest can load
it with zero setup.

Exports:

`VARIABLE_PATTERN_SOURCE: string` — the single regex source string every function in this
module builds a fresh `RegExp` from. Exported so a test can assert the two consumers share
one pattern. Never export a shared `RegExp` INSTANCE: a `/g` regex carries mutable
`lastIndex` state and a module-level instance shared across calls produces
position-dependent misses.

Pattern semantics: two literal open braces, optional inner whitespace, a capture group of
one-or-more characters from the set `A-Za-z0-9_.-`, optional inner whitespace, two literal
close braces.

`detectVariables(body: string): string[]` — every placeholder name in `body`, whitespace
trimmed off the name, de-duplicated, in first-occurrence order. Case-sensitive: `company`
and `Company` are two distinct variables.

`unresolvedVariables(body: string, values: Record<string, string | undefined>): string[]` —
the subset of `detectVariables(body)` whose value in `values` is `undefined`, the empty
string, or whitespace-only. This one function is the shared definition of "unresolved" that
D-10 (skill refuses to inject) and D-11 (UI Copy stays disabled) both mean. Do not define
"resolved" separately anywhere else in the codebase.

`isFullyResolved(body, values): boolean` — `unresolvedVariables(...).length === 0`. Note the
vacuous-truth case is intentional and load-bearing: a body with zero variables is fully
resolved, which is what lets UI-SPEC's "zero-variable prompts skip the fill-in dialog
entirely" rule hold without a special case.

`substituteVariables(body: string, values: Record<string, string | undefined>): string` —
replace each placeholder occurrence with its value in a SINGLE pass using
`String.prototype.replace` with a replacer callback. A value that is `undefined`, empty, or
whitespace-only leaves the literal placeholder text in place untouched (the editor preview
highlights those; no delivery path ever calls this without gating on `isFullyResolved`
first). Single-pass is a security property, not a style choice: a two-pass or
loop-until-stable implementation would let a value containing `{{other}}` be expanded from
whatever `other` happens to hold — write a comment saying so.

Create `convex/galdrVariables.test.ts` alongside it. Required cases:
- a body with no placeholders yields `[]` from `detectVariables` and `true` from `isFullyResolved` with an empty values object
- a repeated placeholder appears once in `detectVariables`, in first-occurrence order alongside its siblings
- inner whitespace is trimmed: `{{ company }}` detects as `company`
- a single-brace `{company}` is NOT detected (control: the same string with double braces IS)
- `unresolvedVariables` reports a variable whose value is `"   "` (whitespace-only) and one whose key is absent, and does not report one whose value is `"0"` (a falsy-looking but legitimate value)
- `substituteVariables` with all values present produces a string containing no `{{` substring
- SINGLE-PASS control: substituting `{{a}}` with the literal value `{{b}}` while `values.b` is `"LEAKED"` produces output containing `{{b}}` and NOT containing `LEAKED`
- `VARIABLE_PATTERN_SOURCE` is a non-empty string and building `new RegExp(VARIABLE_PATTERN_SOURCE, "g")` twice and running each over the same body yields identical match arrays (proves no shared `lastIndex` state)
  </action>

Create `convex/galdrSlug.ts`, pure and import-free like `galdrVariables.ts`.

Export `slugify(title: string): string`. The slug is derived on the SERVER from the title
(plan 116-03's `createPromptHandler` calls it), and the UI's editor drawer calls the same
function to show a live slug preview — so there is one derivation, and D-06's "when
`/galdr-save <title>` produces an existing slug" has exactly one meaning.

Algorithm, in this order:
1. Apply an explicit transliteration map BEFORE any Unicode normalization, because these
   characters do not decompose: lowercase and uppercase forms of eth to `d`, thorn to `th`,
   slashed o to `o`, ae ligature to `ae`, sharp s to `ss`. This project's own vocabulary
   contains them (Ástríðr, Bifröst, Seiðr), so a generic normalizer alone would turn them
   into separator runs.
2. Normalize with `"NFKD"` and strip combining marks (the `̀-ͯ` range) — this is
   what turns accented Latin letters into their base letters.
3. Lowercase.
4. Remove apostrophes and right single quotation marks entirely (so a possessive collapses
   rather than producing a stray separator).
5. Replace every run of characters outside `a-z0-9` with a single hyphen.
6. Trim leading and trailing hyphens.

Return the empty string when nothing survives. Do not throw here — the caller in 116-03
decides what an empty slug means (it refuses the save with an `EMPTY_SLUG` error).

Also export `MAX_SLUG_LENGTH = 80` and truncate the result to it, re-trimming any trailing
hyphen the truncation creates. Reason: the slug is a URL query parameter and a card label;
an unbounded slug from a paragraph-length title is a usability problem, not a correctness
one, but it is cheaper to bound now than to migrate later.

Create `convex/galdrSlug.test.ts` with cases:
- `"Competitor Analysis"` yields `"competitor-analysis"`
- `"Ástríðr's Daily Brief"` yields `"astridrs-daily-brief"` — proves both the transliteration map (eth) and the apostrophe rule
- `"Bifröst  --  Link   Hub"` yields `"bifrost-link-hub"` — proves separator-run collapsing
- a title of only punctuation yields `""`
- a title longer than `MAX_SLUG_LENGTH` yields a string of exactly `MAX_SLUG_LENGTH` or fewer characters that does not end in a hyphen
- the output of every case matches `/^[a-z0-9-]*$/` (a single assertion helper run over all fixtures — proves the ASCII guarantee rather than spot-checking it)
  </action>
