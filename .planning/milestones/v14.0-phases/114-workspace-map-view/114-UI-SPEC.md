## Color

### Existing 60/30/10 (unchanged from the app shell)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `var(--card)` | Page background, coverage-strip card, side-panel background |
| Secondary (30%) | `var(--muted)` / `var(--border)` | Card borders, strip dividers, panel section separators |
| Accent (10%) | `var(--primary)` | Lens-switcher active tab, side-panel close/expand affordance hover state, "expand" cursor-pointer hint |
| Destructive | `var(--destructive)` | Not used this phase — nothing on this surface is a destructive action (read-only map) |

**Accent (`var(--primary)`) reserved for — explicit list, nothing else:** the active lens tab in the
switcher, and the hover/focus ring on interactive canvas nodes (matches `ForceGraphCanvas`'s existing
hover→white-fill + `--primary`-tinted glow shadow, unchanged). Accent is **not** used for department
fill — see below, this is the one place this phase deliberately does not spend its 10%, because the
department channel needs four simultaneously-visible hues, not one saturated highlight.

**Primary visual anchor (Dimension 2 focal point).** The radial map's own **center hub node** (val
14, the single largest node on the canvas, `--foreground`-adjacent neutral fill — see Node Fill
below) is the layout's geometric and visual center; the **lens switcher's active tab** (accent-filled)
is the page's one interactive-chrome focal point. Two anchors, one per state (browsing the map vs.
choosing a lens), consistent with the repo's established "exactly one accent-saturated element per
state" convention (116-UI-SPEC §Color).

### Department fill — new dedicated tokens (resolves the CONTEXT.md constraint)

**Decision: do NOT reuse `--chart-*` for department fill, despite CLAUDE.md's lean toward it.**
Verified against `src/index.css` before choosing: `[data-theme="emerald"]` (lines 190-207) redefines
only `--chart-1`/`--chart-2` — `--chart-3/4/5` silently fall through to `:root`'s light-mode oklch
grays (lines 81-85), a pre-existing gap unrelated to this phase. Worse, `[data-theme="aubergine"]`
(lines 291-328) defines all five `--chart-*` slots as **literal aliases of its own primary/accent/
status colors** (`chart-1`=primary violet, `chart-2`=accent green, `chart-3`=warn amber, `chart-4`=
info indigo, `chart-5`=error red) — every chart slot is already semantically claimed. Reusing
`--chart-*` for four departments would either render broken (emerald) or conflate "this directory is
in the Work department" with "this is a warning" (aubergine chart-3). Three **new** tokens avoid both
problems and keep chart/percentile semantics (`--chart-p50` etc.) untouched for their existing
consumers.

**`--dept-personal` / `--dept-consulting` / `--dept-work`** (new). **Unclassified reuses
`var(--muted-foreground)` — no new token**, which is exactly what "must read as muted, not a fifth
peer color" requires structurally, not just visually.

| Theme | `--dept-personal` | `--dept-consulting` | `--dept-work` | Unclassified (`--muted-foreground`, existing) |
|---|---|---|---|---|
| `cyan` (default) | `#ec4899` (rose-500) | `#22c55e` (green-500) | `#f97316` (orange-500) | `#94a3b8` (`index.css:144`) |
| `emerald` | `#f472b6` (pink-400 — green is claimed by primary `#10b981`/accent `#059669`) | `#8b5cf6` (violet-500) | `#fb923c` (orange-400) | inherited from `:root` — see Open Items |
| `readable` (WCAG-AA) | `#d946ef` (fuchsia-500 — clear of error's `#f87171` red-pink and warn's `#fbbf24` amber) | `#818cf8` (indigo-400 — teal is claimed by primary `#5eead4`, blue by accent `#3b82f6`) | `#fb923c` (orange-400) | `#8892a4` (`index.css:240`) |
| `aubergine` | `#f472b6` (pink-400) | `#22d3ee` (cyan-400 — fully open hue in this theme) | `#fb923c` (orange-400 — clear of warn's `#fbbf24`) | `#9b8a74` (`index.css:303`) |
| `:root` (light "Paperclip") | `oklch(0.65 0.12 350)` (muted rose) | `oklch(0.62 0.12 150)` (muted sage) | `oklch(0.68 0.13 55)` (muted ochre) | `oklch(0.556 0 0)` (`index.css:74`) |

**Light-mode note.** `:root` is a true-monochrome oklch "Paperclip" palette by design. Adding three
low-chroma department hues breaks that purity slightly — flagged explicitly as a discretion call, not
smuggled in. Without them the light theme's map is illegible for department distinction (halo alone
only encodes access, not department), so a small, deliberately muted departure is the better trade.
If Larry would rather keep light mode strictly monochrome and accept that department is only readable
via the side panel there, that is a one-line revert (drop the three `:root` values, department fill
falls back to `--foreground` for all).

**Implementation:** add the four hex/oklch lines to each `[data-theme="X"]` block in `src/index.css`
(cyan block ~132-188, emerald ~190-207, readable ~228-290, aubergine ~291-328) and to `:root`
(~62-131), alongside the existing `--chart-*`/`--muted-foreground` declarations already there.
`amber` (`index.css:209-226`) is skipped — CLAUDE.md confirms it isn't exposed in the theme switcher,
so it's left inheriting `:root` like its other undeclared tokens, consistent with existing practice.

## Component Inventory & Layout

### `/workspace-map` page (`src/pages/WorkspaceMap.tsx`)

- Lazy-imported and routed in `App.tsx`, matching the `Agents`/`Analytics` heavy-page convention.
- `PageHeader` at top: title "Workspace Map", no subtitle CTA (no primary CTA this phase).
- Lens state lives in the URL: `useSearchParams()`, param `lens`, values `"workspace"` (default,
  including when the param is entirely absent) or `"astridr"` (D-12).
- Renders, top to bottom: lens `Tabs` switcher → `WorkspaceCoverageStrip` (workspace lens only —
  the Ástríðr lens has no coverage data to show, D-10) → either `WorkspaceMapCanvas` (workspace lens)
  or `AstridrLensEmptyState` (astridr lens).
- Two independent `SectionErrorBoundary`s: one around the coverage strip, one around the canvas — a
  render fault in the strip must not blank the map and vice versa (`CLAUDE.md` §Patterns).

### `src/hooks/useWorkspaceMap.ts`

Thin wrapper: `useQuery(api.workspace.getWorkspaceMap)`. Returns `undefined` (loading), `null`
(graceful-skip, no snapshot — true-empty state), or the full payload. Follows `useProjectGraph.ts`
directly, per CONTEXT.md's Established Patterns.

### `src/hooks/useArmsProbe.ts`

`useQuery(api.graphSnapshots.listSnapshots)`, then `rows?.some((r) => r.sources.some((s) => s.kind
=== "arms"))`. The one D-13 backend dependency — `listSnapshots`'s return mapping
(`graphSnapshots.ts:317-329`) gains a `sources: r.sources` line; the field already exists on the table
(`schema.ts:1895-1903`), so this is a one-line query-projection change, not a schema migration.

### `src/lib/workspaceMapLayout.ts` (pure functions, independently unit-testable)

- `computeRollups(dirs)` → subtree-aggregated `fileCount`/`totalSize`/`withheldCount` per directory,
  client-side, per D-04. Direct-contents values from the payload are never mutated; rollups are a
  parallel derived map keyed by `(rootId, dirPath)`.
- `buildTree(dirs)` → parent/child structure inferred from `dirPath` segments per `rootId` (root
  itself is `dirPath: ""`).
- `layoutNodes(tree, rollups, expandedSet)` → the deterministic ring/angle/collision assignment (see
  Radial Layout Geometry). Returns nodes with `fx`/`fy` set (not just `x`/`y` — both cooldownTicks=0
  **and** explicit fixed coordinates are required, per the recorded SkillVault lesson CONTEXT.md
  cites) and links (parent→child edges only).
- Pure and side-effect-free by construction — this is what makes D-16's fixture-per-flag + mutation
  test approach straightforward: fixtures feed synthetic `dirs` arrays into these functions directly,
  no Convex mock needed for the layout math itself.

### `WorkspaceMapCanvas` (`src/components/workspace/WorkspaceMapCanvas.tsx`)

- Owns `expandedSet: Set<string>` (node keys, e.g. `rootId + "|" + dirPath`) in component state.
  Initial value: all 53 root-hub keys plus all 333 depth-1 directory keys that themselves have
  children **pre-populated as collapsed** (i.e., the 391-node D-01 load state is the *default visible
  set*, not literally "expandedSet starts empty" — the layout function takes a `visibleDepth` floor
  of 2 rather than deriving everything from click state, so first paint needs no clicks).
- Recomputes `layoutNodes(...)` from `expandedSet` on every change (cheap — pure function over data
  already in memory, no Convex round-trip, per D-02).
- Wraps `ForceGraphCanvas` with **no custom `paintNode`** — reuses the shared default paint entirely
  (fill from `colorFn`, hover→white, dim from `focusSet`, labels at `globalScale > 1.4 || hovered`,
  halo from `communityColorFn`). See Claude's Discretion — resolved, "label density," for why a
  custom paint function is deliberately NOT built.
- `onNodeClick`: opens/updates the side panel for that node (always); if the node has unexpanded
  children, also adds its key to `expandedSet` (reveals the next ring); if already expanded, removes
  it and every descendant key (collapse toggle). Leaf nodes (no children) only affect the panel.
- `onEngineStop`: `zoomToFit(400, 60)` — fires once per layout change (cooldownTicks=0 settles near-
  instantly even with physics off, matching `CodeVaultGraph.tsx:667`'s existing pattern).
- `cooldownTicks={0}` (requires the `ForceGraphCanvas` prop addition above).
- `communityColorFn` degrades gracefully when `accessDerivationOk: false` — halo simply never renders
  (every dir already carries `access: "local-only"` in that state per Phase 115's Pitfall 4
  fallback), no special-casing needed in the canvas component itself.
- Offers the same fullscreen toggle `CodeVaultGraph.tsx:582-605` already implements (`Tooltip` +
  icon button, `h-[600px]` default / `h-[calc(100vh-48px)]` fullscreen) — reused, not reinvented.

### `WorkspaceMapPanel` (`src/components/workspace/WorkspaceMapPanel.tsx`)

- `Sheet` (side="right"), opens on any node click, matching D-09.
- Header: node's display label (masked if privacy on). Body, in order: department `Badge` (dept-

## Radial Layout Geometry (D-08 discretion, resolved)

All coordinates are in `react-force-graph-2d`'s arbitrary force-space units (same space
`ForceGraphCanvas`'s existing `clusterForce` code uses, e.g. its `R = 150` centroid radius) — not
CSS pixels; `zoomToFit` handles screen-space fitting.

**Rings** (radius from center, fixed):

| Ring | Contents | Radius |
|---|---|---|
| 0 | Center hub (1 node) | 0 |
| 1 | Department hubs (4 nodes) | 140 |
| 2 | Root hubs (53 nodes) | 300 |
| 3 | Depth-1 directories (up to 333, visible on load) | 460 |
| 4+ | Depth-2..8 directories (revealed by expansion, D-03) | `460 + 130 × (depth − 1)`, i.e. 590, 720, 850, 980, 1110, 1240 for depths 2–7 (depth 8 continues the same progression) |

**Angular allocation:**

- **Department sector width** — proportional to the department's total directory count
  (Personal 47.6% / Consulting 27.0% / Unclassified 14.2% / Work 11.3% of 360°, ordered by
  descending count starting at 12 o'clock going clockwise), with an **8° minimum floor** per
  department. Non-binding today (smallest, Work, is already ~40.7°) — a protective floor for if the
  department mix shifts.
- **Root sub-sector width, within its department's sector** — proportional to
  **√(root's directory count)**, not linear count. This is the direct answer to "the lopsidedness is
  the design pressure" (CONTEXT.md § Specific Ideas): a root with 4× another root's directory count
  gets 2× the angular width, not 4×, so the two roots holding 1,041 and 601 directories (a third of
  the tree) don't crowd their department's other roots into slivers. **1.5° minimum floor per root**
  — the 19 roots holding ≤10 directories stay a clickable width rather than vanishing.
- **Directory children, at any depth** — split their parent's own allocated angular sector **evenly**
  among currently-visible siblings (not weighted by size). Node *size* already encodes rolled-up
  scale (D-07); weighting angle too would double-encode the same signal and crowd large subtrees'
  siblings unnecessarily.

**Collision handling (fully deterministic, no physics):** when a ring position's per-node arc length
would fall below a minimum click-target width (~14 force-space units, chosen to stay clickable at the
map's typical post-`zoomToFit` scale), the layout function **staggers alternating siblings onto a
secondary radius** — even-indexed siblings at the ring's primary radius, odd-indexed at
`primary + 65` (half the standard 130 per-depth increment). Index-based, not force-based, so it stays
reproducible/screenshot-testable exactly like the primary layout.

**Node size (`val`), sqrt-scaled from rolled-up file count** (area-perceived scaling, matching how
`ForceGraphCanvas`'s default paint already treats `val` as radius):

| Node kind | `val` |
|---|---|
| Center hub | 14 (fixed) |
| Department hub | 10 (fixed) |
| Root hub | `5 + 5 × √(rolledUpFiles / maxRootRolledUpFiles)` → range 5–10 |
| Directory (any depth) | `2 + 4 × √(rolledUpFiles / maxDirRolledUpFiles)` → range 2–6 (2 matches `ForceGraphCanvas`'s own floor, `Math.max(node.val ?? 3, 2)`) |

`maxRootRolledUpFiles` / `maxDirRolledUpFiles` are computed once from the live payload (not
hardcoded), so the scale stays correct as the tree changes.

**Zero-visible-files directories (`fileCount: 0`), resolved:** render at the `val` floor (2) exactly
like any other low-file directory — `withheldCount > 0` on such a node is **not** given a separate
canvas-level visual channel (fill/size/halo already carry three encodings; a fourth was explicitly
rejected in CONTEXT.md for `latestMtime` on the same "keep the encoding to two[-ish] dimensions"
reasoning). The distinction surfaces exclusively through the side panel, which D-09 already mandates
show the withheld-files line on every node where `withheldCount > 0`, regardless of `fileCount`.

## Privacy Masking (D-15, resolved mechanism)

**`maskFilePath`/`maskPath` (`src/lib/privacy.ts:9-17`, `src/hooks/usePrivacyMask.ts:33`) is the
wrong helper for this map's node labels — do not reach for it here.** That utility is built for
multi-segment file-path *strings* and deliberately **keeps the first segment unmasked** ("Keep first
segment + filename, mask middle" — `privacy.ts:12-16`). For most consumers (`FileTree`, breadcrumbs)
the first segment is a project/drive root — not sensitive. For this map, the first segment **is** the
sensitive thing: a Consulting root's `rootId` is itself a client identifier (the exact disclosure
class Phase 115's D-17 exists for). Calling `maskFilePath(rootId)` on a single-segment string is also
a structural no-op — `parts.length <= 2` returns the input unchanged (`privacy.ts:11`) — so it would
silently fail to mask at all for bare root names.

**Resolved mechanism: use `redact()` from `usePrivacyMask()` (`usePrivacyMask.ts:39-42`), not
`maskFilePath`, for every root/directory label on this map**, gated the same way every field there is
(`usePrivacy().enabled && maskPaths`, matching the existing `mp` callback's gate at
`usePrivacyMask.ts:10`).

- **Root hub labels**, when masked: `"{department} root {index}"` (e.g. "Consulting root 3"),
  index assigned by descending rolled-up-file-count within the department, stable across renders.
  Not a bare `redact()` placeholder — 53 identical `"••••••"` root labels would look broken rather
  than intentionally redacted, and roots are the map's primary navigational anchor.
- **Directory labels** (depth ≥ 1), when masked: the plain `redact()` placeholder, `"••••••"`.
  Deep-directory identity carries far less navigational value than root identity for demo/screenshot
  purposes — the reader needs to see structure and scale, not names.
- **Department hubs, the center hub, all counts, all colors, ring position** are never masked — D-15
  is explicit that "structure, counts and colors stay intact." Only string labels are affected.
- **Side panel**, when masked: same substitutions as the canvas label for the selected node's own
  identity fields; counts/dept/access/withheld-notice fields are unaffected (per the rule above).

Off by default (`level: "off"`), so daily use is unaffected — this only engages when Larry turns
privacy mode on for a screenshot/demo, exactly like `FileTree`/`SessionHeader`/`BashLog`.

unconditionally either way ("Scanned Nh ago"), so the reader always has the raw number; the escalation

window before the label would otherwise fire on ordinary day-to-day variance in when the scan
