<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string → page render branch | `?lens=` is the only client-supplied input this phase accepts. It selects a local React branch and never reaches a Convex argument. |
| A failing Convex query → the whole React tree | An unhandled `useQuery` throw unmounts everything, not just the failing widget. Two independent boundaries are the control. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-114-03 | Tampering | `?lens=` search param | mitigate | Closed-set validation to `"workspace"` or `"astridr"` with `"workspace"` as the default for absent **and** unrecognized values; the raw value is never rendered or interpolated. Proven by Task 3's garbage-value test, which asserts the string is absent from the output. 114-RESEARCH.md § Security Domain V5 classifies this as a defensive default, not a security boundary — React's JSX text-node escaping already covers the only rendering path. |
| T-114-18 | Denial of Service | One failing section blanking the entire `/workspace-map` page | mitigate | Two independent `SectionErrorBoundary`s (strip, canvas), proven to isolate by Task 3's two error tests. Recorded precedent: Phase 110's `/analytics` incident and the `heroStats` incident (CLAUDE.md § Patterns). |
| T-114-19 | Denial of Service (client) | Two separate 1.35 MB `getWorkspaceMap` subscriptions | mitigate | `useWorkspaceMap()` is called exactly once on the page and the payload is passed down (D-02); grep-checked in Task 1. |
| T-114-SC | Tampering | npm/pip/cargo installs | accept | Zero package installs this phase (114-RESEARCH.md § Standard Stack); `Radar` comes from the already-installed `lucide-react`. |

V2/V3/V6: none. V4: inherited only — the page adds no Convex function and reopens no auth decision
(CLAUDE.md § SEED-008).
