@CLAUDE.md

**Why the existing tests missed this.** `useProfileSwap.test.ts` is green and exercises the outcome
machine thoroughly, but every case renders the hook ONCE. `unmountedRef` is only latched by a
cleanup→remount cycle, so a single-mount test observes `unmountedRef.current === false` and the
machine advances normally. This is the 2026-07-10 lesson in its exact shape: a test that never
crosses the boundary the property is about cannot fail on it. The new test must remount.

**Do not "fix" this by deleting the guard.** `unmountedRef` exists for a real reason — it stops a
late-resolving dispatch from calling `setOutcome` after the owning component has genuinely
unmounted. The fix is to RESET it on mount, not to remove it.
</context>
