<objective>
Give the trace waterfall the depth OBS-03 asks for: tool executions nested under the LLM call that
triggered them, per-tool timings readable as a share of the turn, and per-turn cache visibility.

Purpose: today `TraceWaterfall` renders one flat lane of LLM-call bars. A turn actually runs as
model responds → tools run → model responds, and nothing on screen shows that. Plans 105-02 and
105-03 have just made the attribution available as REPORTED data (`traceId` + `round` on both
`llmMetrics` and `toolExecutions`) rather than something to infer.

Output: a second-level `Collapsible` per round inside each trace group, tool bars reusing the
existing seconds-domain bar geometry, an honest unattributed bucket, and one shared cache-ratio
helper.
</objective>

<planner_findings>
Verified live 2026-08-03.

**F1 — "LLM call → tool executions" must be implemented as "round → its calls and its tools".**
D-09's literal wording is `trace group → LLM call → tool executions`. But the reported join key that
plan 105-02 introduced is `(traceId, round)`, and a single round can contain more than one
`llm_call` row (a retry, an advisor pass). Attaching tool rows to *one specific* LLM row inside a
multi-call round would be an inference, which D-10 explicitly forbids — "a wrong parent renders
exactly as confidently as a right one with nothing on screen to signal doubt."

Therefore the second `Collapsible` level is the ROUND: `trace group → Round n → [LLM call bars, then
tool bars]`. In the overwhelmingly common single-call round this renders exactly as D-09 describes;
in a multi-call round it stays truthful instead of guessing. State this in a code comment citing
D-09/D-10 so a later reader does not "fix" it back into a per-call attachment.

**F2 — legacy rows have no `round` and that is permanent.** Every `llmMetrics` and `toolExecutions`
row written before plans 105-02/105-03 land has no `round`, and there is no backfill (105-03 F5).
The component must therefore render THREE structurally distinct cases, none of them fabricated:
1. Rows in a trace group that DO carry `round` → grouped into round sub-sections.
2. LLM rows in a trace group with NO `round` → rendered flat directly under the group, exactly as
   today. No synthetic "Round 1".
3. Tool rows with no `traceId`, or with a `traceId` that matches no rendered group, or with a
   `traceId` but no `round` → an explicitly labelled block, never silently dropped and never
   attached to a guess.

**F3 — plan 105-01 already changed both feeder query shapes.** `api.llm.sessionCalls` and
`api.toolExecutions.listBySession` both return `{ rows, truncated, cap }` now, and the truncation
banner for `sessionCalls` already exists in this component. Read the CURRENT file. This plan adds a
SECOND truncation source (the tool query) — surface both in ONE banner rather than stacking two, and
name which side was truncated.

**F4 — `groupCostLabel` is module-local, not exported** (PATTERNS.md's correction to CONTEXT.md,
re-verified against `TraceWaterfall.test.tsx`'s import list). Do not treat that as precedent: D-11's
whole rationale is "one formula, not three drifting copies", so `groupCacheRatio` MUST be exported
and directly unit-tested. Same for the new grouping helper.

**F5 — the test file's Convex mock is single-query today.** `TraceWaterfall.test.tsx:5-15` mocks
`useQuery` as a single `vi.fn()` and the api module with only `llm.sessionCalls`. Adding a second
query requires extending BOTH: add `toolExecutions: { listBySession: "toolExecutions:listBySession" }`
to the api mock and make `mockUseQuery` dispatch on its first argument, so a test can return
different data per query. All 282 existing lines must keep passing.

**F6 — `cacheBadge` and `costLabel` are unchanged by this plan.** D-11 says "existing cache honesty
is preserved unchanged": `cacheBadge` stays a three-state `HIT`/`MISS`/`NO_DATA` that never
conflates an absent field with a zero. Do not touch either.

**F7 — the mount's boundary name stays `"Trace"`.** `src/pages/SessionDetail.tsx:175` mounts
`<SectionErrorBoundary name="Trace">`. The UI-SPEC lists `"Trace Waterfall"` but qualifies it
"unchanged from existing mount". Do not rename it, and do not modify `SessionDetail.tsx` in this
plan at all.
