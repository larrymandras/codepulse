  <action>
Create `src/components/brains/BrainHeaderBadge.tsx`, modeled structurally on
`src/components/voice/SwapBadge.tsx` (Tooltip-wrapped Badge, honest state-dependent copy) but with
two deliberate divergences:

- **Do NOT reuse the Lucide `Brain` icon.** `SwapBadge` already owns it on the Chat page for the
  global runtime axis; this badge is the per-profile axis. Use provider color dots per UI-SPEC §2
  so the two surfaces are visually distinguishable when they legitimately disagree.
- **It is interactive**, unlike `SwapBadge` — clicking opens `BrainPicker`.

Read state from `useActiveEngine()` and `deriveMixedState()`. Rendering rules:

- **Agreement:** a single provider-color dot plus the engine display name at Body 14px.
- **Disagreement:** the literal text "Mixed brains" plus a stacked 3-dot cluster (one dot per
  distinct engine's `PROVIDER_COLORS` value, `-ml-1` overlap). NEVER silently pick one profile's
  value and present it as "the" engine — that recreates the BSC-01 VitalsRail trap this phase
  exists to kill.
- **Clicking from the mixed state** opens the picker with the contextual all-profiles entry scope
  and the per-profile breakdown visible. This is a one-time contextual default from this entry
  point only; the picker still resets to "This profile" on its next open (D-08).
- **Session override vs pinned default (D-02).** A session override appends a `Clock` icon plus
  the remaining-TTL countdown in Label typography, `--status-info` tint. A pinned default appends
  a `Pin` icon, `--muted-foreground` tint. Only ever one — whichever is actually in force.
- **Pending (D-15).** `--status-info` pulsing indicator plus a " · switching to {X}…" suffix
  layered over the still-truthful base label. Never `--primary` for pending.
- **Confirmed-live pulse dot.** A small `--primary` `animate-pulse` dot renders ONLY when the shown
  value is genuinely server-confirmed and is neither pending nor stub.
- **Responsive + accessible.** The text label is `hidden sm:inline` matching the cluster's existing
  pattern, but the button ALWAYS carries `aria-label="Active brain: {EngineDisplayName}"` (or
  `"Active brain: Mixed brains"`), and a `Tooltip` surfaces the same text on hover and focus. The
  cluster already sits inside a `TooltipProvider`, so reuse that pattern rather than adding one.
- **Stub chip.** The dashed `STUB` chip renders next to the engine name when `BRAINS_STUB_ACTIVE`.

Bind no keyboard shortcut. Token-driven colors only, Lucide icons only, no hardcoded hex.

Then write `src/components/brains/BrainHeaderBadge.test.tsx` covering every behavior above, seeding
the engine query from `STUB_PROFILE_ENGINES` for the agreement case and a two-distinct-engine
variant for the mixed case. An all-agree fixture can never reach the Mixed-brains path, so the
mixed test must use genuinely divergent data.
