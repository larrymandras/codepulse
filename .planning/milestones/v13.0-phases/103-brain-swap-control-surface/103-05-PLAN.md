  <action>
Create `src/components/brains/BrainPicker.tsx` as a `Popover` whose content is a cmdk `Command`.
Follow `BrainControl.tsx` structurally — it is the single most important analog in this phase and
already paid three live operator checkpoint rounds for its layout decisions.

**Non-negotiable carried-over lessons.** Popover width `w-96`, never `w-64`. Rows never
`truncate`. Rows grouped under section headers. Catalogue re-fetched on every open, never cached.
The four-state ladder — loading skeleton, fetch error, empty catalogue, filtered-to-nothing.
No keyboard shortcut: `Ctrl+K` is owned by `DashboardLayout.tsx` and `Ctrl+Shift+K` by
`SkillCommandPalette.tsx`; the picker opens by click only.

**Structure, top to bottom inside the popover** (UI-SPEC §3): the stub banner when
`BRAINS_STUB_ACTIVE` (a non-dismissible `--status-warn`-toned strip with a `FlaskConical` icon and
the Copywriting Contract's banner sentence); then the scope selector; then the `CommandInput`
placeholder "Search brains…" which auto-focuses and is the picker's focal point; then three
`CommandGroup`s in the fixed order Subscription, API, Local, each rendering `BrainPickerRow`.

**Scope selector (D-08).** A `toggle-group` with exactly two segments, "This profile" and
"All profiles". It RESETS to "This profile" every time the picker opens and must be moved
deliberately. The single exception: an `entryScope` prop lets the mixed-state header badge open
the picker on "All profiles" once — this is a contextual default from that entry point only, never
a persisted preference, so the next open still resets.

**Catalogue read.** `brainsApi.getCatalogue()`. Bind each `CommandItem`'s `value` to
`entry.id`, NEVER to `entry.name` — cmdk selection is value-keyed and duplicate values cause
double-highlight plus an ArrowDown navigation loop. The fixture deliberately contains two entries
sharing a name so this is testable.

**Dispatch — two genuinely different branches (D-08 amendment / D-16 amendment).**
- "This profile": `brainsApi.dispatchSwap` with the `gateway.model.set` shape from
  `103-CONTRACT.md`, `scope: "profile"`, the picker's `profileId` prop, and the chosen `mode`
  (session override vs pinned default, D-02). This branch is stub-backed and carries the STUB chip.
- "All profiles": open `GlobalSwapModal` and let it dispatch. This branch reaches the LIVE,
  shipped `swap.set` path and must NEVER be routed through `brainsApi` or marked with the stub
  indicator — labelling live data as stub is its own honesty failure.
Do NOT collapse these into one dispatch function that hides the distinction.

**Pending treatment (D-15).** The trigger keeps rendering the actually-active engine from
`useActiveEngine()` and layers a `--status-info` pulsing indicator plus a
" · switching to {X}…" Label-typography suffix on top. Never `--primary` for pending. On failure
the suffix simply drops — there is nothing to roll back because the UI never claimed success.
Do NOT introduce commandId reconciliation or an optimistic pending-state machine; truth is the
plain latest-wins reactive query. Phase 100 already cost two Critical review findings on exactly
that pattern.

**Dispatch call convention.** Do NOT pass a `successMsg` to `useCommandDispatch().dispatch` — an
"ok" ack means accepted, not switched (D-14). Fire the real per-profile success toast from a
separate effect that diffs the previous and new value of the reactive engine query.

Styling: token-driven only, Lucide icons only, no hardcoded hex, no `text-[10px]`.
