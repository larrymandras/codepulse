<objective>
Prove — with executable assertions against the REAL exported functions — that every reader of `metric_type: "events"` and `metric_type: "sankey_edge"` still returns the FULL total once a logical bucket spans multiple rows.

Purpose: research and independent verification concluded that all five readers are already shard-safe and need no code change. That conclusion currently rests on code review alone. If it is wrong anywhere, the phase silently undercounts every analytics number on the dashboard — the exact failure OCC-01 calls out ("a reader that assumes exactly one row per key silently undercounts"). This plan converts the code-review claim into a regression guard.

It also closes a named false-green: `convex/aggregates.test.ts:255-278` (`rollupDaily`) and `:390-401` (`eventCountsByPeriod`) both RE-IMPLEMENT the grouping algorithm inline inside the test instead of calling the shipped function, so they pass unconditionally even if production regresses. The new tests here must call the real exported handlers.

These tests should be GREEN immediately — no production change is required to pass them. If any one of them is RED, that is a genuine discovery: a reader is not shard-safe, and plan 107-03 must be re-scoped before it deploys anything.

Output: `convex/analytics.test.ts` and `convex/aggregates.test.ts`, updated in place. No production file is modified.
