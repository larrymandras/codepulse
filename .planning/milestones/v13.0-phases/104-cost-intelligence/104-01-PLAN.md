<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Convex public `mutation()` | Anyone who can reach the deployment can call `modelPricing.create/update/remove` unless the handler gates it. These mutations set the rate every dollar figure in the product is derived from. |
| operator input → rate field | A free-text numeric rate is untrusted input; a per-Mtok value entered into a per-token field mis-prices by 1e6. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-01 | Tampering | `convex/modelPricing.ts` `create` / `update` / `remove` | mitigate | Reproduce the sibling convention verbatim (`convex/alertRuleCustom.ts:46-48`, `convex/forecasts.ts:143-144`): `const identity = await ctx.auth.getUserIdentity(); if (!identity) throw new ConvexError("Unauthenticated");` as the first two statements of every write handler. Asserted by a unit test and by a grep acceptance criterion. |
| T-104-02 | Tampering | `modelPricing.create` / `update` rate arguments | mitigate | Convex `v.float64()` validators plus an explicit `> 0 && < 1` per-token range check modeled on `forecasts.setBudgetCap`; reject non-`GATEWAY_PROVIDERS` values for `shadowForProvider`; reject duplicate `model` via a `by_model` read. |
| T-104-03 | Denial of Service | any new read added to `convex/modelPricing.ts` | mitigate | The only reads in this file are whole-table `modelPricing` scans (bounded by design, order 10s of rows) and single-row `by_model` lookups. No `llmMetrics` access is permitted here at all — enforced by a grep acceptance criterion — because an unbounded read against `llmMetrics` is the dominant real failure class on this single-node self-hosted instance (CLAUDE.md §Self-Hosted Convex; RESEARCH.md Pitfall 4). |
| T-104-04 | Repudiation | `seedDefaults` | accept | Seeded rows are marked `source: "seed"` versus `source: "manual"`, which is enough provenance for a single-operator deployment; no per-change audit trail is added (`configChanges` is out of scope for this phase). |
