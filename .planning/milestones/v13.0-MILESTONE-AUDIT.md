## DEBT-03 — re-scoped, and why that is not a climb-down

The original criterion asked for the entry chunk under **512,000 uncompressed bytes**. It was
re-scoped (with Larry) to **≤200,000 bytes compressed**, now measured at **163,071 B gzip
(81.5% of budget)**. Three facts made the original unreachable *and* not worth reaching:

1. `react-dom` alone is **452,138 of 534,658** rendered bytes — 85%, irreducible.
2. That leaves ~60 KB for everything else; `@clerk/*` plus transitive `swr` is ~128 KB.
3. The only way to evict Clerk relocates the same bytes behind an extra round-trip for **zero
   rendering benefit**, because `AuthGuard` wraps all content in `<SignedIn>` and nothing
   paints until Clerk initialises regardless.

106-04 had already refused the equivalent shortcut (raising `chunkSizeWarningLimit`) on this
exact principle, so gaming the number would have contradicted the requirement's own standard.
`chunkSizeWarningLimit` was never raised at any point in the milestone.

**Real reduction delivered: 2,042,353 → 534,658 rendered bytes (−73.8%).**

## The failure worth recording — 107 took two tries

107-03 sharded the WRITE target and 107-06 measured the result as **worse** (`VERDICT: FAIL`).
The diagnosis was right and the fix was incomplete: Convex OCC conflicts on documents read
from **or** written to, and the read set was still the whole bucket, so sharding merely made
each bucket ~4.4× wider. 107-07 narrowed the read to a point lookup (**101 rows → 1**) and
contention went to zero.

Two lessons generalise beyond this phase:

- **The test harness was the real defect.** The fake `withIndex()` ignored the index name and
  filter and returned the whole table, so read-set *width* was physically untestable — a
  point lookup and a full scan produced identical results. A wrong fix stayed green. The same
  defect was then found in `events.test.ts`. **This is how 107 failed the first time.**
- **The measuring instrument lied three ways.** `docker logs --since` returns zero lines for
  any window after container start; a large `--tail` silently serves the *rotated* file (a
  previous container instance, with plausible timestamps); and a gap exists between segments.
  The replacement method was calibrated against a known-good answer — it reproduces 107-06's
  published counts byte-for-byte — before being trusted on new data.

Also recorded: hourly OCC counts swing **17× on identical code**, so 107-06's headline
`+70.5%` sits inside the noise band and is annotated everywhere it appears. Its *data* was
sound and its *diagnosis* was correct; only its precision was overstated.

## Tech debt carried forward (none blocking)

1. **convex-backend memory growth — root cause OPEN.** Measured 2026-08-06: `db.sqlite3`
   **byte-identical** while memory went ~7.6 → 31 GiB. Runtime working set, not data volume,
   so retention is not the lever. Mitigated by `ConvexNightlyRestart` (02:00 daily,
   health-gated, verified by running it). See `107-OCC-EVIDENCE.md` § J.
2. **Skill-registry churn.** `computeSkillPrunes` deletes rows for any name absent from an
   incoming snapshot, so a scan that transiently misses the plugin cache silently drops ~56
   live plugin skills until the next full scan. Observed 185 → 131 → 185. Nothing permanently
   lost. Recorded in `106-HUMAN-UAT.md`.
3. **7 astridr event kinds have emitters but no domain route**; **5 more are documented but
   have no emitter at all** (contract drift, fixable in astridr-repo). Scoped in 105's
   `deferred-items.md` — nothing is lost today, all land in `runtime_events`.
4. **`D-106-04-01`** — intermittent `Chat.test.tsx` brain-pill failure. Three hypotheses
   refuted and recorded; deliberately **not** masked with a `waitFor`.
5. **`convex-selfhost/` is not a git repo** — its compose logging block and the restart
   scripts are unversioned.

## What was dropped and why

- **BSC-01 per-agent axis** — scoped out, never built. The only unsatisfied requirement.
- **Clerk lazy-split for DEBT-03** — would move a number without improving load. Rejected on
  the requirement's own established principle.

  `retention.test.ts` protects it because Phase 104 (D-04) re-derives dollar costs from those
  token buckets on every read, so pruning at any horizon destroys re-priceable history. The
  measurement had already shown retention reclaims none of the memory it was meant to fix.
- **A 322-commit `feature/brain-swap` → `main` merge** — the actual goal (stop a daily cron
  POSTing to a deleted deployment) was met by cherry-picking the one relevant commit onto
  `main`. The merge remains a release decision.
