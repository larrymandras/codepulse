127 do not. For comparison, v14.0's close recorded 12/12.

## Findings worth carrying forward

1. **Requirement status drifted badly and silently.** At close prep, 8 requirements
   (`SIGNAL-02`, `SWEEP-01`..`SWEEP-07`) still read `Pending` while their phases were marked
   Complete — and Phase 126 had been deployed and verified on live data the day before.
   Separately, 3 of the 4 `Partial` entries turned out to be **stale notes**, not open work:
   each cell named its own unblocking condition and the condition had already been met.
   This is the mirror image of the documented `phase.complete` false-green: not over-eager
   marking, but no marking at all. **A phase close should re-derive its requirements from the
   code, not leave them to be reconciled at milestone close.**

2. **An automated check can be correct and still miss the point.** 125-13's live E-Stop
   verification found a defect no automated check could: every test asserted the state
   attribute and passed, while an operator staring at the armed screen could not see the 3px
   alarm. "The state is critical" and "an operator can see the alarm" are different
   properties.

3. **Mutation testing earned its place.** 127-07 deleted four carve-out guards one at a time;
   three flipped their tests red, and the fourth (`shouldDeleteClosed`'s `held` check) left all
   24 tests green — a guard nothing protected, which reads as redundant and is exactly what a
   future editor deletes. Closed by `9cd949fd` and re-proven to flip.

4. **A grep-count acceptance criterion is satisfiable by editing a comment.** Three executors
   in Phase 127 did exactly that. Root cause: the GSD planner's own hygiene rule prescribed
   `grep -v '^#'`, which strips `#` comments and is a **silent no-op on TypeScript** (measured:
   raw 25 hits, filtered 25 hits, 671 lines in / 671 out). Fixed in the planner agent and,
   durably, in this repo's `CLAUDE.md`.

5. **The mechanism usually already exists.** Three items carried as open work turned out to be
   already handled — `bifrost.list`'s unbounded read was fixed, `scripts/soak-vitest.mjs`
   already implemented the failure-capture harness proposed for it, and
   `gsd-state-coherence.ps1` exists on this machine despite a memory note recording it as
   absent. All three were carried from notes rather than checked against the code.

6. **Widening an index under an unchanged name is a DROP AND RECREATE.** Settled by reading a
   real deploy's output (127-08); free at 470 rows, an outage-class operation on a large table.
