<objective>
Build the client-only optimistic state machine for drag-triggered lifecycle moves: a `Record<skillName, PendingMove>` map where each entry carries the `commandId` its `enqueueLifecycle` call generated, reconciled against `useLifecycleCommands()` by **commandId** (per `useIntakeFeed.ts`'s proven precedent), status-aware (done clears silently; failed/expired clear + toast; queued/executing stay pending). Expose it (plus the transient dragging-skill identity) through a single React context `SkillControlSurfaceProvider` so consumers (`ScopeRail`, `SkillRow`) read it without prop-drilling through the intermediary list components.

Purpose: This is the crux of UX-03/D-05 — "optimistic move WITH honest rollback." The pending state must be unmistakably unconfirmed and must ALWAYS reconcile to server truth (never a false success). Correlating by commandId (not skillName) is the one thing the existing `latestLifecycleForSkill` badge helper does NOT do, and is required so a second in-flight command for the same skill can never reconcile the wrong drag.
Output: `usePendingLifecycleMoves.ts` (hook + provider + reader hooks `usePendingMove(name)` and `useDraggingSkill()`), plus a direct `renderHook` test file.
</objective>
