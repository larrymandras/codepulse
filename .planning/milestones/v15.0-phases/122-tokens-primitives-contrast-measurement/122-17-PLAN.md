This is the repo's own working instance of the idiom D-25 asks for, and `122-PATTERNS.md` names it as
the template for RIGOR, not for mechanism (it parses one file's AST; this ratchet greps the corpus).
Three things to imitate exactly:

### The mechanism (RESEARCH.md's verified skeleton)

`child_process.execSync` works inside this repo's Vitest environment despite `environment: 'jsdom'` --
jsdom polyfills browser globals; the test process itself is real Node. Verified in research.

`git grep` EXIT CODE 1 means "pattern matched zero files", not an error, and `execSync` throws on any
non-zero exit -- so every call needs a `try/catch` treating `e.status === 1` as an empty result. Verified
in research by running `execSync('git grep -lF "definitely-not-a-real-string-9x7q2" -- src')`, which
throws with `status: 1` and empty stdout. A ratchet that lets that throw escape reports a crash as a
failure and a failure as a crash.

### The six buckets and their sources of truth

| bucket | pattern | exemption source |
|---|---|---|
| palette | `(bg\|text\|border\|from\|to\|via)-(slate\|zinc\|gray\|neutral\|stone)-[0-9]{2,3}` | the five sweep ledgers |
| hex | `(bg\|border\|text)-\[#` | the five sweep ledgers (data-driven colours) |
| duration | `duration-[0-9]+` | none expected |
| violet | `(bg\|text\|border)-(violet\|purple\|fuchsia)-[0-9]{2,3}` | the five sweep ledgers |
| PageHeader | pages under `src/pages/` not importing `PageHeader` | `122-PAGEHEADER-ADOPTION.md`'s named exemption register |
| state honesty | a bare rendered `Loading` string; an em dash in a value slot | `122-LOADING-LEDGER.md` and `122-LOADING-LEDGER-SUBTREES.md` (legitimate typography) |

The state-honesty bucket is the one where a naive pattern produces false positives -- a legitimate
typographic em dash is not a violation. Design that bucket's pattern so it discriminates, and if it
cannot, say so in the header comment and scope the bucket honestly rather than shipping a check that
cries wolf. A ratchet with false positives gets muted, which is worse than not having it.

### Matcher discipline (D-25's own note)
Every literal containing a backslash or `#` uses the fixed-string flag (`grep -F` / `git grep -F` /
`rg -F`) typed exactly as it appears on disk -- never hand-escaped. In a single-quoted BRE, `\\` means
one literal backslash; in `-SimpleMatch` it means two; hand-escaping a Windows path or a `#` literal
has produced a confident zero in this repo before.

And name the unit before quoting any count: `grep -c` is matching LINES per file including `path:0`
rows, `grep -o | wc -l` is OCCURRENCES, `grep -l | wc -l` is FILES.
