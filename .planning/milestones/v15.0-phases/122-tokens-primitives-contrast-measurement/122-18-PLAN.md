### THE COLOUR MEASUREMENT LAW (non-negotiable, and it has already cost this project once)

NEVER parse a computed colour string. Tailwind v4 emits `oklch()` / `oklab()`, and a number-extraction
regex reads the HUE ANGLE as the blue channel. The tell in Phase 120 was an impossible page background
of `rgb(0,0,262)` -- 262 cannot be a channel. Those numbers were quoted to an external reviewer, who
returned a confident "treat this as a release blocker" verdict that had to be retracted.

Rasterise instead: `ctx.fillStyle = colorString; ctx.fillRect(0,0,1,1);
ctx.getImageData(0,0,1,1).data`. The canvas 2D context resolves through the browser's real colour
pipeline regardless of input syntax.

`canvas.fillStyle` silently KEEPS its prior value on unparseable input -- it does not throw and does
not reset. So: set a magenta sentinel (`#ff00ff`) before every assignment, verify the fill actually
moved off the sentinel, and return `null` rather than a guess if it did not. The CALLER must then
REFUSE TO REPORT rather than substituting a default background.

Print the raw intermediate channel values, not only the derived ratio. An impossible value is the
cheapest detector there is, and in Phase 120 it was the ONLY thing that caught the error.

### The pre-phase control (D-27)

Each rendered-result assertion needs a control measured from the PRE-PHASE git state on the same page.
The A11Y-01 before-capture in plan 122-01 was committed BEFORE any `src/index.css` edit, so that
commit is the anchor: `git show <pre-phase-sha>:src/index.css` gives the exact stylesheet the control
must be measured against. Anchor on the EXPLICIT SHA you identify, never on a relative ref like
`HEAD~N` -- this is a shared checkout and a concurrent session's commit makes a relative ref mean
something else entirely.

### The reduced-motion suppressors already in `src/index.css`
A global `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0ms
!important; transition-duration: 0ms !important } }` block at `:509`, plus eight narrower ones, plus
the blanket `[data-theme="readable"]` rule plan 122-03 added. D-12's instruction is to RE-VERIFY these
by population measurement, not to trust them -- a token rewrite is exactly the change that silently
invalidates a prior verification.
