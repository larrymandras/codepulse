### MANDATORY CORRECTION to D-16's literal binding

D-16's prose says bind to `useConvex().connectionState()`. That is a one-shot SNAPSHOT, not a
subscription: `useConvex()` returns the `ConvexReactClient` and `.connectionState()` is a plain method
call, so a component reading it during render never re-renders when the connection drops or recovers.
Bound that way, this plan would replace a fabricated always-green dot with a STALE dot -- the same
defect class wearing a different costume.

The SDK ships the reactive version. Verified in the installed package this session:
`useConvexConnectionState()` is exported from `convex/react`
(`node_modules/convex/dist/esm-types/react/index.d.ts:74`; a bogus-name control returned nothing, so
the probe discriminates). Its implementation
(`node_modules/convex/dist/esm/react/client.js:531-550`) wraps `convex.connectionState()` for the
initial read and `convex.subscribeToConnectionState()` for change notification in React's
`useSubscription` idiom -- i.e. it is exactly what D-16 describes wanting, already built.

`ConnectionState`'s documented shape
(`node_modules/convex/dist/esm-types/browser/sync/client.d.ts:116+`) carries
`hasInflightRequests`, `isWebSocketConnected`, `timeOfOldestInflightRequest`, `hasEverConnected`,
`connectionCount`, `connectionRetries`, `inflightMutations`, `inflightActions`.

**READ THE INSTALLED `client.d.ts` YOURSELF before writing the binding.** RESEARCH.md's assumption
log records `isWebSocketConnected` as the intended field at LOW-MEDIUM confidence -- the field
provably exists, but whether a "connecting" state should show a third colour rather than red is a
design call to confirm against the sibling dot's exact semantics. Do not assume a field name from
this document.

Nothing in `src/` calls either API today -- `git grep -n "useConvex\b|connectionState" -- src`
returns only unrelated `RTCPeerConnection.connectionState` / local voice-call matches in
`useDuplexEars.ts`, `useWarRoomVoice.ts`, `WarRoom.tsx` and `VoiceControlBar.tsx`. Re-run that grep
before concluding anything; and note that a negative from it is a claim about the search string, not
about the codebase.

D-16 explicitly REJECTED the alternative of adding a `convex` key to `convex/integrations.ts`'s
`healthStatus`: a query that answers "is Convex up?" only runs when Convex is up, so it can never
report the failure it exists to report. Do not build it.
