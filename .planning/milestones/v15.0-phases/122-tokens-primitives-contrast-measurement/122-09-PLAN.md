### Convex semantics this design rests on (verified, not assumed)

`useQuery(api.foo.bar, args)` returns `Query["_returnType"] | undefined` -- `undefined` STRICTLY while
loading, per its own doc comment (`node_modules/convex/dist/esm-types/react/client.d.ts:360-403`).
Nothing in the type distinguishes an error: a failing query THROWS synchronously during render and is
caught by the nearest ancestor error boundary. This repo's `SectionErrorBoundary.tsx` is a real
`Component` subclass implementing `getDerivedStateFromError`/`componentDidCatch`, and Phase 121
confirmed the mechanism live -- three real un-injected query timeouts on `/analytics` were caught by
their own boundaries while every other panel kept rendering.

Consequence for this design: `useMetricState` covers `loading` / `ready` / `empty` / `stale` only.
`unavailable` is a CALLER-SUPPLIED flag ("no emitter exists behind this metric"), known statically.
`error` is caught one layer up and is passed to the primitive as an explicit `state` prop by whatever
renders inside the boundary's fallback. The hook must NOT try to infer either.

### The closest in-repo analogs (read them; neither is a wholesale copy)

`src/lib/loomStepState.ts` -- the strongest shape match for BOTH halves of the module:
- `stepStateFrom` (`:28-42`): a precedence-ordered if-chain deriving a discriminated union, with a
  comment block justifying WHY each branch outranks the next. Imitate the per-branch justification.
- `STEP_STATE_COLOR` (`:44-57`): `Record<StepState, string>` where every value is a `var(--token)`
  reference and never a hex or a palette class, with a comment justifying the non-obvious mapping
  (why `pending` gets a neutral rather than a status colour). Imitate exactly.

`src/hooks/useThrottledQuery.ts` (42 lines) -- the hook-file conventions: a small generically-typed
hook with a JSDoc header naming the non-obvious constraint up front.

Stated plainly, per `122-PATTERNS.md`: **no existing hook in this repo takes a bare value plus options
and returns a discriminated state union**, and **no existing component is an empty/no-data panel**.
`useLiveState.ts` was checked and rejected (a `useReducer` WebSocket subscription, wrong shape);
`eventIcons.ts` was checked and rejected (open-ended string keys, raw emoji icons -- this repo is
Lucide-only); `categoryColors.ts` was checked and rejected (explicitly a USER-DATA palette, the
opposite of a token vocabulary). You are composing two partial analogs, not copying one.

`src/components/GlassPanel.tsx` (29 lines) -- the generic panel wrapper `EmptyState` will render
inside at panel scale; it is pure chrome and carries no state logic.
`src/components/ui/skeleton.tsx` (14 lines) -- `bg-muted`-shaped placeholder; the `loading` state at
panel scale routes through a skeleton shaped like the content it replaces, not through `EmptyState`'s
copy+icon rendering. The shared module encodes that boundary.

### Design law binding this module
- `"no signal yet"` is the FIXED empty-state phrasing.
- Icons are Lucide only (`CLAUDE.md`).
- Every tone value is a `var(--token)` reference. Never a hex, never a palette class.
- Depth comes from shadow, never glow.
