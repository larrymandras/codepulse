<objective>
Lay the two foundations both janitors stand on: a cursor-advance helper that works on
application fields, and the schema/index changes that let one index serve each janitor's
two steps.

Purpose: `partitionBatchForPrune` is the ONLY tested implementation of "a skipped row still
advances the cursor" in this repo (D-08). It currently hardcodes `doc._creationTime`, and both
new janitors cursor on application fields (`createdAt`, `closedAt`, `dismissedAt`). Without
this generalization each janitor would hand-roll the loop and reintroduce the exact head-rescan
defect `retentionCursor.ts`'s module docstring is a writeup of.

Output: a backward-compatible `partitionBatchForPrune`, its tests, and three index changes plus
one new field in `schema.ts`.
</objective>

  <behavior>
    - Default path, no third argument: `toDelete` and `lastCreationTime` are exactly what they
      are today, for every existing case (this is the regression control — it must be able to
      fail, so assert concrete values, not just "is defined").
    - Default path additionally returns `lastCursorValue` equal to `lastCreationTime`.
    - Extractor path: given `(doc) => doc.createdAt`, `lastCursorValue` is the `createdAt` of the
      LAST iterated doc, and `lastCreationTime` is still the `_creationTime` of the last iterated
      doc — the two are independent and both correct.
    - All-skipped batch with an extractor: `toDelete` is empty AND `lastCursorValue` is the last
      doc's `createdAt`, NOT null. This is D-08's trap and the reason this task exists.
    - Empty batch: both `lastCreationTime` and `lastCursorValue` are `null`.
  </behavior>
  <action>
    Widen `partitionBatchForPrune` with an optional third parameter `cursorField?: (doc: T) =>
    number` and add a third return key `lastCursorValue: number | null`, computed in the SAME
    loop from EVERY iterated doc (deleted or skipped), falling back to `doc._creationTime` when
    no extractor is supplied.

    Do NOT rename or repurpose `lastCreationTime` — `retention.ts:352` and
    `summarizeOverhangProbe` both depend on its current meaning, and a renamed-but-same-shape
    field is the change most likely to pass typecheck and silently alter the nightly prune.
    Adding a key is purely additive; the existing two-argument call site needs no edit at all.

    Keep the generic bound `T extends { _id: unknown; _creationTime: number }` as-is — real
    Convex documents always carry `_creationTime`, so nothing is lost, and relaxing the bound
    would silently permit a caller that has no default cursor.

    Extend `partitionBatchForPrune`'s docstring with a short paragraph naming Phase 127's use:
    both new janitors cursor on application fields (`createdAt`, `closedAt`, `dismissedAt`),
    which is why the extractor exists, and why hand-rolling the loop per janitor was rejected.

    Add a new `describe` block in `convex/retentionCursor.test.ts` covering the five behaviours
    above. The default-path assertions are the CONTROL: they must be written so that a defect in
    the extractor plumbing which broke the default path would turn them red.
