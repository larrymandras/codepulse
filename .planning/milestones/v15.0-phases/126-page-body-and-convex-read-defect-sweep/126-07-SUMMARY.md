### Confirmatory live-DOM mutation test (measurement-only -- no source file touched)

To go from "rows are compressed inside this specific container" to a named CSS mechanism, before writing any fix, two mutation hypotheses were tested directly on the LIVE RENDERED PAGE via a throwaway Playwright script (`page.evaluate`, never touching `AlertRulesEngine.tsx` -- deleted after use, not part of any commit):

```
BEFORE {"containerScrollHeight":2145,"containerClientHeight":500,"rowHeights":[33,33,33,33,33]}
AFTER overflow:visible on rows {"containerScrollHeight":5135,"containerClientHeight":500,"rowHeights":[79,79,79,79,79]}
AFTER flex-shrink:0 on rows {"containerScrollHeight":5135,"containerClientHeight":500,"rowHeights":[79,79,79,79,79]}
```

Both mutations -- removing `overflow: hidden` from each row, and separately setting `flex-shrink: 0` on each row (container's own `overflow-y-auto`/`max-h-[500px]` left untouched in both cases) -- independently restore every measured row to **79px**, matching the correctly-rendered custom row exactly. This is the CSS Flexbox `min-size: auto` interaction (Flexbox spec S:4.5): a flex item whose own `overflow` is not `visible` has its automatic minimum main-size resolved to `0` instead of its content-based minimum, so with `flex-shrink: 1` (Tailwind's unset default -- confirmed via `getComputedStyle(container.children[0]).flexShrink === "1"`) and 65 rows' combined natural height (~5,135px measured) exceeding the container's `max-h-[500px]` (500px, confirmed via `getComputedStyle(container).maxHeight === "500px"` and `container.clientHeight === 500`), the shrink is distributed across every row down to 33px, well below content size, with nothing (min-height was `auto`, which resolved to a floor of `0` because of `overflow-hidden`) to stop it. `overflow-y-auto` still functions -- `containerScrollHeight: 2145` pre-mutation shows the container is not itself failing to scroll, it is that flex-shrink already crushed the rows BEFORE the browser ever needed to decide whether to scroll.

### Conclusion (Task 1)

**Mechanism named, WITH the measurement that established it:** `overflow-hidden` on the row container removes its content-based automatic minimum height (CSS Flexbox `min-size:auto` rule), and the unconstrained default `flex-shrink: 1` then compresses every row inside `.custom-scrollbar`'s `max-h-[500px] overflow-y-auto flex flex-col` container from its natural 79px down to 33px -- confirmed by (a) the one row living OUTSIDE that container rendering correctly at 79px with an otherwise-identical markup, and (b) two independent live-DOM mutations (`overflow: visible`, `flex-shrink: 0`) each independently restoring every row to 79px. The Radix ScrollArea lead is ruled out by the logged ancestor chain (zero `data-radix-*` attributes, no Radix primitive anywhere between the list container and `<body>`).
