<planner_corrections>
**1. The separator's line numbers in its todo are STALE.** The todo cites
`src/layouts/DashboardLayout.tsx:458,463`. Read live 2026-08-24, the nav is at `:482` and the
separator at `:487`:
```tsx
<nav className="flex-1 overflow-y-auto py-2 px-2" aria-label="Main navigation">
  {navGroups.map((grp, i) => {
    ...
    {i > 0 && <Separator className="my-2 mx-3" />}
```
Find the code by its content, not by the todo's line numbers.

**2. Prefer the wrapper-padding remedy over `w-auto`, and verify whichever you use by measurement.**
The todo offers two: drop `mx-3` and inset via padding on the wrapper, or add `w-auto` alongside
`mx-3`. Prefer the first. shadcn's `Separator` carries `data-[orientation=horizontal]:w-full`, which
is a VARIANT-prefixed utility; `cn()`/`twMerge` will not treat a plain `w-auto` as the same key and
will not drop it, so both land in the class list and the cascade decides — and a variant-prefixed
utility generally wins. `w-auto` may therefore be a silent no-op that looks like a fix. Wrapping the
separator in a `px-3` box and dropping `mx-3` makes `w-full` resolve inside a narrower containing
block, which is a width change rather than a specificity bet. If you use `w-auto` anyway, the
measurement in Task 2 is what has to prove it, not the class list.

**3. `overflow-x-hidden` is forbidden here.** It hides the symptom and keeps the overhang, so
anything that legitimately needs the last 3px gets clipped later with no signal. The todo says so and
this plan is binding on it.

**4. A `gateOrSkip` SKIP is not a measurement.** The header block calls `gateOrSkip`, which calls
`test.skip()` when the Clerk sign-in gate renders. Every number this plan records must come from a
run that actually rendered the app. Per `package.json`'s own `test:e2e:noauth:help`: start the noauth
server FIRST in its own terminal, issue the empty-string env assignment from GIT BASH and never
PowerShell (PS 5.1 deletes a variable assigned `''`, silently leaving the Clerk gate live), and point
Playwright at 5181 — `playwright.config.ts`'s `webServer` is hardcoded to 5173 and will report itself
healthy while the specs target a different port.

**5. Check whether `StatusBadge` forwards unknown props before putting `data-testid` on it.** If it
does not, put the attribute on a wrapper element inside `SystemChip` rather than assuming. An
attribute that never reaches the DOM produces a wait that always times out — which, because the wait
is fail-don't-skip, would at least be loud rather than silent, but it is still an avoidable hour.
</planner_corrections>
