<interfaces>
**The single most important correction in this plan.** D-11's decision text says "reading the same
`by_scope` index at `scope: null`". Implementing that literally returns zero rows, forever,
silently. Verified in `109-RESEARCH.md` section D.10:

- `convex/schema.ts` (~:2093-2124): `scope: v.optional(v.string())`, with the schema's own comment
  reading "explicit profileId when scoped, ABSENT when global"; index `by_scope` on
  `["scope", "timestamp"]`.
- `convex/runtimeIngest.ts` (~:236-248, ~:401-421): `resolveControlVerbSwapEvent`'s
  `normalizeOptional()` converts every `null` to `undefined` before `record` is called, with an
  in-code comment stating Convex's `v.optional(...)` accepts an omitted key or `undefined` but
  rejects an explicit `null` outright. A stored global-swap document therefore never has
  `scope: null` — the key is simply absent.
- Convex's own docs (docs.convex.dev/database/types): an index query on `undefined` matches
  documents that do not have the field, and `undefined < null < all other values`.

The correct implementation is `q.eq("scope", undefined)`.

Existing sibling to mirror exactly (`convex/controlVerbSwaps.ts:76-87`): `listByScope` takes
`{ profileId: v.string() }`, pins `by_scope` with `q.eq("scope", args.profileId)`, orders `desc`,
and takes `SWAP_HISTORY_CAP`.

`SWAP_HISTORY_CAP = 20` is exported from `convex/controlVerbSwapsFilters.ts:20` and already
imported by `controlVerbSwaps.ts:3`. `isBrainSwap<T extends { verb: string }>(row: T): boolean`
(`controlVerbSwapsFilters.ts:22-31`) is the export-style precedent for the new helper.

The client-side row type is `SwapHistoryRow` in `src/hooks/useControlVerbSwaps.ts` — do NOT import
it into `convex/`. Keep `mergeSwapHistory` generic over `{ _id: string; timestamp: number }`.
</interfaces>
