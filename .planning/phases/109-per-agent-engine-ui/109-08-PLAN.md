**The WR-02 import boundary — the one cross-cutting constraint this plan must not violate.**
`convex/controlVerbSwapsFilters.ts` exists solely because `convex/controlVerbSwaps.ts` imports
`internalMutation`/`query` from `./_generated/server`, so any browser code value-importing a
constant or predicate directly from that file pulls the whole Convex server runtime into the client
bundle — a real defect found at RUNTIME after 108-06 shipped. `controlVerbSwapsFilters.ts` is the
ONLY legal import path for `isBrainSwap` / `SWAP_HISTORY_CAP` / `mergeSwapHistory` from browser
code. A re-export from `controlVerbSwaps.ts` would let the defect return silently.

**The existing hook** (`src/hooks/useControlVerbSwaps.ts`): wraps
`useQuery(api.controlVerbSwaps.listByScope)`, coalesces loading and empty into one honest empty
default, never returns `undefined`, and skips the query outright when `profileId` is `undefined`.
It also exports `filterBrainSwaps`, `describeSwapOutcome` (`:90-108`) and re-exports
`SWAP_HISTORY_CAP` (`:24`). `SwapHistoryRow` is declared there.

**The renderer to reuse rather than reimplement** (`GlobalSwapModal.tsx:277-333`,
`SwapHistorySection`). Its own docstring at `:270-276` states it is "the intended reuse seam for
Phase 109's real per-profile host, not test-only scaffolding." Its shape: an honest
`if (profileId === undefined) return null;` gate (`:284-286`), `filterBrainSwaps(rows).slice(0, SWAP_HISTORY_CAP)`,
an empty-state `<p>`, a mapped row list keyed by `_id` calling `describeSwapOutcome(row)`, and a
truncation caption at `:326-327` doing the singular/plural correctly. Its current mount
(`GlobalSwapModal.tsx:630-639`, `<SwapHistorySection profileId={undefined} />`) is kept mounted
deliberately "so the component/hook stay exercised" — do not delete that mount.

**The Collapsible composition precedent — UI-SPEC section H's "this is its first consumer" claim is
factually wrong.** Six files already import `@/components/ui/collapsible`;
`src/components/reminders/ReminderList.tsx:668-705` is the closest analog (a per-section disclosure
inside a list). The house pattern: `Collapsible` wrapping a local `useState` boolean via
`open`/`onOpenChange` (no `defaultOpen` usage anywhere in this repo), `CollapsibleTrigger asChild`
wrapping a plain `<button type="button">` with a rotating Chevron, and `CollapsibleContent` holding
either an empty-state `<p>` or the mapped list.

**The Settings host** (`src/pages/Settings.tsx:246-339`): one `.map()` over `profileConfigs`; each
row has `c.profileId` already in scope, and after plan 109-04 already resolves its engine through
`useResolvedBrain`. The new section is a sibling block rendered directly beneath the row's `<div>`,
inside the same `.map()`, indented `md` (16px).

**UI-SPEC section H's copy, verbatim:**
- Trigger: `[Chevron] [History icon] "Swap history" [count badge]` — e.g. "Swap history (12)", the
  TRUE pre-truncation combined count, never rounded and never capped.
- Row: `[outcome icon] [time] [GLOBAL badge, global rows only] [target -> resolved] [outcome label]`.
- `GLOBAL` badge: `Badge variant="outline" className="text-xs uppercase px-1 py-0"` — same
  treatment as the header badge's existing "Global" chip. Scoped rows carry NO badge; the absence
  IS the "this profile's own swap" signal.
- Pinned note (above the list, below the trigger): Label typography, `Pin` icon,
  `--muted-foreground` (informational, NOT `--status-warn`):
  "This profile is pinned — global swaps below did not change its engine."
- Empty state: "No swaps recorded yet for this profile — includes both direct swaps and global overrides."
- Truncation at cap: "Showing the last 20 combined swaps (per-profile + global) — earlier swaps may exist."
- Under cap: "Showing {N} swap{s} (per-profile + global)."
- Default state: COLLAPSED. Several profiles each with an expanded section would make the Settings
  page unusably long on first load.
