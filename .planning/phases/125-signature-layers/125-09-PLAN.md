<planner_corrections>
**1. Use `useConvex().query(...)`, not `useQuery`.** D-05 says ONE bounded read on mount.
`useQuery` is a live subscription that re-runs whenever matching rows change, which for
`runtime_events` is continuous — that is a subscription wearing a read's costume. An imperative
one-shot honours D-05 literally, and it also removes the `useQuery`-throws-unmounts-the-tree
hazard: a rejected promise is catchable, and a caught failure lands in the already-designed
`unavailable` state.

**2. The trace's merge identity, stated with its failure mode.** UI-SPEC's three paths (a)/(b)/(c)
were about the NUMERAL; D-17 retired that question. The trace still needs a merge rule, and it gets
a deliberately modest one: drop a buffered live event from the merge if a backfill row has the
EXACT same `eventType` AND the exact same `timestamp` float. This works because RESEARCH R-1
established that the WS payload and the eventually-stored Convex row carry the SAME producer float
for buffered-path events (`telemetry.py:214`, assigned once at `TelemetryEvent` construction) — so
there is no cross-clock comparison anywhere in this rule. Do NOT floor or round either side; the
stamps are fractional and flooring would manufacture the ambiguity it pretends to resolve.
Its exact failure mode, which must be written in the code comment, not just here: two genuinely
distinct events of the same type carrying an identical float would merge to one, under-drawing one
blip. That is acceptable for a qualitative trace and would NOT be acceptable for the count — which
is precisely why the count does not use this rule.
A watermark partition was considered and rejected: it would drop every `send_live()`-only violet
event that predates the watermark, since those are never in the backfill at all.

**3. `run.blocks` may still arrive twice even after plan 125-03 ships.** The client guard stays
regardless, so CodePulse is not silently dependent on a specific Ástríðr build being deployed —
D-19 says so explicitly. Test both the doubled and the single-delivery cases.
</planner_corrections>
