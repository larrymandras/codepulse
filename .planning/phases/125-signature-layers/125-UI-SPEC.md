## Signal Horizon Contract (SIGNAL-01)

**Component:** a 2px shell line, one instance, rendered inside `DashboardLayout.tsx` — every route inherits it because the layout is shared.

**Integration point** — between `<header>` (`DashboardLayout.tsx:840`, currently `border-b border-border`) and `<main>` (`:1001`). **Decide at plan time** whether the horizon replaces that `border-b` outright or sits as a new element beneath it (124 deliberately left this slot clean for 125, per `124-CONTEXT.md:372-373` — not a UI-SPEC decision, a planner sequencing call, flagged here so it isn't missed).

**Resting state — aurora gradient** (fixed by the sketch, `shell-and-dashboard.md:47-56`):
```css
.horizon {
  height: 2px;
  background: linear-gradient(90deg, var(--aurora-a), var(--aurora-b) 40%, var(--aurora-c) 75%, var(--aurora-a));
  background-size: 300% 100%;
  animation: aurora-drift 90s linear infinite;
}
@keyframes aurora-drift { to { background-position: 300% 0; } }
```

**Event packets** — 48px wide, 620ms travel, using the house easing token `--ease-house` (NOT the sketch's `--ease-out` name — `src/index.css:57`, F-2's naming correction):
```css
.packet {
  position: absolute; top: -1px; height: 4px; width: 48px; border-radius: 2px;
  background: linear-gradient(90deg, transparent, var(--pk));
  box-shadow: 0 0 12px color-mix(in oklab, var(--pk) 60%, transparent);
  animation: travel 620ms var(--ease-house) forwards;
}
@keyframes travel { from { left: -60px; opacity: 1; } to { left: 101%; opacity: 0.4; } }
```
`--pk` is set per-packet from the D-06 hue map (below) — machine = `var(--primary)`, Ástríðr = `var(--astridr)`, error = `var(--status-error)`.

**State overrides** (highest priority first). **Fail-closed by design:** the horizon defaults to a visibly non-calm state whenever E-Stop's true status is not positively known, rather than defaulting to the calm aurora. The aurora resting state is reachable ONLY via an explicit, fresh, well-formed `estop_state` snapshot confirming disarmed — never by absence of contrary information. This closes a gap the first draft left open: a socket that is connected but has not yet delivered its first `estop_state` snapshot previously matched none of the four original states and fell through to the calm aurora, which could render "all clear" while E-Stop was actually armed.

1. **Critical / E-Stop armed** — 3px, solid crimson (`--status-error`), no gradient, no drift. Triggered by a valid `estop_state` snapshot (D-01/D-02, below) reporting armed.
2. **Warn** — solid amber (`--status-warn`), no drift.
3. **Unknown / awaiting snapshot** — same visual treatment as Offline below (dashed, neutral) — reused rather than inventing a second look, since both communicate "not confirmed calm". Entered:
   - on mount, before the first `estop_state` message of the session arrives;
   - on **every** WS reconnect (`WSStatus` transitioning out of `"disconnected"`/`"reconnecting"`, `AstridrWSContext.tsx:30`), not only the first page load — D-02's "on connect" push means a reconnected tab is exactly as unconfirmed as a fresh one until its own snapshot lands;
   - via a **freshness timeout**: if no `estop_state` message (snapshot or transition) has arrived for a bounded interval while the socket remains connected, fall back to unknown even though the socket never dropped. No design-law source pins an exact duration — this is a discretionary default for the planner/executor to set (e.g. in the tens of seconds), tunable, not a validated figure;
   - on a **malformed or unparseable** `estop_state` payload — stays unknown, never falls through to resting or to whatever state preceded it. A bad payload must never be silently treated as "no change".
   Transitions OUT of unknown only on receipt of a well-formed, current `estop_state` snapshot (→ critical, warn, or resting depending on its content).
4. **Offline** (WS status `"disconnected"`, `AstridrWSContext.tsx:30`) — dashed, neutral (`--ink-dim`/`--muted-foreground`-equivalent), no drift, no packets. Distinct from Unknown only in *cause* (socket genuinely down vs. socket up but state unconfirmed) — the two may share one visual/implementation if simpler, but must remain two named conditions in the test cases below, so collapsing them can't quietly hide the freshness-timeout or malformed-payload cases inside "we happen to also be offline".
5. **Resting** — aurora gradient as above. Reachable only from a fresh, well-formed, disarmed `estop_state` snapshot.

**Required test cases** (carry to the planner): **delayed snapshot** (socket connects, first `estop_state` arrives several seconds late — horizon shows Unknown for that whole gap, never Resting); **missing snapshot** (socket connects, no `estop_state` ever arrives — Unknown forever, never silently resolves to Resting); **malformed snapshot** (an `estop_state` message with an unexpected/unparseable shape — stays Unknown, does not throw inside `AstridrWSContext.tsx`'s fan-out); **reconnect** (armed → disconnect → reconnect — horizon shows Unknown immediately post-reconnect, does not resume showing the pre-disconnect armed/resting state from memory, until a fresh snapshot confirms current status).

**Disarm easing ("dawn")** — on transition from armed → disarmed, ease back through **amber over ~2.6s** before returning to the aurora resting state. This is a named part of what won variant B (`shell-and-dashboard.md:37`, `125-CONTEXT.md` D-04 note) — do not skip straight from crimson to aurora.

**Reduced-motion / `readable` (D-04):** aurora gradient freezes (no drift, no packets); state colors (warn amber / crimson-armed / dashed-offline / dashed-unknown) remain **fully live and instant** — this is a functional safety signal, not decoration, so it is the one thing that must NOT be suppressed. `readable`'s existing blanket `[data-theme="readable"] *, ::before, ::after { animation: none !important }` (`src/index.css:777-780`) covers the CSS-animation freeze for free; do not rely on it alone if any part of the packet/drift logic runs in JS rather than CSS.

**Truth source — `estop_state` (D-01, cross-repo):** CodePulse cannot observe E-Stop today at all (F-1 — 0 `estop` hits in `convex/`, no `estop` topic in `AstridrWSContext.tsx`'s `TOPIC_EVENT_MAP` at `:58-95`, and the existing `GET /api/estop/status` route 403s any non-loopback caller). Ástríðr becomes the source of truth via a new `estop_state` WS telemetry event; it is pushed to each client **both on connect and on every transition** (D-02), following the `commands.catalog` push-on-connect precedent at `astridr/engine/ws_telemetry.py:64`. **This is cross-repo work in `astridr-repo`, needing `docker compose up --build` (never `restart`)** — sequence the horizon so its state layer can be built and verified against a **stubbed/simulated** `estop_state` event first, so a single operator rebuild doesn't gate the whole phase (flag for the planner, not a UI contract item — see `125-CONTEXT.md` `<specifics>`).

**What specifically dies vs. relocates (D-09):**

- "System Load" numeral + fabricated gradient bar (`:172-192`, the `100 - errorRate*2` composite figure named in POLISH-04's fabrication finding) — **deleted**, replaced by the ECG canvas + its own measured numeral (below).
- Memory hit-rate readout (`:194-197`) — **relocates** to a new tile in the existing KPI grid (`:203-230`, currently 8 `MetricCard`s in two rows of 4) — real data, honors 124's D-08 rule that real numbers relocate rather than dying. The KPI grid itself is otherwise untouched.

**Component:** one `<canvas>`, no charting library (Recharts explicitly excluded — criterion 2's own wording).

**Eyebrow + numeral (D-12):** `PULSE / 60s` (11px mono uppercase eyebrow) + a 40px thin (`weight: 300`) `tabular-nums` figure, `letter-spacing: -0.02em`, showing the **count of events in the current 60s window** — a measured figure the trace itself already contains, replacing the composite `100 - errorRate*2` it displaces.

**Trace rendering (fixed by sketch, `shell-and-dashboard.md:23`):**
- 60s rolling window (validated in sketch; 5min was tried and made the trace look empty — do not widen it).
- Breathing baseline when idle: opacity 0.5↔0.8, 4s sine.
- Blips: machine = cyan up-blips (`var(--primary)`), Ástríðr = violet (`var(--astridr)`), errors = red down-spikes (`var(--status-error)`).
- **Colors resolved via `getComputedStyle` at draw time, never hardcoded hex in the canvas drawing code.** Per the house Tailwind-v4 lesson: `getComputedStyle` on this app returns `oklch()`/`oklab()` strings, not `rgb()` — if the canvas 2D context needs an `rgb()`/hex string, convert via an offscreen 1×1 canvas `fillStyle` round-trip or an explicit color-space conversion; do not regex-scrape the `oklch()` string for channel values (that reads the hue angle as a color channel and produces impossible results — the exact defect class documented in this repo's own memory).

**Empty-window states (D-08, mirrors `MetricCard`'s six-state contract, `HeroStatsBar.tsx:157-163`):**
| Condition | Rendering |
|---|---|
| Feed down/absent (`unavailable`) | Dotted baseline + italic "no signal yet" at 55% opacity |
| Feed healthy, zero events in window (`empty`/idle) | Breathing baseline, no text — a quiet system is nominal |

**Render loop (D-11):** `requestAnimationFrame`, gated:
- Runs while `document.visibilityState === "visible"`.
- Stops on `document.hidden` (this repo has prior CPU-drift history on long-lived sessions — do not run an unconditional loop).
- Under `prefers-reduced-motion` or `readable`: paint **one static frame**, never loop. Note this is a canvas rAF loop, not a CSS animation — `readable`'s blanket `animation: none !important` (`src/index.css:777-780`) does **not** cover it; the gate must be explicit JS.

**Data feed (D-05) and backfill↔live reconciliation.** One **bounded** Convex read on mount to backfill the trailing 60s, then rides the live WS stream. **Do not** reuse `useRecentEvents.ts` → `api.events.listRecentUnified` at larger limit — read it first: `convex/events.ts:193-244` `.take()`s `max(limit, 100)` from two tables merged/sorted/sliced (≥200-doc read), its timestamps are **seconds** not milliseconds (confirmed, `convex/events.ts:200`), and it's already 48h range-bound. Write a dedicated bounded query scoped to a 60s window instead.

This split feed has two independent transports with no shared cursor — a Convex query for backfill, Ástríðr's own `/ws/telemetry` for live (`AstridrWSContext.tsx`, fanned out from `ConvexHandler`'s observer pattern per `astridr-repo/astridr/engine/ws_telemetry.py:1-5`, pushed to the browser independently of — not read back from — the Convex write). So query-first can lose events emitted between the query snapshot and subscription, subscribe-first can double-count events present in both, and any WS outage after mount leaves a silent hole in the window. This matters more than it looks: the ECG's numeral IS a measured 60s event count (D-12) whose entire point is replacing POLISH-04's fabricated `100 - errorRate*2` composite — a silently wrong count from an unspecified merge would reintroduce the exact defect this phase exists to remove.

**No stable cross-source event id is confirmed to exist today — verified, not assumed:** `AstridrWSContext.tsx:31` types the WS callback payload as `Record<string, unknown>` with no declared shape, and the context's own dispatch code (`AstridrWSContext.tsx:294-330`) reads only `msg.event_type` (`:319`) to fan the message out — no id field is read or relied on anywhere in this file. Convex documents backing the backfill DO carry a stable `_id` (`convex/events.ts:224,232`), but whether Ástríðr's WS push embeds that same `_id` in the pushed dict is **unverified** — the push path lives inside `ConvexHandler`'s observer implementation, past `ws_telemetry.py`'s router, and was not read this session. This is a required implementation step, not an assumption to build on:

1. At plan/build time, capture one real live WS message and check whether it carries the same `_id` Convex assigned the corresponding row.
2. **If it does** — use that `_id` as the dedup key directly. Simplest, fully correct, no cross-repo work needed. Proceed straight to Reconciliation sequence below.

**If it does not — a stable shared identity is a prerequisite for shipping the measured numeral, not a QA-contingent fallback.** This revision retires the composite key previously proposed here (`(event_type, floor(timestamp_to_seconds), secondary_field)`) outright — it cannot be shipped as a correctness guarantee. The unified projection this phase's backfill query draws its shape from carries exactly six fields (`convex/events.ts:224-241`: `_id`, `eventType`, `toolName`, `sessionId`, `timestamp`, `source`), so `secondary_field` could only ever have been `toolName` or `sessionId` — and neither disambiguates the dominant case: two `tool_call` events in the same session within the same second is what an agent burst *is*, not an edge case, and adding `toolName` does not rescue it (calling `Bash` twice in one second is ordinary). The 1-second granularity was never a choice this spec could make — `convex/events.ts:200` (`const nowSec = Date.now() / 1000`) forces whole-second buckets on every timestamp this key could use. Worse, a collision on this key **silently discards a distinct event — an undercount, not a double-count** — and the previously-drafted escalation trigger ("visible double-counts or drops in QA") could not detect its own failure mode: a dropped event during a burst produces no visible symptom, just a numeral that reads as measured and is quietly wrong. That defeats D-12's entire reason for existing, which is replacing POLISH-04's fabricated composite with something actually measured. So, if step 1 finds no shared id, do **not** ship a composite-key dedup. Choose one of:

**(a) Add a stable event id in the Ástríðr emitter.** Cross-repo work in `astridr-repo`, same class as the `estop_state` item above (D-01) — `docker compose up --build` (never `restart`) to land it, and the same stub-first sequencing so one operator rebuild doesn't gate the phase. Clean and fully correct: once every WS event carries the id Convex already assigns its row, use it exactly as in step 2 above.

**(b) Time-partitioned merge, requiring no identity at all.** Capture a watermark when the backfill query is issued; take backfill rows strictly older than it, and live events (buffered per Reconciliation step 1 below) at/after it — the two sources never overlap, so no dedup key is needed. **Evaluated honestly, this is not a free win: it trades identity risk for clock-skew risk, and that risk is unverified from this session's evidence, not established as acceptable.** The watermark is a Convex-assigned, second-granularity timestamp (`convex/events.ts:200`); the live WS timestamp originates in a different process (Ástríðr's own container, via `ws_telemetry.py`) whose clock offset from the Convex container's clock was not measured this session — the `convex-topology-all-local` memory establishes both run self-hosted/local, but not that they share a synchronized clock, and this session opened neither container's clock source to check. Even with perfectly synced clocks, `convex/events.ts:200`'s whole-second timestamps create an inherent ~1s boundary-rounding band on top of any skew: an event genuinely stamped in the same second as the watermark can legitimately belong on either side of it, and neither payload today carries a sub-second tiebreaker. **Do not select (b) without first measuring the actual inter-process clock offset** (e.g. log `Date.now()` on the Convex mutation path and on the Ástríðr WS emit path for the same real event and diff them) **and stating the resulting bound explicitly in the plan.** If that measurement is skipped, treat (b) as unverified and prefer (a) or (c).

**(c) Ship the ECG trace without the measured numeral** until (a) lands, or until (b) lands with its clock-skew risk measured and stated as acceptable. The trace itself is qualitative (blips on a 60s canvas) and unaffected by any identity question — only the count claim requires measurement. In this case D-12's numeral renders in the `unavailable`/degraded state already defined above (dotted baseline, "no signal yet"-equivalent copy) rather than a placeholder guess — the copywriting/empty-window contract above already has the visual language for this; no new state is invented. Note what D-12 would then need to say: the eyebrow (`PULSE / 60s`) and trace still ship, but the 40px numeral is withheld rather than shown as an approximation.

**Whichever path is chosen, the numeral must never render as a measured figure over a window the component knows may be incomplete.** Until reconciliation can complete with a correctness guarantee — path (a), or a path (b) whose clock-skew bound has actually been measured and stated — the ECG stays in its `unavailable`/degraded state per the Empty-window states table above rather than showing an approximate count.

**Timestamp normalization** (applies to path (b) and to any cross-source comparison): Convex backfill timestamps are seconds (`convex/events.ts:200`, confirmed); the live WS payload's timestamp precision is unverified — floor/round both to whole seconds before comparing, never assume they already share a unit.

**Reconciliation sequence** (path (a), and path (b) once its clock-skew bound is measured and accepted — not applicable to path (c), which does not merge sources into a count at all):
1. **Subscribe (and buffer) before issuing the backfill query** — call `subscribeEvent` for every relevant event type immediately on mount and hold everything received in an in-memory buffer without rendering, so nothing emitted during the query round-trip is lost.
2. Issue the bounded 60s-window Convex backfill query, capturing its issue time as the watermark (path (b) only).
3. On backfill resolution, merge backfill rows with the buffered live events — by shared `_id` (step 2 / path (a)) or by the time-partition watermark (path (b)) — and discard anything (from either source) outside the current rolling 60s window.
4. Only once merge completes does the ECG leave its `unavailable`/degraded empty-window state (defined above) and render the reconciled trace + numeral — never show a partial live-only or backfill-only count as though it were the measured figure.
5. **Re-run this entire sequence (re-subscribe-and-buffer, re-backfill, re-merge) on every WS reconnect**, not only on mount — a reconnect after any outage leaves the same kind of hole a fresh mount does, and the ECG must return to its degraded state for that window rather than silently resuming with a gap.

**Required test cases** (carry to the planner, applies to whichever of path (a)/(b) is chosen): overlap window (an event present in both the backfill read and the live buffer merges to exactly one, never two); during-backfill arrival (events buffered while the query is in flight are not lost); reconnect (a WS outage produces a degraded-state window, not a silently gapped count); out-of-order arrival (a live event with an earlier timestamp than one already merged is still placed correctly, not dropped); and **multiple same-type, same-session events within a single second** — e.g. two `tool_call` events, same `sessionId`, same floored second, the ordinary shape of an agent burst — both must be counted, asserting that whichever identity mechanism was actually chosen (shared `_id`, or the time-partition watermark), and not the composite key this revision retired, is what prevents them from being merged away.

**Entry-chunk budget (D-10) — the ratchet, not just a rule:** No byte budget exists anywhere in this repo today (F-3 — confirmed no measurement exists, only a DEBT-03 convention). Before any 125 code lands, measure and record the **current** entry-chunk size (build `dist/assets/*.js` matching the entry, not the lazy `Dashboard` chunk), then assert the post-change size against that baseline with a stated allowance — same shape as `src/tokenSweep.ratchet.test.ts` (its own refusal-when-`dist/`-absent pattern, `:339`). **Note the inversion:** `Dashboard` is lazy (`src/App.tsx:18`, `lazy(() => import("./pages/Dashboard"))`), so the ECG canvas itself lands in the *lazy* Dashboard chunk — the entry-chunk risk is actually the **Signal Horizon**, because `DashboardLayout` is a static import (`src/App.tsx:4`). Both signatures should be measured, but the ratchet's real target is the horizon's contribution to the entry bundle.
