## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ástríðr process → authenticated WS client | `estop_state` crosses from the only process that knows the true halt state to every connected browser, which will treat it as a SAFETY signal |
| activation surface → `EmergencyStop` | Five surfaces (loopback HTTP + admin key, in-process, CodePulse WS command, Telegram/Slack `/estop`) converge on `activate()`/`deactivate()` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-03-01 | Spoofing | `estop_state` on the WS stream | mitigate | The event is only ever produced inside `EmergencyStop.activate()`/`.deactivate()` and the router's own snapshot read — there is no ingest path by which a client can inject one. The socket itself is auth-gated at upgrade time (`ws_telemetry.py` constant-time dual-key check), so an unauthenticated peer cannot even receive it, let alone publish. No new write path is added. |
| T-125-03-02 | Information disclosure | `estop_state.data` | mitigate | The payload carries `armed`, `reason` and `initiator` only. `reason` is operator-supplied free text and could in principle contain sensitive context; it is already broadcast verbatim in the existing `security_event` payload (`estop.py:150-159`) to the same authenticated audience, so this adds no new exposure. No key, host, path or token is included. |
| T-125-03-03 | Denial of Service | on-connect snapshot push | mitigate | One `send_json` per connection, wrapped in try/except that logs and continues. Test (d) proves a raising `is_active` cannot close the socket, so a broken estop instance degrades the horizon to its fail-closed Unknown state rather than taking the telemetry pipeline down. |
| T-125-03-04 | Repudiation | replacing `security_event` | mitigate | Explicitly NOT done. `estop_state` is an additional sibling emission; the audit-trail event and the `insert_audit_log_bg` call are untouched, asserted by test (a) and by a grep count of 1 on `"security_event"`. |
| T-125-03-05 | Tampering | deleting the buffered `run.blocks` send | mitigate | The deletion removes `run.blocks` from Convex persistence as a side effect. Gated on a recorded grep proving no persisted consumer exists, with an explicit STOP branch if one does. The surviving frame is the one `useAstridrChat` gates on, asserted directly by test (b). |
| T-125-03-06 | Elevation of privilege | `estop` instance handed to the router | accept | `create_ws_router` receives the live `EmergencyStop` and reads two read-only properties. It never calls `activate`/`deactivate`, so no new control path over the kill switch is created. Reviewed and accepted rather than proxying behind a read-only view, which would add a class for no measured benefit. |
| T-125-03-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs nothing in either repo. If any test import turns out to need a package that is not already in `astridr-repo`'s environment, STOP and report — do not install. |
</threat_model>
