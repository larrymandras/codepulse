<planner_corrections>
**Integration decision (UI-SPEC:134 explicitly defers this to plan time):** the horizon SITS
BENEATH the header as a sibling element, and the header's `border-b border-border` is REMOVED. The
horizon becomes the separator. The sketch's own shell is `topbar → .horizon → .canvas`
(`shell-and-dashboard.md` §"HTML Structures"), and keeping both would stack a 1px border on a 2px
line — a doubled rule at rest and a 1px crimson-adjacent artefact when armed. The
`SectionErrorBoundary` fallback restores a plain hairline so the separator survives a horizon
failure.

**Packet subscription mechanism.** `subscribeEvent` is per-event-type, so covering "every event"
that way would need ~25 registrations and would still miss any NEW server event type — exactly
what D-06's unknown-type rule exists to handle. Instead subscribe with `subscribe(topic, cb)` for
each key of the exported `TOPIC_EVENT_MAP`, and dedup by MESSAGE OBJECT IDENTITY in a `WeakSet`:
`AstridrWSContext.tsx:322-343` passes the identical `msg` object to every matching callback, and
its unknown-event-type branch (`:337-342`) fans out to ALL topic subscribers — so identity dedup
is exactly right for both the multi-topic case and the unknown-type case, and unknown types still
produce exactly one machine-coloured packet. Do NOT dedup on `event_type` or on any payload field;
`run.blocks`'s genuine double-delivery (D-19) is a separate concern that the 1s drop-gate absorbs
for packets and that plan 125-09 handles for the count.
</planner_corrections>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ástríðr WS → shell DOM | Producer-controlled event types drive DOM node creation on the every-route shell |
| horizon component → whole-app layout | A component mounted in `DashboardLayout` renders on every route, so its failure mode is app-wide |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-08-01 | Denial of Service | packet DOM churn under an event storm | mitigate | The D-07 drop-gate caps creation at 1 node/second regardless of arrival rate, each node is removed after 700ms, and all removal timers are tracked and cleared on unmount. Asserted by cases (a) and (f). A queue-and-drain design was rejected for exactly this reason. |
| T-125-08-02 | Tampering | producer-supplied `event_type` reaching CSS | mitigate | `event_type` never reaches the DOM. It is mapped through `eventTypeToHue` to one of three fixed `var(--token)` strings from `HUE_TOKEN`; the `--pk` value can only ever be one of those three literals, so no injection into a `style` attribute is possible. Asserted by cases (b) and (c). |
| T-125-08-03 | Denial of Service | a throw in the packet handler | mitigate | This handler runs inside `ws.onmessage` alongside every other subscriber (`AstridrWSContext.tsx:322-343`), so a throw would kill the whole telemetry stream. The handler skips malformed messages inside try/catch, and the render half is contained by `SectionErrorBoundary`. |
| T-125-08-04 | Spoofing | the error-boundary fallback claiming a safety state | mitigate | The fallback is a plain hairline with `aria-hidden`, deliberately making NO state claim. Rendering "offline" or the resting aurora there would assert something about E-Stop at the exact moment the component that knows has crashed. |
| T-125-08-05 | Denial of Service | a new every-route Convex subscription | mitigate | Zero added: the existing `api.alerts.countBySeverity` call is hoisted, not duplicated, asserted by a call-count spy that mutation (3) proves fires. This is the deliberate avoidance of Phase 124's WR-01 shape, still open as Phase 126 work. |
| T-125-08-06 | Information disclosure | packet appearance leaking activity to a shoulder-surfer | accept | The horizon conveys "something happened, in one of three families" with no identity, payload or rate fidelity (the 1/s cap actively destroys rate information). Accepted as the intended ambient signal. |
| T-125-08-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs nothing. |
</threat_model>
