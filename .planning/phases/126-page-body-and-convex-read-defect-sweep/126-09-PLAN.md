<planner_corrections>
**1. Unlike plan 125-07, `git diff convex/schema.ts` is EXPECTED to be non-empty here.** Plan 125-07's
audit asserted `SCHEMA_CLEAN`. This deploy legitimately changes the schema — plan 126-02 added one
table, one index, and one optional field. The audit's job is therefore different: prove the change is
ADDITIVE ONLY. A removed table, a removed field, or a renamed index would be a destructive migration
on a single-node SQLite instance whose MVCC tombstone GC cannot absorb mass deletes.

**2. `function-spec` is a one-directional probe and its limits must be stated where it is used.**
It lists PUBLIC functions only. `inbox:countHeldUnacked` and `graphSnapshots:getProjectGraph` are
public and will appear. `graphSnapshots:backfillGraphBlob`, `getGraphEntityPage` and
`getGraphMetaForBackfill` are internal and will NOT appear no matter what is deployed — a zero hit
there is guaranteed and proves nothing. The evidence that the internal functions deployed is that
running the backfill works.

**3. The shared-checkout enumeration is by NAME, not by reassurance.** Run `git log` against the
range the deploy would carry and list whose commits are in it. This repo has had a "surgical"
older-tree deploy silently delete three live indexes on another session's active phase, and has twice
in one day had a build ship a concurrent session's work in both directions. Say what you are about to
carry BEFORE deploying, and say what you carried AFTER.

**4. Do not run a state.* verb anywhere in this plan.** They miscount and clobber; Phase 125 closed
without running one at all and that is the standing practice here.

**5. `npx convex import --replace-all` is FORBIDDEN, as is any bulk delete or bulk patch against the
live instance.** Nothing in this plan needs either. If the backfill fails, the answer is to
investigate, not to reach for an import.
</planner_corrections>
