<objective>
Expose Galdr to Claude Code over HTTP: four bearer-authed routes, none of which negotiates
CORS and none of which has an OPTIONS partner.

Purpose: this is CodePulse's first authenticated GET endpoint, and D-04 makes it the second
route family in the repo that deliberately breaks the POST+OPTIONS pairing convention every
other one of the 56 routes in `convex/http.ts` follows. The precedent exists —
`convex/health.ts` already ships a GET with zero CORS involvement — but the departure is easy
to "helpfully" undo, so the test asserts absence on a real `Response`.
Output: `convex/galdrHttp.ts`, four route registrations, and a test file.
</objective>

`./_generated/api`, and `validateGaldrAuth` + `unauthorizedResponse` from `./ingestAuth`.

Do NOT import `getCorsHeaders` or `getCorsHeadersWithAllowlist`. Do NOT write an
`if (request.method === "OPTIONS")` branch in any handler — `convex/configVersionIngest.ts`
opens with exactly that branch and it must be dropped, not adapted. Put a file-header comment
citing D-04 stating that these routes are agent/CLI only, that browser writes go through the
existing Clerk-authed Convex mutation path, and that adding an OPTIONS pair "for consistency"
with the other 56 routes would contradict a locked decision.

Write each handler as a named exported plain async function
`(ctx, request: Request) => Promise<Response>` and wrap it in `httpAction(...)` for the export
the router consumes. Reason: an `httpAction`-wrapped value cannot be invoked from vitest, and
the D-04 header-absence assertion has to run against a real `Response` object. This mirrors
the handler-extraction shape already used in `convex/reminders.ts` / `convex/galdr.ts`.

Add a private `jsonResponse(payload, status)` helper in this file returning
`new Response(JSON.stringify(payload), { status, headers: { "Content-Type": "application/json" } })`
— one place where the header object is constructed, so there is one place to audit for a
CORS regression.

`galdrPromptGetHandler` — GET `/galdr/prompt`.
1. `if (!validateGaldrAuth(request)) return unauthorizedResponse();` as the first statement.
2. Read the query string with `new URL(request.url).searchParams.get("slug")`. The parameter
   is named `slug` but carries either an exact slug or free search terms — D-05's contract
   lives in `api.galdr.lookup`, not here.
3. Missing or empty parameter → 400 with `{ error: "MISSING_SLUG" }`.
4. `ctx.runQuery(api.galdr.lookup, { query })` and return its `{ match, candidates }` result
   at 200 verbatim. Do not collapse a single candidate into a match here — that would move
   D-05's decision out of the one place it is tested.
5. The bearer key must never be echoed into any response body or into the URL. Comment it.

`galdrListGetHandler` — GET `/galdr/list`. Auth check, then
`ctx.runQuery(api.galdr.listCategories)` at 200. This serves D-08's bare `/galdr`.

`galdrPromptPostHandler` — POST `/galdr/prompt`. Auth check, then `await request.json()`.
Require `title` and `body` as non-empty strings; `category` optional, defaulting to the
string `"uncategorized"`; `tags` optional array of strings. Missing required field → 400 with
`{ error: "MISSING_FIELD", field }`. Call `ctx.runMutation(api.galdr.createPrompt, {...})`
inside a try/catch. In the catch, read `err.data` (a `ConvexError`'s `.data` survives Convex's
client-side redaction; a plain `Error`'s message does not):
- `.data.code === "SLUG_COLLISION"` → 409 with `{ error: "SLUG_COLLISION", existingSlug,
  existingTitle, existingUpdatedAt, existingArchived }` taken from `.data`. This is D-06's
  wire form: the operator sees exactly what they collided with.
- `.data.code === "EMPTY_SLUG"` → 400 with `{ error: "EMPTY_SLUG" }`.
- anything else → 500 with `{ error: "SAVE_FAILED" }` and no internal detail.
On success → 201 with `{ ok: true, slug, promptId }`.

`galdrUsagePostHandler` — POST `/galdr/usage`. Auth check, parse `{ slug }`, 400 if absent,
`ctx.runMutation(api.galdr.recordUsage, { slug })`, 200 with `{ ok: true }`. This is a
separate narrow route rather than a flag on the save route because bumping usage is NOT a
body-changing write and must never reach D-15's version-append path — keeping it on its own
route makes that impossible by construction rather than by a conditional. Comment that.

Export the four wrapped actions as `galdrPromptGet`, `galdrListGet`, `galdrPromptPost`,
`galdrUsagePost`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public network → Convex HTTP router | Anything can reach these paths; the bearer check is the only gate |
| Browser JS → `/galdr/*` | Deliberately unreachable: no ACAO header means the browser blocks the read before the response is usable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-01 | Spoofing | all four galdr routes | mitigate | `validateGaldrAuth` is the first executable statement of every handler; Task 3 asserts 401 AND zero `runQuery`/`runMutation` calls, so the gate provably precedes database access |
| T-116-04 | Tampering | browser-origin call to a galdr route | mitigate | No `getCorsHeaders` import, no OPTIONS route; asserted on real `Response` objects with a positive control (D-04) |
| T-116-02 | Information Disclosure | `GALDR_API_KEY` leaking via query string or server logs | mitigate | The key travels only in the `Authorization` header; the sole URL parameter is `slug`; no handler echoes the header into a response body |
| T-116-06 | Tampering | silent overwrite on a colliding save | mitigate | The mutation's `ConvexError` is mapped to a 409 carrying the existing title and `updatedAt`; nothing is auto-suffixed. Task 3 asserts the 409 body |
| T-116-14 | Repudiation | a usage bump silently consuming a version slot | mitigate | Usage lives on its own `/galdr/usage` route calling `recordUsage`, which cannot reach the version-append path; asserted by the recorded mutation reference |
| T-116-17 | Information Disclosure | internal error text reaching an unauthenticated-ish caller | mitigate | The catch-all branch returns a bare `{ error: "SAVE_FAILED" }` at 500 with no message, stack, or field detail |
| T-116-03 | Elevation of Privilege | one key for read and write | accept | D-02 — do not add scoping the decision rejected |
| T-116-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages this phase |
</threat_model>
