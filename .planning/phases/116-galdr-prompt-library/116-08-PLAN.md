Layout, per UI-SPEC's Component Inventory:

  no categories table and no category-admin UI this phase (the plain `category` string field
  was chosen in plan 116-01; note the reason in a comment so the absence reads as a decision).

Card anatomy: `CardHeader` with the title and a favorite Star toggle top-right; `CardContent`
with a two-line-clamped body preview in `--muted-foreground`, a category chip, and the usage
count rendered as the count plus a multiplication sign in `tabular-nums`; `CardFooter` with
`SendSplitButton` and an overflow menu offering Edit and Archive. Clicking the card body — not
the footer controls — opens the drawer in edit mode.

Every icon-only control carries the `aria-label` UI-SPEC's Icon-only control labels table
specifies: the Star toggle reads `Toggle favorite {title}`, the overflow trigger reads
`More actions for {title}`. A bare Lucide icon with no accessible name is not an acceptable
implementation of any of them.

The favorite star uses `var(--status-warn)` for fill and stroke — deliberately NOT
`SkillRow.tsx`'s hardcoded `fill-amber-400 text-amber-400`, which contradicts the repo's own
no-hardcoded-colour rule. This is the single intentional visual divergence from the Skills
donor; note it in a comment so it does not get "corrected" back.

States, verbatim from UI-SPEC's Copywriting Contract:
- Loading: three to six skeleton cards shaped like the real card (title bar, two body lines,
  chip row). Never a bare spinner and never blank.
- Truly empty: heading `No prompts yet`, body
  `Save one from Claude Code with /galdr-save <title>, or create one here.` plus a New Prompt
  button. The library begins empty on purpose — ship no seed rows.
- Filtered to zero: the mono dashed-border `[ NO PROMPTS MATCH ]` panel, reusing the existing
  `AllSkillsOverview` treatment.
- Error: `Couldn't load prompts — check your connection and try again.` replacing the grid
  region only; the header and chip row stay visible and interactive.

Wiring: `useGaldrPrompts()` for the list, `useGaldrPromptVersions(selectedId)` for the drawer,
and `useMutation` for `createPrompt`, `updatePrompt`, `restoreVersion`, `archivePrompt`,
`toggleFavorite`, `recordUsage`. Pass `recordUsage` down to `SendSplitButton` as its `onUsage`
prop.

Search filters client-side across title, slug, category and body — the whole list is already
subscribed, matching how `src/pages/Skills.tsx` treats its own set. Sort: favorites first,
then `usageCount` descending, then `updatedAt` descending.

Do not build an Archived view or an Unarchive control. UI-SPEC discloses this as a deliberate
scope boundary: an archived prompt is retained with its versions but is not reachable again
from the UI this phase. Do not add it silently. Do not add a purge or hard-delete control
anywhere — D-16 ships archive-only and plan 116-03 exposes no mutation that could serve one.

Every colour is a CSS var. No hex literal, no Tailwind palette colour. Render the body preview
as plain text — no `dangerouslySetInnerHTML`, no markdown renderer.
