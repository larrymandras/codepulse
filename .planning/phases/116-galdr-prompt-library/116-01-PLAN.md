Add `export function validateGaldrAuth(request: Request): boolean` to `convex/ingestAuth.ts`,
placed immediately after `validateForgeIngestAuth` and before `unauthorizedResponse`.

Behaviour, structurally identical to its two siblings: read `_env.GALDR_API_KEY`; if it is
falsy, return `_env.GALDR_ALLOW_ANON === "true"` (fail closed — a missing key must not open
the prompt library to the public internet); otherwise compare
`request.headers.get("Authorization") ?? ""` against the template string `Bearer ` + the key
with `===`.

Use plain `===`, NOT a constant-time comparison. This is deliberate: both existing siblings
use `===`, and D-01 says the new validator must mirror them. Introducing a different
comparison for one of three validators would create an inconsistency without changing the
realistic risk on a single-operator self-hosted instance. Record that reasoning in the
doc comment so a future reviewer does not "fix" it.

The doc comment must also record D-01's blast-radius rationale: a dedicated `GALDR_API_KEY`
rather than reusing `ASTRIDR_INGEST_API_KEY`, because that key is write-only telemetry today
and reusing it would widen a leaked-key blast radius to include reading the prompt library.
And D-02: this one key authorizes both the galdr read and the galdr writes — do not add a
read/write split, which the decision explicitly rejected.

Do not modify `getCorsHeaders`, `getCorsHeadersWithAllowlist`, `parseAllowlist`,
`unauthorizedResponse`, or either existing validator.

In `convex/__tests__/ingestAuth.test.ts`, add a new `describe("validateGaldrAuth", ...)`
block with five tests mirroring the existing suite exactly, each using `vi.stubEnv` and
`vi.unstubAllEnvs`:
1. rejects a request with no Authorization header when `GALDR_API_KEY` is set
2. rejects a request whose Bearer value is a different key
3. accepts a request whose Bearer value matches `GALDR_API_KEY`
4. fails closed: `GALDR_API_KEY` unset and `GALDR_ALLOW_ANON` unset returns false
5. returns true only when `GALDR_API_KEY` is unset AND `GALDR_ALLOW_ANON` is exactly the
   string `"true"` — include a negative control in the same test asserting the string
   `"1"` and the string `"TRUE"` both return false

Build every request as a real `new Request("http://localhost/galdr/prompt?slug=x", ...)` —
GET for the read cases — not a hand-rolled header object.
