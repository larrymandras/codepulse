<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| laptop → tailnet | A new device joins a private network that fronts the self-hosted Convex and Ástríðr backends |
| probe commands → transcript | Authenticated probes carry a bearer token that must not be echoed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106-15 | Elevation of privilege | tailnet device admission | mitigate | Device authentication and approval are performed by Larry through the Tailscale sign-in and admin console; Claude runs no command that approves a device or alters ACLs, and the checklist explicitly includes the approval step rather than assuming auto-join. |
| T-106-16 | Information disclosure | `VITE_ASTRIDR_API_KEY` bearer token during the Ástríðr probe | mitigate | Record only that an Authorization header was present and the resulting status. Never echo the token, never paste the full curl command with the header value, never write it into the checklist file. |
| T-106-17 | Spoofing | endpoints published via `tailscale funnel` (public internet) rather than `serve` (tailnet only) | mitigate | The discovery step records `funnel status` separately from `serve status`, so any endpoint exposed beyond the tailnet is visible in the artifact rather than silently assumed private. |
| T-106-18 | Tampering | self-hosted Convex instance | mitigate | Every probe in this plan is a read/health request. No write, no `convex import`, no bulk operation, per `CLAUDE.md` § "Self-Hosted Convex — Operational Rules". |
| T-106-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs nothing in the repo. Tailscale is installed by Larry on his own laptop from the vendor's official download, outside any package manager this repo controls. |
</threat_model>
