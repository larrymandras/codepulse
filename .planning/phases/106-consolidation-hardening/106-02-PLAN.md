<objective>
Measure what is actually in the CodePulse production bundle before changing anything, so DEBT-03's remediation targets real bytes.

CONTEXT.md D-09 already established, from a real `npm run build` during pattern-mapping, that REQUIREMENTS.md's named chunks are a stale hypothesis: `WarRoom` (485 kB) is under the threshold and needs no work, `react-force-graph-3d` (1.29 MB) is already correctly lazy, and the single biggest chunk — the `index-*.js` entry at 2.05 MB, downloaded on every page view — is not named in REQUIREMENTS.md at all. What is still missing is *module-level attribution*: which source modules and dependencies actually make up those bytes.

This plan adds a reproducible, opt-in build-time composition report using the project's own inline-Vite-plugin convention (the existing `drop-unused-ort-wasm` plugin in `vite.config.ts`), runs it, and writes the baseline.

Purpose: plan 106-04 removes bytes; this plan is the measuring stick it is held against.
Output: an opt-in `chunk-composition-report` plugin in `vite.config.ts`, and `.planning/phases/106-consolidation-hardening/106-BUNDLE-ANALYSIS.md` recording the baseline.

**Do not change any application source file in this plan.** No `lazy()` conversion, no import rewrites — those belong to 106-04. The only source edit here is the additive plugin in `vite.config.ts`.

**Install no packages.** Do not add `rollup-plugin-visualizer`, `source-map-explorer`, or any other analyzer dependency. Rollup's own `generateBundle` hook already exposes per-chunk `modules` with `renderedLength`, which is everything this plan needs, and adding a dependency here would require a package-legitimacy audit this phase does not have.
</objective>

  <action>
Add a second inline plugin object to the `plugins` array in `vite.config.ts`, immediately after the existing `drop-unused-ort-wasm` entry. Keep `drop-unused-ort-wasm` byte-identical — this is additive only.

Requirements for the new plugin:

- `name: "chunk-composition-report"`.
- **Opt-in, never on by default.** Gate every effect on `process.env.ANALYZE_BUNDLE === "1"`. A normal `npm run build` must emit exactly the same asset set it does today. Implement the gate with an `apply: "build"` plus an early return inside the hook (or by conditionally including the plugin in the array) — either is fine, but a default `npm run build` must produce no `chunk-composition.json`.
- Implement a `generateBundle(_options, bundle)` hook that walks `Object.entries(bundle)`, keeps only entries whose `type === "chunk"`, and for each records:
  - `fileName`
  - `code.length` as `renderedBytes`
  - `isEntry`
  - `isDynamicEntry`
  - `modules`: an array of `{ id, renderedLength }` built from `Object.entries(chunk.modules)` (rollup's `RenderedModule` carries `renderedLength`), sorted descending by `renderedLength`, capped at the top 30 modules per chunk, plus an `otherModulesCount` and `otherModulesBytes` tail so the numbers still reconcile after the cap.
- Sort the chunk array descending by `renderedBytes`.
- Emit the result via `this.emitFile({ type: "asset", fileName: "chunk-composition.json", source: JSON.stringify(report, null, 2) })` so it lands in `dist/` through the normal asset pipeline (do not write with `node:fs` — `emitFile` is the rollup-correct path and respects `outDir`).
- Include a short docstring comment above the plugin stating: what it is for (DEBT-03 chunk attribution), that it is opt-in via `ANALYZE_BUNDLE=1`, and the exact reproduction command. Follow the commenting style of the neighbouring `drop-unused-ort-wasm` plugin.
  - **Grep-gate hygiene warning** (this repo has tripped it on five consecutive plans): do NOT write the literal string `chunk-composition-report` inside that comment. The acceptance criteria below count occurrences of that string in the file and expect exactly one — the `name:` field. Refer to it in prose as "this plugin" instead.

Do not add `build.rollupOptions`, `manualChunks`, or `build.chunkSizeWarningLimit` in this plan. Raising the warning limit is explicitly out of scope: it would silence the exact signal this phase exists to act on, and a masked threshold cannot catch the next regression.
  </action>
