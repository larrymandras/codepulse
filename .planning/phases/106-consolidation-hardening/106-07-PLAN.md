## Why this plan does not patch anything

The voice stack has a documented history in this project of blind fixes making it worse:

- 2026-07-20: a naive restart-on-`onend` handler, reasoned out from event ordering rather than a trace, caused a restart storm that broke the listen path. It was committed and then reverted. The real cause — barge-in only acting on `final` while Chrome takes ~6s to finalise under continuous TTS — was found in one shot once the recognizer lifecycle was actually instrumented.
- 2026-07-30: `tts.end { barged: false }` was read as "the audio finished" when it only meant "our own barge-in latch didn't fire". That misreading survived four failed rounds aimed at the wrong subsystem.
- 2026-07-30: a side effect inside a React state updater double-invoked under StrictMode, so the second call tore down the first mid-playback. And the paired interim/final handlers turned out to be twins — fixing one of the two made the overall behaviour strictly worse.

So: instrument, capture, record, route. Do not patch here.

Purpose: DEBT-04 names this sequence explicitly, and no unit test can close it.
Output: three new test sections appended to `.planning/phases/106-consolidation-hardening/106-HUMAN-UAT.md`.
