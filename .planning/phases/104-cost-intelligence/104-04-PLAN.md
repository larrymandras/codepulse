Create `convex/costBudgets.ts`.

D-10 requires the planner to pick and state a timezone. IT IS UTC. State that in a file-header
comment with the two reasons: `crons.daily` is `hourUTC`-anchored, and both `rollupDaily` and
`SDKSpendGuard.projectDayEndSpend` already floor on `86400` (UTC midnight). A local-time boundary
would put the budget's day on a different edge than the rollup buckets that measure it.

PURE HELPERS (module-level `export function`, no ctx, all seconds not millis):
- `periodStartFor(period, nowSec)`:
  `"daily"` → `Math.floor(nowSec / 86400) * 86400`;
  `"weekly"` → Monday 00:00 UTC, i.e. `Math.floor((nowSec - 345600) / 604800) * 604800 + 345600`
    (the 345600 offset exists because epoch day 0 was a Thursday — put that in a comment, it is the
    kind of arithmetic a later reader will "simplify" incorrectly);
  `"monthly"` → the first instant of the current UTC calendar month, via
    `Date.UTC(d.getUTCFullYear(), d.getUTCMonth(), 1) / 1000`.
- `periodEndFor(period, nowSec)`: the start of the NEXT period. For `"monthly"` this must use
  `Date.UTC(year, month + 1, 1)` — do NOT add 30 days, because a projection to period end must land
  on the real month boundary or every alert names a wrong date.
- `periodHours(period, nowSec)`: `(periodEndFor - periodStartFor) / 3600`. This is what makes the
  projection generalize past `SDKSpendGuard`'s hardcoded `24`.

WRITE MUTATIONS — `create`, `update`, `remove`, each opening its handler with the sibling
convention reproduced verbatim from `convex/alertRuleCustom.ts:46-48`:
`const identity = await ctx.auth.getUserIdentity(); if (!identity) throw new ConvexError("Unauthenticated");`

- `create` args: `scope: v.string()`, `scopeKey: v.optional(v.string())`, `period: v.string()`,
  `limit: v.float64()`, `warnFraction: v.optional(v.float64())`, `enabled: v.optional(v.boolean())`.
  Validation, all throwing `ConvexError` with an operator-readable message:
  * `scope` ∈ `{"global","model","provider","quota"}`.
  * `period` ∈ `{"daily","weekly","monthly"}`.
  * `scopeKey` must be `""` when `scope === "global"`, and non-empty otherwise.
  * `unit` is DERIVED, never taken from the caller: `"quota_pct"` when `scope === "quota"`,
    otherwise `"usd"`. D-07 forbids a fictional dollar entering a budget, so the caller cannot
    choose the unit.
  * `limit` for a `"usd"` unit: `> 0 && < 1_000_000`, matching `forecasts.setBudgetCap`'s existing
    range and message shape. For `"quota_pct"`: `> 0 && <= 100`.
  * `warnFraction` defaults to `0.8` and must satisfy `> 0 && < 1`.
  * Reject a duplicate `(scope, scopeKey, period)` by reading the `by_scope_key_period` index first.
  `enabled` defaults to `true`; `createdAt`/`updatedAt` are `Date.now() / 1000`.
- `update` args: `id: v.id("costBudgets")` plus optional `limit`, `warnFraction`, `enabled`. Scope,
  scopeKey and period are IMMUTABLE after creation — changing them would silently re-target every
  dedup key plan 104-06 stores in alert `details`. Reject an attempt to pass them with a message
  saying to delete and recreate instead.
- `remove` args: `id: v.id("costBudgets")`; `ctx.db.delete(args.id)`.

READ QUERIES (no identity gate, matching the sibling read convention):
- `list` → `await ctx.db.query("costBudgets").collect()` with the comment
  `// small table by design (D-09); full scan is intentional. Plan 104-06 reads it once per hour —` +
  `// keep row count in the low double digits (RESEARCH.md Pitfall 5).`
- `get` args `{ id: v.id("costBudgets") }`.
- `getByScope` args `{ scope: v.string(), scopeKey: v.optional(v.string()), period: v.string() }`
  → the single row via the `by_scope_key_period` index, or `null`. This is what
  `SDKSpendGuard` (global/daily) and `CostForecastPanel` (global/monthly) read in plan 104-08.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `costBudgets.create/update/remove` public mutations | Untrusted callers can otherwise set or delete the thresholds that decide whether a spend alert ever fires. |
| operator input → `limit` / `warnFraction` | Free-text numerics that drive alert firing; an out-of-range value silently disables or spams alerting. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-13 | Tampering | `convex/costBudgets.ts` `create` / `update` / `remove` | mitigate | The sibling convention reproduced verbatim (`convex/alertRuleCustom.ts:46-48`, `convex/forecasts.ts:143-144`): `ctx.auth.getUserIdentity()` then `throw new ConvexError("Unauthenticated")`, as the first two statements of each write handler. Asserted by unit test and grep criterion. |
| T-104-14 | Tampering | `unit` field on a `quota` scope budget | mitigate | `unit` is derived server-side from `scope` and is not a caller argument, so a client cannot store a quota threshold in dollar units and cause the plan 104-06 evaluator to compare a percentage against money (D-07). |
| T-104-15 | Tampering | mutable `scope`/`scopeKey`/`period` on `update` | mitigate | Those three fields are immutable after creation. Changing them would re-target the `(budgetId, level, periodStart)` dedup key plan 104-06 stores in alert `details`, silently re-arming or permanently suppressing alerts. `update` rejects them explicitly. |
| T-104-16 | Denial of Service | `alerts` flooding from a mis-set `warnFraction` | mitigate | `warnFraction` is range-checked to `(0, 1)` and `limit` to `(0, 1_000_000)` for USD or `(0, 100]` for quota percent; D-15's per-period dedup in plan 104-06 is the second layer. |
| T-104-17 | Denial of Service | `costBudgets.list` whole-table `.collect()` read hourly by the evaluator | accept | Bounded by design (D-09 scopes this table to a handful of rows) and documented in a code comment; RESEARCH.md Pitfall 5 flags a row count in the hundreds as the trigger to revisit.
