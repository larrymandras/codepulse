<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form → `api.modelPricing.*` / `api.costBudgets.*` mutations | The form is a thin client; the authoritative gate is the Clerk identity check inside each Convex handler (plans 104-01 and 104-04). Client-side validation is convenience, not security. |
| operator keyboard input → numeric rate / limit fields | Free text reaching a money-affecting mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-29 | Tampering | `ModelPricingAdmin` / `CostBudgetsAdmin` mutation calls | transfer | Authorization is enforced server-side by the `ctx.auth.getUserIdentity()` gate in `convex/modelPricing.ts` and `convex/costBudgets.ts` (T-104-01, T-104-13). These components add NO client-side authorization check, because a client-side gate would be a false assurance; an unauthenticated operator sees the mutation rejected with the backend's `Unauthenticated` error surfaced through the existing `toast.error` path. |
| T-104-30 | Tampering | per-Mtok to per-token conversion in `ModelPricingAdmin` | mitigate | A single named helper performs the conversion in both directions and is covered by a round-trip unit test asserting a per-Mtok input of `5` reaches the mutation as `0.000005`. A duplicated `1_000_000` literal is the 1e6 mis-pricing vector; the backend's `> 0 && < 1` range check is the second layer. |
| T-104-31 | Tampering | quota budget stored in dollar units | mitigate | The unit is derived from the selected scope in the form and independently derived from `scope` server-side, so a tampered client payload cannot store a quota threshold as USD (D-07). |
| T-104-32 | Denial of Service | one throwing query blanking the whole Settings page | mitigate | Each admin surface is wrapped in its own `SectionErrorBoundary`, matching the documented codebase failure mode where a throwing `useQuery` unmounts the React tree. |
| T-104-33 | Repudiation | a form control implying an enforcement action the system never performs | mitigate | D-16 guard: no throttle/cap/swap control exists, an explicit `"Budgets raise alerts. They don't stop work."` disclaimer is rendered, immutable fields are shown disabled rather than editable-then-rejected, and a unit test asserts the forbidden strings are absent. |
</threat_model>
