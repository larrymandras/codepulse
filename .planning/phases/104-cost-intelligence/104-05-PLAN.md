  export type DerivedRow = {
    provider: string; model: string; billingType: "api" | "subscription";
    promptTokens: number; completionTokens: number;
    billedUsd: number | null;    // null when unpriced OR when billingType is subscription
    coveredUsd: number | null;   // null when unpriced OR when billingType is api
    priced: boolean;
    pricedVia: "model" | "shadow" | null;
  };

  export function deriveBucketDollars(
    dims: { provider: string; model: string; billingType: string },
    promptTokens: number,
    completionTokens: number,
    index: RateIndex
  ): DerivedRow;

  export const costOverTime = query({ period: string, lookbackHours?: number })
    -> Array<{ bucket_start: number;
               billedByProvider: Record<string, number>;
               coveredByProvider: Record<string, number>;
               unpricedTokensByProvider: Record<string, number> }>

  export const costBreakdown = query({ period: string, lookbackHours?: number })
    -> { rows: DerivedRow[]; billedTotal: number; coveredTotal: number;
         unpricedModelCount: number; unpricedTokenTotal: number }

  export const unpricedModels = query({ lookbackHours?: number })
    -> { count: number;
         models: Array<{ provider: string; model: string; billingType: string;
                         promptTokens: number; completionTokens: number }> }

  export async function computePeriodSpend(
    ctx: { db: DatabaseReader },
    args: { scope: "global" | "model" | "provider"; scopeKey: string;
            periodStart: number; nowSec: number }
  ): Promise<{ billedUsd: number; unpricedTokens: number }>;

Create `convex/costDerived.ts`.

PURE FUNCTION `deriveBucketDollars(dims, promptTokens, completionTokens, index)` — the single
place tokens become money. Rules, all of them load-bearing:
- `const hit = resolveRate(dims, index)`. When `hit === null`, return
  `{ ...dims, promptTokens, completionTokens, billedUsd: null, coveredUsd: null, priced: false, pricedVia: null }`.
  `null`, NOT `0` — D-03's whole point is that an unpriced bucket must be impossible to accidentally
  add into a total. A caller that sums with `?? 0` is a bug; state that in the doc comment.
- When `dims.billingType === "api"`: `billedUsd = priceTokens(...)`, `coveredUsd = null`.
- When `dims.billingType === "subscription"`: `billedUsd = 0` (D-05: subscription turns genuinely
  cost nothing per call, and the billed total must always mean money actually owed) and
  `coveredUsd = priceTokens(...)`.
- SECOND HONESTY GUARD: when `promptTokens === 0 && completionTokens === 0`, return the row as
  UNPRICED (`priced: false`, both dollar fields `null`) regardless of whether a rate resolved.
  Plan 104-02 records gateway turns whose token counts the CLI never reported; pricing those at
  `$0.0000` of covered spend would be D-03's failure mode applied to imputed money, which D-18
  explicitly forbids.

QUERY `costOverTime({ period, lookbackHours })`:
- `const cutoff = Date.now() / 1000 - (lookbackHours ?? 24) * 3600`.
- Two index-bounded reads on `by_type_period_bucket`, one for `"tokens_prompt"` and one for
  `"tokens_completion"`, each `.eq("period", args.period).gte("bucket_start", cutoff)`. Never a
  bare `.collect()` over `llmMetrics` and never a `by_period_bucket` read without a `metric_type`
  equality — both would scan far more than needed on this instance.
- Join the two reads on `(bucket_start, provider, model, billingType, goalId)`, using the same
  4-segment key string `convex/aggregates.ts` builds, with the same defaults
  (`provider ?? "unknown"`, `model ?? "unknown"`, `billingType ?? "api"`, `goalId ?? ""`).
- `const rates = await ctx.db.query("modelPricing").collect()` once, outside the loop, then
  `buildRateIndex(rates)`. Reading the rate table per bucket would be the fan-out shape that
  killed `evaluateInternal`.
- Emit one entry per `bucket_start`, ascending, with three provider-keyed maps: `billedByProvider`
  (sum of non-null `billedUsd`), `coveredByProvider` (sum of non-null `coveredUsd`), and
  `unpricedTokensByProvider` (sum of `promptTokens + completionTokens` for unpriced rows). The
  three maps are never merged — plan 104-10's toggle renders billed alone by default.

QUERY `costBreakdown({ period, lookbackHours })`:
- Same two reads and same join, but aggregate across buckets into one `DerivedRow` per
  `(provider, model, billingType)` — collapse `goalId`, since this is the org-wide table.
- Return `billedTotal` and `coveredTotal` as separate sums of the non-null fields, plus
  `unpricedModelCount` (distinct `(provider, model)` pairs with `priced: false`) and
  `unpricedTokenTotal`. Do NOT return a combined total field of any kind — there must be no
  single number in the response that an unsuspecting consumer could render as "the total".
- Sort `rows` by `billedUsd` descending with unpriced rows last, so plan 104-09's table has a
  stable order without client-side sorting logic.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `costDerived` public queries | Read-only, unauthenticated by the same convention as every other read query in this repo; the risk is query cost, not disclosure (no new field is exposed that `aggregates` did not already expose). |
| `aggregates` bucket contents → dollar arithmetic | Bucket dimensions originate from ingested telemetry, so `provider` / `model` are attacker-influenceable strings used as `Map` keys. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-18 | Denial of Service | `costOverTime` / `costBreakdown` / `unpricedModels` reads | mitigate | Every read is `by_type_period_bucket` with a `metric_type` equality plus a `bucket_start` lower bound; `modelPricing` is read exactly once per query and never inside a loop. No `llmMetrics` access at all — enforced by a grep acceptance criterion. This is the dominant real failure class on the single-node self-hosted instance (CLAUDE.md; RESEARCH.md Pitfall 4). |
| T-104-19 | Denial of Service | `computePeriodSpend` for a monthly budget, called hourly from the cron in plan 104-06 | mitigate | Split daily/hourly window strategy caps the read at ~31 daily bucket-sets plus ~24 hourly bucket-sets instead of ~744 hourly bucket-sets, and the two windows are disjoint by construction. Live execution timing is verified in plan 104-11, not asserted from the unit suite. |
| T-104-20 | Tampering | attacker-controlled `model` / `provider` strings from ingest used as rate-lookup keys | mitigate | Lookup is exact-match against `Map`s built from operator-authored `modelPricing` rows, so an unknown string can only ever resolve to `null` (unpriced) — it can never select a cheaper rate. `resolveRate` has no prefix, fuzzy or default matching by construction (plan 104-01 T-104-02). |
| T-104-21 | Repudiation | the displayed dollar no longer matches what Astridr reported | mitigate | The ingested value is preserved and returned under the explicitly evidence-named `reportedTotal` / `reportedCost` fields rather than deleted, so a discrepancy between what CodePulse computes and what the provider billed remains observable (D-01). |
| T-104-22 | Information Disclosure | unpriced rows exposing model ids not otherwise surfaced | accept | Model ids are already exposed by the existing `costByPeriod` / `providerBreakdown` queries and by the dashboard's own charts; no new class of information is disclosed. |
</threat_model>
