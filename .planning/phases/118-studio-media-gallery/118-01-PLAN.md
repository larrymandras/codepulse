  <action>
Create `scripts/probe-convex-storage.mjs`, a Node ESM script with zero third-party dependencies
(`node:crypto`, `node:fs`, global `fetch` only), no shebang, that performs the D-01 proof as a
single run producing a machine-readable report on stdout.

Resolve the backend API base from `process.env.CONVEX_SELFHOST_URL`, defaulting to
`http://127.0.0.1:3210`. Wrap every `fetch` in an `AbortController` with a 15000 ms timeout.

The probe performs, in order:

1. **Control-A acquisition (must run FIRST so a missing control aborts before any write).**
   `POST /api/query` with path `avatars:list` (args `{}`). Scan the returned rows for the first one
   carrying a non-empty `imageStorageId`; call it `ORPHAN_ID`. If no such row exists, `die(4, ...)`
   with the message that the null-control is unavailable and the probe therefore cannot
   discriminate. **Never continue without the control and never substitute a fabricated ID.**

2. **Control-A assertion.** `POST /api/query` with path `avatars:getImageUrl`, args
   `{ storageId: ORPHAN_ID }`. Record the raw response. The expected control result is
   `{"status":"success","value":null}`. If the value is NOT null, that is itself a finding — record
   it and continue; it means the orphaned-ID premise has changed and the run's discrimination
   argument must be restated in the evidence file rather than assumed.

3. **Mint.** `POST /api/mutation` with path `avatars:generateUploadUrl`, args `{}`. Record the
   returned URL verbatim, including its host and port.

4. **Upload.** Generate a small deterministic payload in-process (e.g. 4096 bytes from
   `crypto.createHash("sha256")` output repeated, or a fixed byte pattern — the content does not
   matter, only that its byte length is known and non-zero). `POST` those raw bytes to the URL from
   step 3 with `Content-Type: image/webp`. Record the HTTP status and the parsed `storageId`.

   **A2 handling — this is a load-bearing detail, not a nicety.** If the URL returned in step 3 has
   a host other than `127.0.0.1`, attempt the upload against the URL verbatim FIRST and record the
   result; if that attempt fails at the transport layer (DNS/connect/TLS), retry once against the
   same URL with only its origin rewritten to `http://127.0.0.1:3211`, and record BOTH attempts and
   which one succeeded. The evidence file must state which origin the watcher will have to use.

5. **Read back.** `POST /api/query` with path `avatars:getImageUrl`, args
   `{ storageId: <from step 4> }`. Record the returned URL.

6. **Fetch the bytes.** `GET` the URL from step 5 (applying the same origin-rewrite fallback rule
   as step 4). Record the HTTP status, `content-length` header, and the actual received byte count.

7. **Verdict.** Print a final block containing, one per line: `CONTROL_ORPHAN_ID`,
   `CONTROL_RESULT` (the literal value, `null` or otherwise), `MINTED_UPLOAD_URL_ORIGIN`,
   `UPLOAD_STATUS`, `NEW_STORAGE_ID`, `GETURL_RESULT`, `GET_STATUS`, `GET_BYTES`,
   `WORKING_ORIGIN`, and `VERDICT` = `PASS` only when ALL of: control resolved `null`, upload
   status is 2xx, GET status is 200, and received byte count is greater than zero. Anything else
   prints `VERDICT: FAIL` with a one-line reason. Exit 0 on PASS, exit 4 on FAIL, exit 3 on any
   transport error, exit 2 on a configuration error.

Do NOT delete the uploaded blob at the end — leave it in place as durable evidence that
`/convex/data/storage/files` is no longer empty, and say so in the script's header comment.

Do NOT print any `Authorization` header value or any environment variable value in the output.
  </action>
