<objective>
Create the media vault on disk and build the watcher's local half: walk the vault, derive each
file's content identity, pair it with its sidecar, and produce a candidate list — with an mtime
cache that avoids re-hashing unchanged files without ever letting mtime into the identity.

Purpose: this is where D-05, D-06 and D-07 are decided. `hooks/idempotency.mjs`'s own docstring
states the governing rule this repo already paid to learn — "the key must be derived purely from
payload content" — and this phase's key is the file's bytes. A path- or mtime-derived key breaks on
exactly the operations this phase ships: rename, the `trash\` move and restore, and the `G:\` mirror
round-trip.

Output: `hooks/studioWatch.mjs`'s scanning core plus its tests. **This plan performs no network
I/O, no ffmpeg, and no file mutation inside the vault** — those arrive in plan `118-08`.
</objective>

<interfaces>
**The sidecar contract this phase defines.** The design doc's tree shows `*.json` without pinning a
naming rule, and D-11 makes `/studio-generate` (plan `118-12`) the only writer, so the rule is ours
to fix. Fix it here, deterministically, and plan `118-12` writes it up as the contract document
Ástríðr will later implement against (D-10):

- Primary form: the media file's full path plus `.json` — `gen/sunset_v3.png` →
  `gen/sunset_v3.png.json`. Unambiguous even when two files share a stem across extensions.
- Accepted fallback for hand-placed files: same directory, stem plus `.json` —
  `gen/sunset_v3.json`. The primary form wins when both exist.
- Sidecar body (every field optional — an empty object and an absent file are the same state):
  `{ prompt, model, provider, style, project, params, refs, tags }`. `params` may be an object;
  the watcher serialises it to JSON text for the `params` string column.

**Candidate object** produced by the scan and consumed by plan `118-08`:
`{ absPath, filename, relPath, kind, mediaType, sizeBytes, mtimeMs, contentHash, sidecar | null,
sidecarStatus }` where `sidecarStatus` is one of `"present"`, `"absent"`, `"malformed"`.
`"malformed"` is reported and treated as absent (D-07) — never as a reason to skip the file.

`kind` derives from the top-level vault directory: `gen\` → `"gen"`, `refs\` → `"ref"`, `styles\` →
`"style"`. `mediaType` derives from the file extension against an explicit allowlist.
</interfaces>

   `contentHash` differs from anything path-derived. This is the assertion that fails if someone

   stored identity in the cache would produce different (or missing) hashes here.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host filesystem (`media-vault\`) → watcher process | Filenames, file bytes and sidecar JSON are all attacker-influenceable in principle (any process or download can write into the vault) and are untrusted input to the scanner. |
| sidecar JSON → `media` row provenance | Whatever the sidecar says becomes the row's provenance and is later rendered in the UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-06 | Tampering | path traversal — a sidecar or symlink resolving outside the vault root | mitigate | `scanVault` resolves every candidate path with `path.resolve` and refuses any resolved path that does not start with the resolved vault root; `classifyFile` is an extension ALLOWLIST, never a denylist. State both in the module and assert the allowlist in test #10. |
| T-118-22 | Denial of Service | hashing a very large video by reading it wholly into memory | mitigate | `hashFile` streams through `crypto.createHash`; `readFileSync` on a media file is forbidden and its absence is an acceptance criterion. |
| T-118-23 | Tampering | malformed sidecar aborting the scan and silently dropping files | mitigate | `readSidecar` never throws; malformed is a reported state (`"malformed"`, warned on stderr) that still yields a candidate. Tests assert candidate count equals media-file count under invalid JSON and under a JSON array. D-07's own rationale: a file vanishing from a directory you are looking at is the failure mode with no diagnostic. |
| T-118-24 | Spoofing | provenance inferred from a filename | mitigate | Test #8 uses a prompt-shaped filename as adversarial input and asserts no candidate field contains it. Inference is forbidden in the module and guarded in the suite. |
| T-118-04 | Information Disclosure | `STUDIO_API_KEY` printed by the watcher or written into the cache file | mitigate | `resolveConfig` has no default for the key, `main()` never prints it, and the cache file stores only path/mtime/size/hash. Acceptance criteria assert no secret printing. |
| T-118-25 | Tampering | tests operating on the real vault | mitigate | Fixtures are built under `os.tmpdir()` per run; an acceptance criterion requires inspecting every `media-vault` hit in the test file, using a fixed-string grep because a hand-escaped backslash pattern silently returns zero (this repo's recurring grep-false-negative class). |
| T-118-SC | Tampering | npm/pip/cargo installs | accept | Zero third-party dependencies — enforced by an automated check that every `import` specifier begins with `node:`. |
</threat_model>
