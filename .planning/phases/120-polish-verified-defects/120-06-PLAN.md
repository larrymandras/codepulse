### The jsdom trap — read this before writing the helper
`src/test/setup.ts` (138 lines) does NOT mock `window.matchMedia`, and jsdom does not implement it. The
existing in-repo precedent works precisely because it uses the OPTIONAL-CALL form:

  `src/components/control-center/ReadinessPill.tsx:39-41`
    const prefersReducedMotion = () =>
      typeof window !== "undefined" &&
      Boolean(window.matchMedia?.("(prefers-reduced-motion: reduce)").matches);

In jsdom that evaluates to `false`, so `animate-pulse` IS applied and every existing test asserting its
presence keeps passing. Writing `window.matchMedia(...)` without the `?.` throws
`TypeError: window.matchMedia is not a function`; writing a helper that defaults to `true` silently
strips the class. `src/components/brains/BrainHeaderBadge.test.tsx:401` asserts
`querySelector('[class*="status-info"].animate-pulse')` is present — that test is the tripwire.

Three more hand-copies of the same predicate already exist (`voice/AvatarAura.tsx:70`,
`voice/ShareScreenToggle.tsx:36`, `pages/Chat.tsx:73`). **Do NOT refactor those four call sites** — that
is TOKEN-03's, and D-02 forbids a refactor here. Create ONE shared helper for the NEW gates only. A new
one-line utility for new code is not the card-class-string centralization D-02 rejected; adding the same
five lines to 15 more files would be.

Note also `src/index.css` already carries a global
`@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0ms !important } }`.
That means **a visual "the pulse stopped" check cannot distinguish a gated site from an ungated one** —
the CSS already stops it either way. D-11's observable is the rendered className, so assert on that.
