<objective>
Close the one CONFIRMED live instance of D-14's defect class that plan 112-04's sweep classified as
latent, and enable the compiler guard for the dispatch-fallthrough class its tests cannot see.

Purpose: this is not speculative hardening. The exposure was traced to its emitter during 112-04's
adversarial verification. `astridr/agent/loop.py:2090-2097` sends `tool_executed` with
`"round": get_round_context()` UNCONDITIONALLY, and `astridr/engine/telemetry.py:683` declares
`get_round_context() -> int | None`. So whenever round context is unset, the payload carries an
explicit JSON `null`. `convex/runtimeIngest.ts:94` forwards it as a bare `round: d.round` — a single
reference with no alias and no guard — into `toolExecutions`'s `round: v.optional(v.float64())`,
which REJECTS an explicit null. The entire `toolExecutions` insert is lost while ingest reports
success. That is the Phase 108 `control_verb_swap` signature, live, on every tool call made outside
a round context.

Note the contrast that proves the diagnosis rather than merely asserting it: the `llm_call` emitters
guard the identical value behind `if _rnd is not None:` (anthropic_provider.py:681, ollama.py:232,
openrouter.py:361), so the key is absent there and `llm_call` is NOT exposed. `tool_executed` has no
such guard.

Output: a one-field normalization, its three-wire-shape tests, and a compiler flag. No new surface,
no schema change, no deploy — plan 112-07 deploys this alongside the rest of the phase.
</objective>
