<hard_constraints>
These are operational rules for the live single-node self-hosted instance, from CLAUDE.md and this
phase's research. Violating any of them is worse than not running the task.

- Deploy command is exactly `npx convex deploy --env-file C:\Users\mandr\convex-selfhost\selfhosted.envfile`.
  If it prompts for confirmation you may add `-y` ALONGSIDE `--env-file`, never instead of it.
- NEVER `npm run deploy`, and never a bare `npx convex deploy` or `npx convex deploy --yes` without
  `--env-file`. The retired cloud deployment `tidy-whale-981` (frozen 2026-07-15) can be targeted
  by ambient config, and that deploy exits 0 while never reaching the backend the ingest code
  talks to.
- NEVER add `--push` or `--prod` to a `convex run` probe. `convex run` is read-only; `--push`
  deploys the working tree first.
- NEVER call `events:countByType` (`convex/events.ts:310`) against the live instance - it
  `.collect()`s the firehose. Use `events:listByType`, which is indexed and bounded.
- NEVER `npx convex import --replace-all`, and never a bulk delete or bulk patch.
- NEVER run `npx convex env list` or `npx convex env get`. Against this self-hosted backend those
  print full `NAME=VALUE` pairs into the transcript. Nothing in this plan needs an env value.
- Do not construct a synthetic ingest POST. `/runtime-ingest` requires a bearer token that lives
  in the deployment env, and retrieving it would leak a credential into the session. Organic
  arrival plus paired controls is the evidence path here.
- Prefer `--env-file` over `--admin-key` on every probe so no credential value reaches a command
  line.
</hard_constraints>
