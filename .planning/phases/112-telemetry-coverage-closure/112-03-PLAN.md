<objective>
Build the Convex-side data modules for the two tables created in plan 02: an append-only
`internalMutation` write path and a bounded indexed read for each, plus the source-level security
guards that keep them that way.

Purpose: TELE-03's routing half. Per CR-01 and the repo-wide rule in CLAUDE.md, every public
Convex function is callable with no credential by anything that can route to the host - so a
public `record` mutation would be a forgeable telemetry write path that the UI would then render
as truth. `internalMutation` closes the `api.` namespace entirely.

Output: two domain modules, one shared cap module, two test files, and regenerated Convex API
types. No ingest wiring (plan 04), no UI (plan 05), no deploy (plan 07).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (any holder of VITE_CONVEX_URL) -> Convex `api.` namespace | Every PUBLIC Convex function is callable with no credential by anything that can route to the host; only 8 of ~137 modules reference `ctx.auth` |
| Convex query -> single-node SQLite instance | An unbounded read against this instance is the documented cause of the 2026-07-21/22 outage |
| Ingest dispatch -> domain table | The only legitimate write path into these tables |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-01 | Spoofing / Tampering | `governorDecisions.record`, `messageRoutes.record` | mitigate | Declared as `internalMutation`, never `mutation`, so neither exists in the client-callable `api.` namespace; enforced by a source-level CR-01 guard test in each module's test file, itself mutation-proven in Task 3's acceptance criteria and paired with a vacuity control |
| T-112-02 | Denial of Service | `governorDecisions.listRecent`, `messageRoutes.listRecent` | mitigate | Both use `.withIndex("by_timestamp").order("desc").take(CAP)` with a named constant; a source-level guard asserts `.take(` present and `.collect(` absent in each module |
| T-112-03 | Tampering | Client bundle pulling the Convex server runtime via a value import | mitigate | `GOVERNOR_DECISION_CAP` lives in a dependency-free `convex/governorDecisionsFilters.ts`; the guard test asserts `governorDecisions.ts` imports rather than re-declares it |
| T-112-13 | Elevation of Privilege | Adding `ctx.auth` gating to these mutations | accept | Explicitly REJECTED by the standing SEED-008 decision in CLAUDE.md: the tailnet is the auth boundary and hardening one module's mutations in isolation is the exact shape that was rejected. `internalMutation` is the sanctioned control here because nothing in the UI calls these writes |
| T-112-14 | Tampering | An unintended deploy during codegen | mitigate | Task 3 forbids `deploy`, `--push`, `--prod` and `--yes`; the deploy is plan 07's single explicitly-ordered blocking task and the SUMMARY must state the exact codegen invocation used |
| T-112-SC | Tampering | npm/pip/cargo installs | accept | No package is installed - Vitest and Convex are already configured repo-wide and RESEARCH.md confirms this phase introduces no new external dependency |
</threat_model>
