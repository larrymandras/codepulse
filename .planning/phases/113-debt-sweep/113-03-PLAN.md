<objective>
Make the four frontend files that compare an origin string EXACTLY against `"claude-code"` also
accept `"claude-code:plugin"`, so D-02's origin split does not silently delete ~57 skills from the
Skills page.

Purpose: research traced eight production call sites across four files that treat the literal
`"claude-code"` as "the active global scope". Ship D-02 without them and the Global tab loses ~57
rows and its count, plugin skills fall into `resolveScopeDrop`'s unrecognized-origin branch and
become undraggable, the ⋯ menu mislabels their scope, and `OriginBadge.styleFor` returns
`undefined` so they render no badge at all. DEBT-05 would "close" by making the catalog visibly
wrong in a different way.

This is behaviour PARITY work. A `claude-code:plugin` skill must behave exactly as a `claude-code`
skill behaves today at every one of these sites — this plan introduces no new policy about what
plugin skills may or may not do.

Output: eight mechanical edits, three extended test files, two new test files, and an executed
control proving the Global-tab regression was real.
</objective>
