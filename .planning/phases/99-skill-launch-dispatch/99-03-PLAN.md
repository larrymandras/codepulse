## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User arg input → handoff text | The text the user confirms becomes the executed turn (via caller → Chat.tsx) |
| Persona pick → `profile` field | Selects which SecurityContext.profile_id policy applies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-99-07 | Tampering | Arg-input text | mitigate | D-05 makes the popover a deliberate capture — nothing sends without the user pressing Enter/Send on their OWN input; no untrusted skill metadata is injected into the send without this confirmation. |
| T-99-08 | Spoofing / EoP | persona `profile` | mitigate | The picker only ever emits a value from the constrained `ProfileId` union (`PROFILES` ids); an arbitrary/higher-trust profile cannot be selected. Escalation to a higher-trust policy requires the user to explicitly pick it (matches the security-model note in the phase brief). |
| T-99-09 | Repudiation (false success) | Ástríðr copy | mitigate | Honesty guard test forbids any "answered as {persona}" claim — the UI never asserts a persona-voice override that does not exist (D-14a). |
