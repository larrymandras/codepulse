# Phase 99 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extend-don't-rebuild phase.** Every visual/interaction decision below reuses an already-shipped CodePulse primitive or pattern. No new tokens, no new shadcn installs, no new registries. Source: `99-CONTEXT.md` D-01..D-14 (locked) + live inspection of `SkillLifecycleMenu.tsx`, `QuickDeck.tsx`, `ForgeLaunchModal.tsx`, `SkillCommandPalette.tsx`, `useAstridrChat.ts`, `Reminders.tsx` (profile accent convention), `DeleteSkillDialog.tsx` (confirmation copy convention), and `src/index.css` (token values).

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from the existing house scale, reused as-is:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside menu items/chips (`gap-1`) |
| sm | 8px | Compact element spacing (`gap-2`, popover internal stack `gap-2`) |
| md | 16px | Default element spacing (popover padding `p-4`, dialog field stacks `gap-4`) |
| lg | 24px | Section padding (not newly introduced this phase) |
| xl | 32px | Layout gaps (not newly introduced this phase) |

Exceptions:
- **Icon-only trigger buttons stay at the existing 32px (`min-w-8 min-h-8`) touch target**, not the 44px WCAG-recommended minimum — this matches the already-shipped `SkillLifecycleMenu` ⋯ trigger and `QuickDeck` hover-reveal icon buttons byte-for-byte (Phase 98 precedent, not re-litigated here). The Run entry point on both surfaces (⋯ menu item, QuickDeck primary chip click) reuses these exact existing hit targets — no new sizing decision.
- Popover surfaces (arg-input, persona picker) use `w-72` (288px) fixed width with `p-4` padding, matching `KGViewsPopover.tsx`'s `w-72 p-4` precedent (not `ConnectionPopover`'s narrower `w-[280px] p-3`, since this popover holds a labeled input + helper text, closer to KGViewsPopover's content density).

## Typography

Reused from the existing scale (Tailwind defaults + `text-[Npx]` overrides already in use across `ForgeLaunchModal`/`SkillLifecycleMenu`/`DeleteSkillDialog`/`dialog.tsx`) — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dialog/Popover title | 18px (`text-lg`) | 600 semibold | 1.2 (`leading-none`) — matches shadcn `DialogTitle` default exactly |
| Body / form label | 16px (`text-base`) | 400 regular | 1.5 — matches `ForgeLaunchModal` field labels, chooser menu item text |
| Secondary / helper text | 14px (`text-sm`) | 400 regular | 1.5 — matches host/workspace hint copy, popover helper lines |
| Caption / mono invocation | 12px (`text-xs`, `font-mono`) | 400 regular | 1.4 — matches `skillInvocation()` display in `QuickDeck`/`SkillCommandPalette` |

Only 2 weights in play: **400 regular** (all body/label/caption text) and **600 semibold** (popover/dialog titles only — reserved, never used for menu items or button labels, which stay regular per existing `DropdownMenuItem`/`Button` defaults).

## Color

All values are CSS custom properties resolved at runtime by the active `data-theme` — **never hardcode hex**. Values shown are the default `cyan` theme's resolved values for reference only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` (zinc neutrals) | Popover/dialog surfaces, page background — unchanged |
| Secondary (30%) | `--popover`, `--border`, `--muted` | Dropdown/popover chrome, dividers, muted helper text |
| Accent (10%) | `--primary` (`#06b6d4` Electric Cyan in `cyan` theme) | **Reserved for:** (1) the Run trigger's hover/active tint (matches existing ⋯ trigger `hover:bg-primary/20 hover:text-primary`), (2) the checkmark/highlight on the chooser's remembered "last pick" target row, (3) the primary "Send"/"Launch" action button in the arg-input and persona popovers, (4) the "Command Deck" pulse dot (unchanged, pre-existing) |
| Destructive | `--destructive` | **Not used by any new Phase 99 surface** — Run/launch is non-destructive. Reserved exclusively for the pre-existing Delete Permanently flow (`DeleteSkillDialog`), untouched by this phase. |
| Persona accent (Ástríðr target only) | `--status-ok` (Personal), `--status-warn` (Business), `--status-info` (Consulting) | Reuses `Reminders.tsx`'s `PROFILES` accent convention verbatim (`accentVar` per `profileId`) — a small colored dot next to each persona option in the Ástríðr popover. This is a semantic-status reuse, not a new accent — do not invent a 4th "profile" color family. |
| Error/failed feedback | `--status-error` | Toast copy for a failed Chat send or unreachable Ástríðr dispatch (matches `RowStatusBadge`'s existing `failed` styling — `bg-[var(--status-error)]/20 text-[var(--status-error)]`) |

Accent reserved for: Run trigger hover state, last-pick highlight, the popover's primary Send/Launch button, and the Command Deck pulse indicator. Nothing else in this phase's new surfaces may use `--primary` as a background fill (menu items, chip borders, and popover chrome stay neutral/secondary per the existing `SkillLifecycleMenu`/`ForgeLaunchModal` precedent).

## Interaction Contract (Phase 99)

Resolves the `<decisions>` "Claude's Discretion" items from `99-CONTEXT.md` with concrete, prescriptive answers so planner/executor need no further UI judgment calls.

### 1. Run entry points (D-02)
- **⋯ menu (`SkillLifecycleMenu`, both `SkillRow` and `ColdStorageView` lanes):** add a **"Run"** `DropdownMenuItem` (icon: Lucide `Play`) as the **first** item in the menu, above the existing Archive/Restore/Move/Delete items, separated by a `DropdownMenuSeparator`. Available in every scope/lane state (dormant, active, shadowed, multi-scope) — Run never disables, since launching doesn't touch the filesystem the way lifecycle actions do.
- **QuickDeck primary chip click** becomes Run (was clipboard-copy). The hover-reveal icon group changes from `[MessageSquare (open in chat), Star (favorite)]` to `[Copy (clipboard, D-03), Star (favorite)]` — the passive "open in chat" affordance is retired (superseded by the Chat target inside the chooser, D-05/D-06); clipboard copy survives as the small secondary icon.
- **`SkillCommandPalette` is untouched** — no Run item added there (D-02). Its existing Enter-to-copy / Ctrl+Enter-open-in-chat behavior stays exactly as shipped.

### 2. Chooser component (D-01, discretion resolved)
**`DropdownMenu`**, not `Popover` — mirrors `SkillLifecycleMenu`'s existing ⋯ menu construction exactly (same file pattern, same primitive, zero new interaction paradigm). Three items, icon + verb-noun label each:
- `Play`/`MessageSquare` icon — "Send to Chat"
- `Play`/`Bot` (or `Rocket`) icon — "Launch as Forge Agent"
- `Play`/`Sparkles` icon — "Dispatch to Ástríðr"

The item matching the remembered last pick renders with a leading checkmark and `text-primary` tint (visual-only, no extra copy — see Copywriting Contract).

### 3. Last-pick persistence (D-01, discretion resolved)
**`localStorage`**, not Convex. Key: `codepulse-skills-run-target`, value one of `"chat" | "forge" | "astridr"`. Mirrors `Reminders.tsx`'s `codepulse-reminders-profile` `STORAGE_KEY` convention exactly (read on mount with `isValidTarget` guard + `"chat"` fallback, written on every successful pick). No server round-trip needed — this is a pure per-browser UX convenience, not shared state.

### 4. Target-specific follow-up step (D-04/D-05/D-07/D-08/D-09)
Choosing a chooser item opens exactly one follow-up surface, anchored to the Run trigger:

- **Chat** → a `Popover` (`w-72 p-4`) containing: title "Run {displayName}" (18px semibold) → an `Input` prefilled `/{skillname} ` (cursor after the space, not auto-selected) → helper text "Press Enter to send, or add arguments first." → primary "Send" `Button`. Enter in the input or clicking Send calls `useAstridrChat().sendMessage(value)`, then `navigate('/chat')`, then `recordSkillLaunch`. Escape/outside-click closes with no side effects (D-05: never leaves a prefilled-and-waiting composer — either it fires or nothing happens).
- **Forge** → opens the existing `ForgeLaunchModal` directly (no intermediate popover) with its `prompt` state initialized to `/{skillname} ` instead of empty (D-11). All other modal behavior (host/agent/workspace/mode picker, submit) is unchanged. On successful `enqueueLaunch`, call `recordSkillLaunch`.
- **Ástríðr** → a `Popover` (`w-72 p-4`), same shell as Chat's but with one extra control stacked above the input: a "Answer as" label + 3-way persona segmented control (reusing `Reminders.tsx`'s `PROFILES` list — id/label/accentVar — rendered as small colored-dot + label pills, one active at a time, defaulting to whatever profile is currently active app-wide if determinable, else "Personal"). Below it, the identical prefilled `/{skillname} ` input + Send button. Submit routes through whatever persona-scoping mechanism the phase's technical research (D-14, run at `/gsd-plan-phase`) confirms exists — if a true per-turn override is unavailable, the UI still renders and sends (per D-09, codepulse-only v1 ships against whatever the channel supports); it must never claim a persona override happened if it didn't — copy stays limited to "Send" with no "as {persona}" success confirmation unless the researcher confirms the override is real end-to-end.

### 5. Usage recording (D-12/D-13)
`recordSkillLaunch` fires exactly once per successful real execution — on `sendMessage` resolving, on `enqueueLaunch` resolving, and on the Ástríðr dispatch resolving. It does **not** fire on the QuickDeck copy-icon click (D-13) or on popover cancel/escape.
