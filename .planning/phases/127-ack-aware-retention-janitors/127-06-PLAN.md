`convex/crons.ts` registration form, from the `studio-trash-prune` entry:
`crons.daily("studio-trash-prune", { hourUTC: 7, minuteUTC: 0 }, internal.media.pruneTrashBatch, {});`
A four-argument form with a trailing `{}` args object is the convention for a janitor that
takes optional args. `crons.ts` currently ends with `export default crons;`.

`convex/retentionCoverage.ts`:
- `COVERAGE_BOUNDED_BY_CRON: Record<string, string>` — table → the `internal.*` function that
  bounds it. Current entries include `media: "internal.media.pruneTrashBatch"`.
- `COVERAGE_PRUNE_PROPOSED: Record<string, { rowsPerDay, proposedDays, note }>` — currently
  holds `inbox` and `ideationFindings` as its first two entries.

`convex/retentionCoverage.test.ts` enforces, among others:
- every schema table appears in EXACTLY ONE bucket (a table in two buckets fails);
- every `COVERAGE_BOUNDED_BY_CRON` value appears in the COMMENT-STRIPPED `crons.ts` source;
- the comment-stripping filter is itself controlled in both directions — a live cron must
  survive stripping and the known-commented `internal.archival.markStaleArchived` must not;
- a proposed table is never already enrolled in `RETENTION_DAYS`.
