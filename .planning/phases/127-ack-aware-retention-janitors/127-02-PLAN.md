<objective>
Build `internal.inbox.autoCloseAndPrune`: a bounded, cursor-seeked, self-rescheduling two-step
chain that stamps `closedAt` on stale-open and already-acked `inbox` rows, then permanently
deletes rows 14 days past closure.

Purpose: `inbox` grows at ~100 rows/day and 83.7% of it has never been acked. A calendar prune
cannot bound it without deleting items the operator never saw; an `ackedAt`-keyed prune reaches
at most 16% of the table. Auto-close into a dedicated lifecycle field bounds 97.3% of the
growth without touching the field two frontend surfaces read as "the operator saw this".

Output: constants, two step predicates, one exported handler, one `internalMutation` wrapper —
all in `convex/inbox.ts`, beside the rest of that table's mutations (D-01).
</objective>

    a range on `closedAt`: seek from the cursor, bound above by
    `nowSec - INBOX_CLOSED_GRACE_SEC`, order ascending, `.take(INBOX_JANITOR_BATCH_SIZE)`.

    than merely filtered out of it — Convex's index value ordering is `undefined < null < all
    other values` (cited at `convex/controlVerbSwaps.ts:97-117`, independently re-derived at
    `convex/media.ts:733-736`), so an absent `closedAt` sorts below any real cursor. A
    not-yet-closed row cannot be reached by this query even if every post-query predicate in the

    Split with `partitionBatchForPrune(batch, shouldDeleteClosed, (doc) => doc.closedAt ?? 0)`
    and `ctx.db.delete` each returned row. Advance the cursor from `lastCursorValue`.

    **The chain.** One exported handler,
    `autoCloseAndPruneHandler(ctx, args, nowSec)`, with args
    `{ step?: "closing" | "deleting"; cursor?: number; batchesDone?: number }`, defaulting to
    `step: "closing"`, `cursor: 0`, `batchesDone: 0`. One `internalMutation` wrapper,
    `autoCloseAndPrune`, whose `v.` validators mirror those args and whose body calls
    `autoCloseAndPruneHandler(ctx as JanitorCtx, args, Date.now() / 1000)`. Note the `/ 1000` —
    the handler's third parameter is SECONDS.

    Entry guard first, before any read: if `batchesDone >= INBOX_JANITOR_MAX_BATCHES`, log and
    return doing zero work, exactly like `media.ts:720-725`.

    Transition rules:
    - `"closing"`, full batch → reschedule `"closing"` with the advanced cursor and
      `batchesDone + 1`.
    - `"closing"`, short batch → the open set past the cutoff is drained; reschedule
      `"deleting"` with `cursor: 0` and `batchesDone + 1`.
    - `"deleting"`, full batch → reschedule `"deleting"` with the advanced cursor and
      `batchesDone + 1`.
    - `"deleting"`, short batch → the chain is done. Log and return without rescheduling.

    **Carry `batchesDone` ACROSS the `"closing"` → `"deleting"` transition; never reset it.**
    Resetting would give one chain invocation a fresh full budget for its second step, doubling
    the worst case with no cap governing it. Only the cursor resets, because the two steps range
    over different fields.

    Every reschedule decision must ALSO be gated on `batchesDone + 1 < INBOX_JANITOR_MAX_BATCHES`
    — the batch already in flight still completes, but the chain must not reschedule past its
    own ceiling. That is `media.ts:765-779`'s exact arithmetic.

    **Log unconditionally on every invocation**, including a zero-work one — one line naming the
    step, rows acted on, the next cursor, and whether it rescheduled. `media.ts` logs only when
    `deletedCount > 0`; deviate deliberately here, and say why in the comment: R-01 makes the
    ran-and-matched-nothing line a hard requirement for the sibling `ideation` janitor, and
    Verification F reads `docker logs convex-backend` rather than the cron's own success line,
    so a silent invocation is invisible to the only instrument that can see the failure mode.

    Return `{ step, actedCount, nextCursor, rescheduled }` so the tests can assert the chain
    decision directly rather than inferring it from mock call counts.

    Do NOT touch `listHeldUnackedHandler`, `countHeldUnackedHandler` or `dismissAllCardsHandler`
    (D-11). Do NOT add an outer force-expire ceiling for carve-out rows (R-03).
