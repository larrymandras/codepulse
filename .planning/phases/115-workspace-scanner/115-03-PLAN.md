<!-- A KNOWN DEFECT in the upstream draft. Do not transcribe it. -->

`115-RESEARCH.md` § "Code Examples" proposes:

`const canonical = JSON.stringify(report, Object.keys(report).sort());`

**This is wrong and must not be used.** `JSON.stringify`'s second argument, when an array, is a
key **allowlist**, not a sort order. Consequences, both of which silently break the gate:

1. It filters keys at EVERY nesting level, so any nested key whose name is not also a TOP-LEVEL key of
   `report` is **dropped from the serialization entirely** — a change to, say, a per-department count
   nested two levels down would produce the SAME hash, and the gate would pass a report whose content
   had materially changed. That is a gate that reports green without having evaluated the thing.
2. It does not sort output; object key order in the output still follows the array's order per object,
   so it does not deliver the stability it was reaching for either.

**Use a recursive canonical serializer instead** (specified in Task 1). Write a test that would have
caught the defective version — mutate a NESTED field and assert the hash changes. This is the load-
bearing regression guard for this whole module.

The five-case contract is fixed by `115-VALIDATION.md` § "Mandatory mutation test — D-12's refusal
(BLOCKING)". Do not re-derive the cases; implement 1-4 here verbatim.

The no-shebang constraint applies (`hooks/scanner.mjs:5-10`): Vite/Rolldown's SSR module transform
hoists imports above line 1 and a shebang there breaks parsing with `Invalid Character '!'`. This
module is imported by its own test file.

- `export function stableStringify(value)` — a recursive canonical serializer:
  - `null`, numbers, booleans, strings → `JSON.stringify(value)`.
  - Arrays → `"[" + elements.map(stableStringify).join(",") + "]"`. **Order is preserved** — array
    order is semantically meaningful in the report (e.g. the Unclassified root list is ordered), so do
    NOT sort arrays.
  - Plain objects → `"{" + Object.keys(obj).sort().map(k => JSON.stringify(k) + ":" + stableStringify(obj[k])).join(",") + "}"`.
    Keys sorted at EVERY level — this is the property `JSON.stringify`'s replacer array cannot give you.
  - `undefined` object values are omitted (matching `JSON.stringify` semantics) so an explicitly-set
    `undefined` and an absent key hash identically.
  - Non-finite numbers (`NaN`, `Infinity`) → serialize as `null`, matching `JSON.stringify`, and note
    this in a comment: a report field that goes `NaN` (e.g. a division by a zero file count) must not
    make the hash nondeterministic.

- `export function canonicalReportHash(report)` — `createHash("sha256").update(stableStringify(report), "utf8").digest("hex")`.
  Import `createHash` from `node:crypto`.

- `export function isDryRunApproved(reportHash, approvalFileContents)` — **fail closed**:
  - `if (typeof reportHash !== "string" || reportHash.length !== 64) return false;` — a malformed hash
    can never approve anything.
  - `if (typeof approvalFileContents !== "string") return false;` — covers `null`/`undefined`, i.e. no
    marker at all.
  - Return `approvalFileContents.trim().toLowerCase() === reportHash.trim().toLowerCase()`.
  - The comparison is a plain string equality, not a prefix/`startsWith`/`includes` match. A substring
    comparison would let a marker file containing extra content approve a different report.
  - No I/O, no `existsSync` — the caller reads the file and passes `null` when it is absent. That split
    is what makes this unit mutation-testable.

- `export function buildApprovalMarkerContents(reportHash, meta)` — returns the exact text to write to
  the marker: the bare 64-char hex hash on line 1, then optional `#`-prefixed comment lines carrying
  `meta` (e.g. the approval timestamp and the scanner version). `isDryRunApproved` must therefore
  tolerate a marker with trailing comment lines — implement it by comparing only the FIRST non-empty,
  non-`#` line. Update `isDryRunApproved` accordingly and test that shape explicitly, otherwise the
  helper and the checker disagree.

Add a header comment recording: this module implements CONTEXT.md D-12; the refusal must remain
