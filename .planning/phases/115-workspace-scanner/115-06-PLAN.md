`export const workspaceIngestPostHandler = async (ctx: any, request: Request) => {...}`:

1. `if (!validateIngestAuth(request)) return unauthorizedResponse();` — the **first executable
   statement**, before any `ctx.db`/`ctx.runMutation` access. Comment it with the reason: an
   unauthenticated caller must not be able to probe stored state via response-code differences.
2. `let body: any; try { body = await request.json(); } catch { return jsonResponse({ error: "INVALID_JSON" }, 400); }`
3. Field validation, each a distinct 400 so a producer bug is diagnosable rather than a generic failure:
   - `snapshotId` must be a non-empty string → else `{ error: "MISSING_FIELD", field: "snapshotId" }`.
   - `dirs` must be an Array → else `{ error: "MISSING_FIELD", field: "dirs" }`.
   - `dryRunReportHash` must be a 64-char hex string → else
     `{ error: "MISSING_FIELD", field: "dryRunReportHash" }`. The host gate (D-12) is the real control;
     this is a shape check so a snapshot cannot be stored with an unrecorded provenance, not a second
     gate. Say so in a comment — do not let a future reader mistake it for the D-12 gate and then
     "simplify" the host-side one away.
   - `generatedAt` must be a finite number → else a 400. Also **reject a value that looks like
     milliseconds**: this repo has been bitten twice by epoch seconds/millis confusion producing 1970
     dates and vacuously-passing cutoff comparisons. Refuse `generatedAt > 1e12` with
     `{ error: "BAD_UNIT", field: "generatedAt", expected: "epoch seconds" }`.
   - Booleans (`scannedRootsComplete`, `accessDerivationOk`) must be actual booleans, not truthy
     values — `typeof x === "boolean"`, else a 400. An explicit `null` arriving where
     `v.boolean()` is declared is rejected by Convex outright, and this repo has a documented incident
     where exactly that mechanism made a route land zero rows while reporting `dropped: 0`.
   - Arrays (`coveredRoots`, `unclassifiedRootIds`) must be arrays of strings.
   - `rootCount` must be a finite number; `localConfigStatus` must be one of
     `"merged" | "absent" | "version-mismatch"`.
   - **Bound the payload:** refuse when `dirs.length` exceeds a named constant
     `const MAX_DIRS_PER_INGEST = 20000;` with `{ error: "PAYLOAD_TOO_LARGE", dirs: n, max: 20000 }` and
     status 413. Rationale in a comment: the mutation chunk-inserts at 1,000 per batch under a
     ~16,000-doc per-invocation write ceiling and shares that budget with its own inline prune, so an
     unbounded `dirs` array is a denial-of-service vector against the single-node self-hosted backend.
     Refusing at the route is cheaper than a half-written version.
   - Validate each element of `dirs` has the eight required keys with the right primitive types, and
     refuse the whole request on the FIRST bad element with its index —
     `{ error: "BAD_DIR_ROW", index: i, field: "..." }`. Do not silently drop bad rows: a dropped row
     becomes a missing directory in the map with no signal, which is the failure shape this project has
     been burned by.
4. `const result = await ctx.runMutation(internal.workspace.upsertWorkspaceSnapshot, {...})` — forward
   every validated field explicitly by name. No spread of the raw `body`.
5. Return `jsonResponse({ ok: true, version: result?.version, prunedVersion: result?.prunedVersion, pruneIncomplete: result?.pruneIncomplete }, 200)`.
   If plan 115-04's mutation does not return those fields, either read its return shape and match it, or
   add the return there — say which you did in the SUMMARY. The version number in the response is what
   plan 115-09's live proof asserts on.
6. Wrap steps 4-5 so an unexpected mutation throw becomes a 500 with a generic message and the real
   error logged server-side. **Never echo the request body in an error response** — it carries directory
   paths.
