<objective>
Ship the sharding change: one new constants module, one additive optional schema field, a shard parameter threaded through the three write-path helpers, and a single shard draw per ingest call.

Purpose: `events.ingest` currently funnels every concurrent write for a given `(metric_type, period, bucket_start, dimensions)` tuple through ONE document, and Convex's OCC layer serializes the collisions by retrying. Live measurement on 2026-08-05 put that at ~644 retries/hour on the `aggregates` table alone, with a single document accounting for 35% of them. Spreading the write across 8 rows that every reader already sums removes the hot document without touching any reader and without rewriting any history.

Output: `convex/lib/aggregateShard.ts` (new), plus edits to `convex/schema.ts`, `convex/analyticsRollup.ts`, `convex/events.ts`. This plan does NOT deploy — plan 107-04 captures the pre-deploy baseline and plan 107-05 deploys.

**Deliberately NOT changed, and each for a verified reason:**
- `convex/analyticsRollupQueries.ts`, `convex/analytics.ts`, `convex/aggregates.ts` — every reader already accumulates across all rows sharing its group key (`heatmapFromAggregates:43`, `errorRateTrendFromAggregates:75`, `sankeyFromAggregates:108`, `eventCountsByPeriod:841`, `rollupDaily:444`). Plan 107-02 turned that into a regression guard. Do not add a `sumAcrossShards` helper — it would have zero call sites; CONTEXT.md strikes it on disk as a no-op abstraction.
- `insertBucketsBatch` / `backfillHistorical` (`analyticsRollup.ts:262-362`) — single-writer batch action with no concurrency to spread. Leaving its inserts unsharded is compatible with the read contract (a missing `shard` is just another row that gets summed) and keeps every historical-data path consistent.
- Both existing indexes on `aggregates`. `shard` is deliberately unindexed, exactly like `dimensions` is today (see the file's own "Pitfall 3" header comment) — the lookup stays ONE index-bounded `.collect()` with one more field checked in JS, not a fan-out across 8 index queries.
</objective>
