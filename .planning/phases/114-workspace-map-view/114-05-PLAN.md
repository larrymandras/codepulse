<objective>
Build the first half of the pure layout module: `buildTree` (parent→children adjacency over the flat
`dirs` array) and `computeRollups` (subtree-aggregated counts).

Purpose: D-04 is a correctness requirement, not a cosmetic one. `convex/schema.ts` records
`fileCount`/`totalSize` as **direct contents only** — "VISIBLE files directly in this directory only
— never withheld files, never subdirectories' files" — so without a rollup a collapsed root that
contains a thousand directories renders as a handful of files and reads as broken. Everything the map
sizes, labels and panels depends on these two functions being right.
Output: a pure module with zero React/Convex imports, and its test suite.
</objective>

  <action>
    Implement `computeRollups(tree: DirTree): RollupMap`, returning subtree-inclusive totals for
    `fileCount`, `totalSize` and `withheldCount` keyed by `nodeKey`.

    Algorithm: sort node keys once by **descending depth**, then walk that order accumulating each
    node's own direct values plus its already-computed children's rolled-up totals. Because children
    are strictly deeper than their parent, every child is finished before its parent is visited — so
    this is O(n) with no recursion and no node visited twice. Do not implement it as a recursive
    depth-first walk: the tree is 8 levels deep today but a recursive implementation makes depth a
    stack-size dependency for no benefit.

    Do **not** mutate the input rows. The direct-contents values from the payload must remain readable
    unchanged — the side panel (D-09) shows **both** the direct figure and the rolled-up figure,
    explicitly labeled, so if the rollup overwrites the direct value that requirement becomes
    unsatisfiable. Rollups are a parallel derived map.

    Do not roll up any byte figure keyed to withheld files. The schema deliberately does not carry
    one; deriving one client-side would reconstruct exactly the side channel the producer refused to
    emit.

    Tests in `src/lib/workspaceMapLayout.test.ts`:
    - **The D-04 proof**: for a known synthetic root in the fixture, assert the rolled-up `fileCount`
      equals the independently-computed sum of every descendant's direct `fileCount` **plus its own**
      — compute the expected value in the test by filtering the flat `dirs` array by `rootId` and
      summing, so the assertion is derived from the input rather than from the function under test.
      An assertion that just re-runs the implementation's own logic proves nothing.
    - The same for `totalSize` and `withheldCount`.
    - A **leaf** node's rollup equals its own direct values exactly (the degenerate control — a
      rollup that double-counted would fail here first).
    - The input `dirs` rows are unmodified after the call: deep-equal the array against a
      pre-call structured clone.
    - Depth ordering is not required of the caller: shuffle the input `dirs` (e.g. `.slice().reverse()`)
      and assert the resulting `RollupMap` is deep-equal to the forward-order result.
  </action>
