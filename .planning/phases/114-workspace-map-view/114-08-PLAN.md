Build the node-detail side panel (D-09) with privacy-aware labels (D-15).

snapshot carries a withheld count per directory so the omission is visible in the map rather than

  <action>
    Create `WorkspaceMapPanel.tsx` — a shadcn `Sheet` with `side="right"`, opening on any node
    selection. Props: the selected `WorkspaceMapNode | null`, an `open` boolean, and an
    `onOpenChange` callback.

    **Body field order for a `kind === "dir"` or `kind === "root"` node:**
    1. Header — the node's display label (masked per below).
    2. Department `Badge`, filled with that department's color.
    3. Access `Badge` — rendered as plain language, **"Reachable by Ástríðr"** or **"Local only"**,
       never the raw enum string.
    4. Direct file count and direct byte size, labelled **"direct"**.
    5. Rolled-up file count and rolled-up byte size, labelled **"total incl. subdirectories"**.
       Both figures must appear with both labels — this is D-09's "both figures" requirement, and the
       whole point is that the reader can never confuse the two. The direct values come from the
       node's `direct`, the rolled from its `rolled`; do not compute either in this component.
    6. `latestMtime` as a relative time. It is epoch **seconds** — multiply by 1000 before handing it
       to any `Date` construction.
    7. **Withheld notice — rendered if and only if `withheldCount > 0`:** a labelled row reading
       "{withheldCount} file(s) withheld", plus body text: "Classified sensitive by the local scanner
       config — never left this machine. Only the count is recorded, never the name." The second
       sentence states the schema's own side-channel rule back to the reader, so the notice is honest
       about its own precision rather than only its existence. Pluralize correctly.
    8. Expand/leaf hint — "{N} more subdirector(y/ies) not shown — click the node to expand." when the
       node has unexpanded children, or "No further subdirectories." for a leaf.

    A `fileCount: 0, withheldCount: 0` node gets **no special copy** — its direct row simply reads
    "0 files" like any other count. The distinction between that and `fileCount: 0, withheldCount: 12`
    surfaces entirely through the withheld notice, which is the only place UI-SPEC gives it a home;
    no third canvas- or panel-level visual channel is added.

    **Hub nodes** (`kind === "center"` or `"department"`) show a reduced set: the label, and for a
    department hub its total directory and file counts — read off the node as `node.dirCount` and
    `node.rolled.fileCount`, both populated by `layoutNodes` (plan 114-07, their sole producer) and
    labelled here as "directories" and "files, total incl. subdirectories". The panel computes
    neither, exactly as it computes neither of the per-directory figures above. No `access` field, no
    withheld notice — those are per-directory facts a hub does not itself carry.

    **Masking (D-15).** Gate on `enabled && maskPaths` read from `usePrivacy()`, then:
    - a **root** node's label becomes `"{department} root {index}"` (e.g. "Consulting root 3"), the
      index assigned by descending rolled-up file count within the department and stable across
      renders. Not a bare placeholder: 53 identical `"••••••"` labels would read as broken rather
      than as deliberately redacted, and roots are the map's primary navigational anchor. The index
      must be supplied by the caller (the canvas already computes it for its own labels) rather than
      recomputed here from data the panel does not hold.
    - a **directory** node's label (depth ≥ 1) becomes the plain `redact()` placeholder `"••••••"`.
    - department hubs, the center hub, **all counts, all colors and the access badge are never
      masked** — D-15 is explicit that structure, counts and colors stay intact. Only string labels
      are affected.

    Masking is off by default (`level: "off"`), so daily use is unaffected.

    Fallback: when `open` is true but the selected node is `null` (e.g. the node was collapsed out
    from under the panel), render the `Skeleton`/plain-text fallback rather than stale content — a
    panel must not go on describing a node that is no longer in the visible set. This closes
    114-RESEARCH.md § Open Question 2, whose recommendation was exactly this; the canvas (plan 114-09)
    owns clearing the selection.

    No hardcoded hex. Lucide icons only.

    Write these tests, all asserting on user-visible text:

    **Withheld notice, both directions.** A node with `withheldCount: 0` renders **no** withheld
    notice — assert the explanatory sentence is absent. A node with `withheldCount: 12` renders it,
    including the "never left this machine" sentence. Both directions are required: a presence-only
    test would pass against a component that renders the notice unconditionally, which is the exact
    failure mode D-09's "if and only if" wording guards against.

    **Direct vs rolled-up.** Give a node deliberately different direct and rolled figures (e.g. direct
    3 files, rolled 1,041 files) and assert **both** numbers are present **and** each is adjacent to
    its own label. If the component rendered only one of them the test must fail — so assert on the
    label-plus-value pairing, not merely that "1041" appears somewhere in the DOM.

    **The two zero-file cases are distinguishable.** Render `fileCount: 0, withheldCount: 0` and
    `fileCount: 0, withheldCount: 12` and assert the two renders differ, specifically on the presence
    of the withheld notice. 114-CONTEXT.md § Specific Ideas names these as facts the map must not
    conflate.

    **Access copy.** Assert the panel shows "Reachable by Ástríðr" / "Local only", and that the raw
    enum strings `astridr-reachable` / `local-only` appear **nowhere** in the rendered output.

    **Masking, three cases.**
    - Privacy off (the default) → the synthetic root label renders verbatim.
    - Privacy on with `maskPaths: true` → a root node's label matches the
      `"{department} root {index}"` form, a directory node's label is the `"••••••"` placeholder, and
      **the counts, department badge and access badge are unchanged from the unmasked render**. That
      last clause is the load-bearing one — D-15 says structure, counts and colors stay intact, so a
      component that masked everything would satisfy a masking-only assertion while violating the
      decision.
    - Privacy `enabled` but `maskPaths: false` → labels render **unmasked**. This is the case that
      discriminates a correct `enabled && maskPaths` gate from a bare `redact()` call, since
      `redact` alone is gated on `enabled` only (`usePrivacyMask.ts:38-42`). Comment that reasoning
      in the test.

    **Department hub fields.** Construct a `kind === "department"` node with deliberately distinct
    non-zero `dirCount` and `rolled.fileCount` values (the type comes from plan 114-05, so this test
    needs nothing from plan 114-07) and assert **both numbers render, each adjacent to its own
    label** — the values, not merely the labels, so a `0`/`undefined`/label-only render fails here
    rather than at the operator checkpoint. Assert the same render shows no access badge and no
    withheld notice.

    **Fallback.** `open` true with a `null` node renders the fallback, not stale content from a
    previous node.

    All root and directory names in this file are invented.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Real workspace directory names → the rendered screen (and any screenshot of it) | The panel renders the most identifying string in the payload — a full `dirPath` under a root that may be a client engagement. `PrivacyContext` is the app-wide control on this boundary. |
| Withheld-file metadata → the reader | The producer deliberately emits a count and no byte total. The panel must not widen that channel. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
