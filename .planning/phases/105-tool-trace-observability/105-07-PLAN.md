**F1 — the kind→colour→label mapping is LOCKED by the UI-SPEC, not per-instance discretion.**
CONTEXT.md: "the boot-degrade vs reload-rejected distinction is load-bearing... never collapse the
two." Reproduce it exactly:

| Kind | Alerts (D-06)? | Badge token | Badge label |
|---|---|---|---|
| `malformed_policy_boot` | Yes | `var(--status-error)` | `Boot degraded to permissive` |
| `malformed_policy_reload_rejected` | Yes | `var(--status-warn)` | `Reload rejected — prior policy kept` |
| `tool_call_leaked_as_text` | No | `var(--status-warn)` | `Leaked as text` |
| `execution_denied` | No | `var(--status-info)` | `Blocked by policy` |

`execution_denied` MUST render neutral, not alarming. D-06's own rationale: a denial is the policy
WORKING — Ástríðr returns a self-correcting string and deliberately does not count it against the
failure-rate circuit breaker (`loop.py:2105-2109`). Colouring it like a warning trains operators to
ignore real signals.

**F2 — the alert marker is a UI-SPEC requirement, not decoration.** The two alerting rows render a
Lucide `Bell` (already mapped as `iconComponents.bell` in `src/lib/navRegistry.ts`) with an
`InfoTooltip` reading `This also raised an alert via the existing alert-routing layer` — so an
operator scanning the feed can tell, without leaving the page, which rows already woke someone up.

**F3 — which fields each kind actually carries** (verified in astridr-repo, so the detail panel does
not render a wall of `undefined`):

| Kind | Fields present |
|---|---|
| `malformed_policy_boot` | `field`, `error` — and NO `tool`, NO real session (routed under the synthetic `system:bootstrap` session) |
| `malformed_policy_reload_rejected` | `field`, `error` — same, no tool |
| `execution_denied` | `tool`, `sessionId` |
| `tool_call_leaked_as_text` | `tool`, `taskCategory`, `sessionId`, plus plan 105-02's `toolWasOffered`, `toolsOfferedCount`, `round`, `agentId` |

Render only the fields a row actually has. A boot row must NOT show an empty "Tool:" line, and a
row from BEFORE plan 105-02 deploys will have `toolWasOffered === undefined` — which is not `false`
and must not render as "was not offered".

**F4 — `toolsOfferedCount` has three states, not two.** `undefined` means "no tool filter was
active on that turn"; `0` means "the filter offered zero tools"; `n > 0` is a count. The astridr
expression `len(_permitted) if _permitted is not None else None` preserves that distinction
deliberately. Collapsing `undefined` to `0` in the UI destroys the diagnosis.

**F5 — this plan creates no page and no route.** `src/pages/Tools.tsx`, `src/App.tsx` and
`src/lib/navRegistry.ts` belong to plan 105-08 and must not appear in this diff. That separation is
what lets this plan run in parallel with 105-06.

**F6 — do not wrap in `SectionErrorBoundary` here.** Plan 105-08 owns the page-level wrapping (D-16,
one boundary per stacked section). A double wrap catches at the wrong granularity. Also do not copy
`SectionErrorBoundary`'s own hardcoded-hex styling as a template — it is pre-existing debt flagged
for Phase 106.
