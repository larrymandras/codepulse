<planner_findings>
Verified live 2026-08-03.

**F1 — "source" cannot be a plain `provider` equality check.** The UI-SPEC's four filter options are
"Ástríðr" / "Claude Code" / "Gateway" / "All sources", but the underlying `provider` values do not
partition that way:
- Ástríðr rows (plan 105-03): `provider === "astridr"` — clean.
- Gateway rows: `provider` is the gateway's own id (`codex`, `antigravity`, `claude-sdk`, and
  **`claude-cli`**) with `toolName` of the form `gateway:{provider}`. So `claude-cli` COLLIDES with
  the Claude Code hook rows.
- Claude Code hook SUCCESS rows: `provider === "claude-cli"`.
- Claude Code hook FAILURE rows, otel `tool_result` rows and execution-terminal rows: `provider` is
  **absent entirely** (`convex/ingest.ts:168`, `convex/otelLogs.ts:169`, `convex/runtimeIngest.ts:761`).

Therefore classify by a pure function over `(toolName, provider)`:
`provider === "astridr"` → `"astridr"`; else `toolName.startsWith("gateway:")` → `"gateway"`; else
→ `"claude-code"`. This correctly absorbs the provider-less rows and resolves the `claude-cli`
collision by tool name. The same function works on aggregate dimension objects, because plan 105-04
keys its buckets on exactly `{ tool, provider }`.

**F2 — metric types and dimension key come from plan 105-04.** `tool_calls`, `tool_failures`,
`tool_duration_ms`, `tool_duration_samples`; `period: "hourly"`; `dimensions: { tool, provider }`.
Read 105-04's SUMMARY for the final names before writing the query — if they differ from this list,
the SUMMARY wins and you must say so in yours.

**F3 — absent duration buckets mean "not measured", not zero.** Plan 105-04 deliberately writes NO
`tool_duration_*` bucket for a dimension where no row reported a duration. The read path must
therefore render `n/a` for that tool's average, never `0ms`. Computing `sum / samples` when
`samples` is 0 or absent must yield `null`, not `NaN` and not `0`.

**F4 — `FlexBarChart`'s `StackedSegment.color` accepts a CSS var string.** Verified: it is passed
straight to `style={{ backgroundColor: seg.color }}`, so `"var(--status-ok)"` works. The interface
comment says `// hex color e.g. "#22c55e"` — that comment is stale relative to the token system;
pass CSS vars and do not introduce hex.

**F5 — this plan creates no page and no route.** It exports a component. `src/pages/Tools.tsx`,
`src/App.tsx` and `src/lib/navRegistry.ts` belong to plan 105-08 and must not appear in this plan's
diff — that separation is what lets this plan run in parallel with 105-07.

**F6 — `SectionErrorBoundary` is pre-existing hex debt** (`bg-gray-800/50`, `border-red-500/30`,
`text-red-400`, …). Wrap with it (plan 105-08 does the wrapping) but do NOT copy its styling as a
template for anything new here. Flag as a Phase-106 candidate; do not modify it.
