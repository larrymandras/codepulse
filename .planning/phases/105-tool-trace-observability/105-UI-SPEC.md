# Phase 105 — UI Design Contract

> Visual and interaction contract for Tool & Trace Observability (OBS-01, OBS-02, OBS-03).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds to an already-locked, 100+-phase-old design system.** Nothing below invents a
> new visual language — every token, component, and copy voice is either lifted verbatim from an
> existing file (cited by path) or is a direct, minimal extension of one. Where this spec's
> defaults (spacing exceptions, weight count) diverge from the template's generic guidance, that
> divergence is the *existing* codebase convention, not a new decision made here.

## Spacing Scale

Base 8-point scale (template default), **plus the codebase's standing half-step exceptions** —
already pervasive in the components this phase extends (`ToolExecutionPanel.tsx` `gap-1.5`,
`InfoTooltip.tsx` `ml-1.5`, `MetricCard.tsx` `p-5`). Do not "fix" these to strict 4px multiples;
matching sibling components matters more than a stricter scale this phase didn't set.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding |
| sm | 8px | Compact element spacing, filter pill gaps |
| md | 16px | Default element spacing, panel `p-4` |
| lg | 24px | Section padding, panel `p-6` (glow-card convention) |
| xl | 32px | Layout gaps between stacked sections |
| 2xl | 48px | Major section breaks (Usage section → Policy section on the Tools page) |
| 3xl | 64px | Page-level spacing (not used on this phase's single-column page) |

Exceptions (inherited, not introduced): `6px` (`gap-1.5`/`ml-1.5`, filter row + tooltip trigger
spacing), `10px` (`p-2.5`, compact stat tiles). Both already appear in `ToolExecutionPanel.tsx`,
which this page directly links to (D-15) — new Tools-page filter rows and stat tiles must match,
not diverge.

## Typography

Reuses the existing scale verbatim (`PageHeader.tsx`, `SectionHeader.tsx`, `MetricCard.tsx`,
`ToolExecutionPanel.tsx`). This phase introduces **zero new sizes or weights** — the two weights
below are the ones every *new* text this phase renders should use; `700` (page title, via
`PageHeader`) is listed separately because it is produced by an already-built shared component,
not a choice made here.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cells | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Section/panel label, badges, filter pills | 14px (`text-sm`), mono, uppercase, `tracking-widest` | 600 (semibold) | 1.2 |
| Metadata (timestamps, ids, counts) | 12px (`text-xs`), mono | 400 (regular) | 1.5 |
| Page title (`PageHeader`, inherited component — not a new choice) | 24px (`text-2xl`) | 700 (bold) | 1.2 |

## Color

All values are CSS custom-property names — resolved per active theme, never a literal hex.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `var(--card)` | Page background, panel surfaces (`glow-card bg-card/60`) |
| Secondary (30%) | `var(--card)` + `var(--border)`, `var(--muted)` | Panel borders, table row dividers, the untraced-calls bucket background in `TraceWaterfall` |
| Accent (10%) | `var(--primary)` | **Reserved for:** the pulsing status dot in every panel header (existing `glow-card` convention), the active `ToggleGroupItem` in the source filter (D-02), the "View in Tools →" cross-link text/underline from Dashboard/Analytics panels (D-15), the active `OBSERVE → Tools` nav item, focus rings |
| Destructive | `var(--destructive)` / `var(--status-error)` | `malformed_policy_boot` badge only (the fully-permissive fail-open case — the most severe of the four policy kinds), failed-tool-execution status dot (existing `ToolExecutionPanel` red pulse) |

### Additional semantic tokens this phase depends on (not accent, not destructive — load-bearing for OBS-02's four-kind distinction)

| Token | Usage |
|-------|-------|
| `var(--status-warn)` | `tool_call_leaked_as_text` badge ("leaked as text" — concerning but not alerted); `malformed_policy_reload_rejected` badge (alert-worthy per D-06, but fails *safe*, not permissive — deliberately lighter than boot-degrade); the D-12 truncation notice banner |
| `var(--status-info)` | `execution_denied` badge — **must render as neutral/expected, not alarming**: D-06's own rationale is that a denial is the policy working correctly, and coloring it like a warning would train operators to ignore real signals |
| `var(--status-ok)` | Cache `HIT` badge (existing `TraceWaterfall.tsx` convention, unchanged), success-rate chart bars |
| `var(--info)` | Alias of `--status-info`, available if a component already imports it (e.g. `MetricCard`'s `severityConfig.info`) |

**Policy-kind → color is a locked mapping, not per-instance discretion** (CONTEXT.md: "the
boot-degrade vs reload-rejected distinction is load-bearing... never collapse the two"):

| Kind | Alert-worthy (D-06)? | Badge color | Badge label |
|------|----------------------|-------------|-------------|
| `malformed_policy_boot` | Yes | `var(--status-error)` | "Boot degraded to permissive" |
| `malformed_policy_reload_rejected` | Yes | `var(--status-warn)` | "Reload rejected — prior policy kept" |
| `tool_call_leaked_as_text` | No (view-only) | `var(--status-warn)` | "Leaked as text" |
| `execution_denied` | No (view-only) | `var(--status-info)` | "Blocked by policy" |

The two alert-worthy rows additionally render a small `Bell` icon (Lucide, already in
`iconComponents.bell`) with an `InfoTooltip` reading "This also raised an alert via the existing
alert-routing layer" — so an operator scanning the feed can tell, without leaving the page, which
rows already woke someone up.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None page-level — this is a pure observability page (view-only, per the phase boundary: "This phase observes and reports. It never enforces."). The nearest thing to a CTA is the cross-link *from* the three existing panels *into* this page: **"View in Tools →"** (link text, `text-primary`, matches D-15's "gain links into the new page"). |
| Source filter default label | **"Ástríðr"** (selected by default, D-02) — other `ToggleGroupItem` options: "Claude Code", "Gateway", "All sources". Never label the default option "All" — that is the specific mixed-ranking mistake D-02 exists to prevent. |
| Tool Usage empty state — heading | "No tool calls yet" |
| Tool Usage empty state — body | "Ástríðr's tool calls will appear here once the agent loop runs — no refresh needed." (verbatim voice match to `TraceWaterfall.tsx`'s existing empty state, lines 199-205) |
| Policy feed empty state — heading | "No policy events yet" |
| Policy feed empty state — body | "CodePulse has never received a tool-policy event from Ástríðr. Last received: **{relative time, or "never"}**." — the "Last received" clause is mandatory (D-07): it is what lets an operator tell later silence apart from a dead ingest pipe. Never render this section as if it were simply "healthy" with no data. |
| Truncation notice (D-12, both feeder queries capped) | "Showing the most recent **{cap}** of **{total}** — older rows aren't loaded. [Truncated in the time axis / list, not silently dropped.]" Rendered as a `var(--status-warn)`-tinted inline banner at the top of whichever section was capped, not buried in a tooltip. |
| Error state (both new panels + extended `TraceWaterfall`) | Reuse `SectionErrorBoundary` verbatim — "{name} failed to load" + the real error message + a Retry button. `name` props: `"Tool Usage"`, `"Tool Policy Events"`, `"Trace Waterfall"` (unchanged from existing mount). No new error copy pattern. |
| Destructive confirmation | **None.** This phase ships zero destructive or mutating UI actions by design (CONTEXT.md phase boundary: no tool disabling, no policy changes, no execution blocking — `toolGovernance.disabled` enforcement is explicitly deferred, not this phase's scope). |
| Page-level disclaimer (mirrors Phase 104's `CostBudgetsAdmin` "Budgets raise alerts. They don't stop work." pattern) | **"This page observes tool behavior. It never disables a tool, changes policy, or blocks a call."** — place at the bottom of the Policy feed section, `text-sm text-muted-foreground`, same treatment as the Phase 104 precedent. |
| Nested trace row (D-09, tool under LLM call) | Tool rows show `{toolName} · {durationMs formatted} · {success/failed}` — mirrors the existing `TraceCallRow` line format (`{model} · {cost}`), not a new row grammar. |
| Cache ratio on trace-group header (D-11) | Appended to the existing group header line: `Turn {n} · {count} · {duration} · {cost} · {cacheRatio}% cached` — same separator (` · `), same position pattern as `groupCostLabel` already occupies. |
