    ScopeRail renders a "Scope" section header (styled identically to "Categories") and three always-visible entries (Global/Project/Cold Storage) — NEVER gated on a nonzero count (a user must be able to drag into an empty Cold Storage). Props: { dropTargetScope: string | null; onDragOverScope(scope): void; onDragLeaveScope(): void; onDropOnScope(scope, e): void }. These are an INDEPENDENT prop set — never shared names/state with the Categories drop props (Pitfall 5). Per-entry visual state, mutually exclusive:
    - idle (no drag, or dragging but this entry is a no-op target): border-transparent hover:bg-accent/50 hover:border-border, no hint.
    - valid drag-over (this entry is the dropTargetScope AND resolveScopeDrop(draggingSkill, scope).kind is "enqueue" or "dialog"): bg-primary/30 border-dashed border-primary shadow-[var(--glow-sm)].
    - invalid drag-over (this entry is dropTargetScope AND kind === "reject"): border-dashed border-destructive/40 bg-destructive/5 cursor-not-allowed, AND render the reject hint (from resolveScopeDrop result) inline beneath the entry label.
    - no-op drag-over (kind === "noop"): treat as idle — NO highlight (D-02 honest no-op; do not flash a highlight for a drop that does nothing).
    Validity is computed from useDraggingSkill().draggingSkill via resolveScopeDrop; when draggingSkill is null the entry is idle. onDragOver calls e.preventDefault() then onDragOverScope(scope). onDrop calls e.preventDefault() then onDropOnScope(scope, e). The component calls NO mutation.
    Test cases: (1) all three entries render with correct labels/icons even when counts are zero; (2) with a mocked draggingSkill that is active-global and dropTargetScope="cold", the Cold entry has the valid primary highlight; (3) with a dormant draggingSkill and dropTargetScope="project", the Project entry has the destructive not-allowed classes AND renders "Restore to Global first, then move."; (4) with an active-global draggingSkill and dropTargetScope="global" (own scope → noop), the Global entry has NO highlight; (5) firing dragOver on an entry calls onDragOverScope with that scope and preventDefault; firing drop calls onDropOnScope with the scope + event.
  </behavior>
