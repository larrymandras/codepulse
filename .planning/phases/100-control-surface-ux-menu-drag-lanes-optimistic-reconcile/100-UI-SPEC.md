# Phase 100 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds no new visual primitives. It extends an already-mature, token-driven design system (Phase 89+ theme switcher) with exactly two new visual states — a **scope-rail drop target** (mirrors `CategoryGrid`'s existing highlight) and an **optimistic-pending row treatment** — plus a completeness audit of the existing ⋯ menu. Every color/spacing/type value below is either a direct rename of an existing token/class already in the codebase, or an explicit new pairing built from existing tokens. Nothing here introduces a new hex value, a new font, or a new component library.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` | Page background, list/rail surfaces |
| Secondary (30%) | `var(--card)` / `var(--border)` | Rail container, dropdown menu surface, row hover backgrounds, dividers |
| Accent (10%) | `var(--primary)` | See "Accent reserved for" below |
| Destructive | `var(--destructive)` | Delete Permanently menu item + confirm dialog (unchanged, Phase 98); invalid-drop scope-rail highlight (new, this phase) |

Accent (`--primary`) reserved for — explicit list, nothing else may use it:
1. Active/selected state on Categories and the new Scope rail entries (background `bg-primary/20`, border `border-primary`, glow `shadow-[var(--glow-xs)]`) — mirrors `CategoryGrid`'s `isActive` branch exactly.
2. **Valid** drag-over highlight on a scope-rail entry (dashed border + `bg-primary/30` + `shadow-[var(--glow-sm)]`) — mirrors `CategoryGrid`'s `isDropTarget` branch exactly. This is the *only* new use of `--primary` this phase introduces, and it is a direct reuse of an existing pattern, not a new one.
3. Row hover/focus accents (GripVertical, favorite/edit icon hover, ⋯ trigger hover) — unchanged from existing `SkillRow`.
4. "New Category"-style add affordances, count badges when active — unchanged.

Second semantic token — `var(--status-info)` (existing token, not new) reserved for **all optimistic-pending visuals** introduced by this phase:
1. The inline `RowStatusBadge` chip already rendered by `SkillLifecycleMenu` for `queued`/`executing` states (unchanged Phase 98 behavior, now also covers drag-triggered commands).
2. The new **pending row indicator** — see "Optimistic Pending Row" below — uses `--status-info`, never `--primary`, so a "this just moved but isn't confirmed yet" row is never visually confusable with a "this is the active/selected item" row.

`var(--destructive)` also reserved for the new **invalid-drop (not-allowed) highlight** on the Project scope-rail entry when a cold/dormant row is dragged over it (D-02's reject case) — `border-dashed border-destructive/40 bg-destructive/5`, distinct from both the valid-drop primary highlight and the plain hover state, and paired with `cursor-not-allowed`.

## Interaction States (Phase-Specific)

These states are the actual deliverable of this phase and are called out separately from the standard template sections because they are stateful/behavioral, not static tokens.

### 1. Scope rail (D-01)
- New section below Categories in the left rail, same visual grammar: section header identical in style to "Categories" (`text-xs font-mono font-bold text-primary/70 uppercase tracking-[0.2em]` + pulsing `--primary` dot), labeled **"Scope"**.
- Three always-visible rows: Global, Project, Cold Storage (icons `Globe`/`FolderGit2`/`Archive`, matching `DestinationBadge`). Each row's markup/hover/active/drop-target classes mirror `CategoryGrid`'s row exactly (`group relative flex items-center gap-3 w-full px-3 py-2 rounded transition-all border`).
- Drop-target states per row, mutually exclusive:
  - **Idle:** `border-transparent hover:bg-accent/50 hover:border-border` (identical to CategoryGrid idle).
  - **Valid drag-over:** `bg-primary/30 border-dashed border-primary shadow-[var(--glow-sm)]` (identical to CategoryGrid's `isDropTarget`).
  - **Invalid drag-over** (cold/dormant row over Project only, D-02): `border-dashed border-destructive/40 bg-destructive/5`, `cursor-not-allowed`, and renders the "Restore to Global first, then move." hint inline under the row label while this state is active.
  - **Own-scope / no-op drop:** no highlight change at all on `dragover` (treat identically to idle) — dropping is silently accepted with zero mutation and zero visual feedback, per D-02's "honest, no fake success" no-op rule. Do not flash a highlight for a drop that will do nothing.
- The Categories grid remains independently droppable (re-categorization, `handleDropOnCategory`) — no visual or DOM overlap with the new Scope rows.

### 2. Optimistic pending row (D-05)
- Because the Scope rail is a fixed sidebar (not a parallel column of skill rows), "moves to destination lane" means the row's **displayed state changes in place** within whichever list is currently rendering it (`AllSkillsOverview`, `SkillsInCategory`, or `ColdStorageView`) — it does not physically relocate across two simultaneously-visible lists.
- On drop, apply immediately to the affected row:
  - Opacity `70%` (distinct from the existing dormant-row `opacity-50`, so "pending" and "dormant" are never visually identical).
  - A pulsing left-edge indicator bar using `--status-info` (`bg-[var(--status-info)] shadow-[var(--glow-sm)] animate-pulse`), styled after `CategoryGrid`'s active glow bar but in the info color, not primary — this is the visual difference between "selected" and "pending, unconfirmed."
  - The existing `RowStatusBadge` chip (already rendered by `SkillLifecycleMenu` next to the ⋯ trigger) shows "Queued…" / "Executing…" — reused verbatim, not restyled.
- Reconciliation (status from `useLifecycleCommands`/`useLifecycle`, unchanged hook):
  - **done:** clear the pending overlay; the row's underlying membership already reflects the daemon rescan, so it naturally appears/disappears from the current filtered view without any special-cased fade-out.
  - **failed / expired:** clear the pending overlay (row visually "snaps back" to its pre-drag appearance since it never structurally left its list), fire the rollback toast (see Copywriting Contract).
- Optimistic state is client-only ephemeral (a local pending-moves map keyed by skill name, per CONTEXT.md's discretion note) — never written to Convex, never survives a page reload as "confirmed."

### 3. ⋯ menu completeness audit (D-06, UX-01/UX-04 — no new visuals)
- No new menu component or styling. Verify the existing `SkillLifecycleMenu` scope-gating (dormant / active-single-scope / active-multi-scope branches, already implemented) renders identically across `AllSkillsOverview`, `SkillsInCategory`, `ColdStorageView`, and is reconciled with `QuickDeck`.
- Verify no `/manage-skills` terminal-instruction string remains anywhere in the Cold Storage restore path (a test already asserts this — confirm it still holds after this phase's changes).
