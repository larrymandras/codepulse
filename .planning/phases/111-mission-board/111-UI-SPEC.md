# Phase 111 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Read this first:** this phase is a subtraction, not an addition. Its entire subject is UI honesty —
removing chrome and copy that claim a state `subagentJobs` cannot back (7 lifetime rows, none since
2026-07-07, zero `queued`/`running`, no join key). Nothing in this contract introduces new visual
language. **Do not apply the `sketch-findings-codepulse` "Borealis Console" redesign to this
phase** — that overhaul (aurora Signal Horizon, Pulse ECG, quiet-badge restyle, 11px eyebrow, etc.)
is explicitly held for milestone v15.0 and Phase 111 is v14.0. This surface keeps today's existing
token system, `EntityRow`/`StatusBadge`/`BlackboardPanel` visual conventions, and Tailwind default
type scale, unchanged in shape — only the copy, iconography map, and two consumer sites change.

### Row-level copy (replaces D-09's dual-meaning `formatElapsed`)

`formatElapsed` currently means "time since finished" for terminal rows and "elapsed since start" for
running ones, under one ambiguous label with no unit word. Since D-08 removes `queued`/`running`
entirely, every row remaining is terminal — so the function has exactly one meaning now, and must say
so explicitly:

| Age tier | Exact string |
|---|---|
| < 60s | `finished moments ago` |
| < 60m | `finished {m}m ago` |
| < 24h | `finished {h}h ago` |
| ≥ 24h | `finished {d}d ago` — **add this tier; it does not exist today.** Without it, the one real row 34 days old renders as `finished 816h ago`, which is technically correct but reads as a bug, not honesty. |

No upper cap on the day count — an honest large number (`finished 34d ago`) is correct behavior, not
a state to hide or round away.

### Header copy (D-10: remove live chrome, label as history)

| Element | Before | After |
|---|---|---|
| Eyebrow label | `BACKGROUND JOBS` + `<span className="w-2 h-2 rounded-full bg-primary animate-pulse" />` | `MISSION HISTORY` — **pulsing dot deleted, not recolored or made static.** No replacement glyph. |
| Count badge | `{n} jobs` | `{n} missions` |

Use "missions" in all rendered copy on this surface (header, empty state already says "missions",
row `secondary` text stays `job.agentTypeId` — unchanged, it's an identifier not prose). Backend
identifiers (`jobId`, `subagentJobs`, `useSubagentJobs`, the `JobsPanel.tsx` filename) are unaffected
— this contract governs rendered copy only, not code naming.

### Status treatment — "unknown" and any future status

`runtimeIngest.ts:616` can write `status: "unknown"` (or, in principle, any value the emitter sends).
The contract requires this render honestly, not as a plausible-looking known state:

- **`stateIcon` map** (`JobsPanel.tsx`): after D-08 removes `queued`/`running`, only `completed`,
  `failed`, `cancelled` remain as explicit keys. **Do not add an `"unknown"` key.** Any status not in
  the map — including `"unknown"` — must fall through to the existing default:
  `stateIcon[job.status] ?? <Clock className="h-3.5 w-3.5 text-muted-foreground/50" />` (muted,
  unfilled). This fallback already exists; preserve it as-is.
- **`StatusBadge`** (`src/components/StatusBadge.tsx`): **do not add an `"unknown"` entry to
  `legacyMap`.** An unmapped status must fall through the existing chain (`legacy?.semantic ??
  status` → `semanticStyles[resolvedSemantic] ?? semanticStyles.idle`) to the muted `idle` style with
  label `.toUpperCase()` (renders `UNKNOWN`). This is already the correct, honest behavior —
  the fix here is a **prohibition** (don't "improve" it into a colored mapping), not new code.

### Timestamp unit (preserve, do not remove)

`subagentJobs.submittedAt`/`finishedAt` are Unix epoch **seconds** (~1.78e9), not ms. `JobsPanel.tsx:40`'s
defensive `ref < 1e12 ? ref * 1000 : ref` normalization must be preserved in the rewritten
`formatElapsed`. Dividing by 1000 or omitting the guard produces 1970-epoch dates.

## Component Contract — Open Questions Resolved

CONTEXT.md left two questions to design time ("Claude's Discretion"), provided MISSION-03 holds.
Both are resolved here as locked contract, not left to the executor:

### D-07 resolution: delete `ActiveAgentsPanel` outright

**Decision: delete**, not re-source. `ActiveAgentsPanel.tsx`'s own code comment already surveyed the
only other candidate feed (`useSwarmGraph`) and rejected it as goal-scoped and identity-less. No
feed genuinely carrying agent liveness exists without astridr-repo work, which D-01 places out of
scope. Re-sourcing is therefore not achievable within this phase; deleting the permanently-false
panel is the only in-scope fix that satisfies D-07 and MISSION-03 ("absent, not fabricated").

- Delete `src/components/control-center/ActiveAgentsPanel.tsx`.
- Remove its mount at `Chat.tsx:1054` **and** the `<SectionErrorBoundary name="Active Agents">`
  wrapper around it (`Chat.tsx` ~1053-1055) — do not leave an empty boundary or a placeholder card
  in its place. `IntelligenceFeedPanel` becomes the sole occupant of the `cc-left-rail` flex
  container; no layout compensation is needed beyond what the existing `flex flex-col gap-2` rail
  already provides for a single child.
- Do not introduce any replacement affordance (empty card, "coming soon" tile, disabled panel) —
  per MISSION-03, the correct treatment of an unbuildable feature is **absence**, not a styled void.

### Mount/route: keep the existing mount, add no route

**Decision: no new route.** The history board stays mounted at `LiveRun.tsx:251` inside
`<JobsPanel />`'s existing container. Do not add a `src/lib/navRegistry.ts` entry (`iconComponents`
map + a `navGroups` item) for this phase.

Rationale: the surface holds 7 lifetime rows and D-01/D-11/D-12 deliberately keep this phase small —
a dedicated route would need nav registry wiring and would visually promote a surface whose entire
point this phase is to make quieter and more honest, not more prominent. `D-13` already forbids
naming collision with `MissionTimelinePanel` (`Chat.tsx:1124`); keeping the existing mount site sidesteps
that risk entirely rather than requiring a new distinct name for a new route/nav-label.
