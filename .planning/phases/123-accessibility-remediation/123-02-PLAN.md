<objective>
Build D-02's pass-2 measurement instrument: a shared, sentinel-guarded rasterisation module plus an
isolation spec that can measure any class string against any theme's real surface tokens and apply
D-03's font-metric-gated WCAG threshold. Prove the instrument works by making it flag a
deliberately sub-AA fixture (C3) alongside a known-passing element.

is meaningless until there is a trustworthy way to measure a threshold. It also carries C6, the
before/after control that inverted Phase 120's conclusion.
Output: `e2e/lib/contrast.ts` (new, extracted from Phase 122's already-hardened primitives),
`e2e/contrast-isolation.spec.ts` (new), and `e2e/theme-rendered-result.spec.ts` re-pointed at the
shared module.

    Create `e2e/contrast-isolation.spec.ts`. It renders class strings against real theme surfaces in
    a live page and rasterises the painted result — it does not compute anything from hex + alpha.
    Tailwind v4 compiles `/NN` to `color-mix(in oklab, var(--token) NN%, transparent)`, a perceptual
    mix that hex arithmetic cannot reproduce, which is why arithmetic is forbidden here.

    Structure:
    - A `CLASS_MATRIX` constant holding the 15 unique class strings listed in `<interfaces>` above,
      each with the surface token(s) it must be measured against. Default surface set is
      `["--background", "--card", "--popover", "--muted"]`; narrow a class's set only with a stated
      reason in a comment.
    - For each `theme x class x surface` cell: navigate with `gotoWithTheme`, paint the class on a
      probe element over the surface colour, sample with the shared `paintedColorOfClass` /
      `compositeSample`, read the surface with `getThemeTokenText`, and compute `contrastRatio`.
    - Emit every measured cell into a module-level array and write it to
      `e2e/.artifacts/123-isolation-pass2.json` at the end of the run (create the directory; add
      `e2e/.artifacts/` to `.gitignore` if not already ignored). Plan 123-07 consumes this file.
    - Each emitted row MUST carry `pass: "isolation"`. D-02 requires every ledger row to be labelled
      by which pass produced it; "measured" must never silently mean "calculated".
    - Threshold: apply a flat **4.5:1** at class level, because font size is a property of an
      occurrence, not of a class. Record the threshold used on every row. An occurrence may later be
      claimed under the 3:1 large-text allowance ONLY with a `readTextMetrics` reading attached —
      state that rule in the file's header comment.

    Assertions in this spec (this task ships the instrument and its controls, NOT the verdicts —
    the corpus verdicts are 123-07's job, so do not assert that every class passes):
    1. **C3 — the harness flags a sub-AA fixture.** Paint a deliberately sub-AA pairing (e.g.
       `text-muted-foreground/30` on `--background`, or an explicitly constructed near-identical
       pair) and assert the measured ratio is BELOW 4.5. In the same pass, paint a known-passing
       element (`text-foreground` on `--background`) and assert it is ABOVE 4.5. Both assertions in
       one test, so a harness that flags nothing and a harness that flags everything both fail.
    2. **Sentinel discipline.** Assert `sampleColor(page, "not-a-color-9x7q2")` returns exactly
       `null`, and that `sampleColor(page, "#ffffff")` returns `[255,255,255]`. A sampler that
       returns the previous fill on unparseable input is the documented `canvas.fillStyle` trap;
       this is the control that shows it is not happening. Every consumer must assert
       `.not.toBeNull()` rather than substituting a fallback.
    3. **`wcagThresholdFor` unit cases** from Task 1's acceptance criteria, all five.
    4. **C6 — before/after control.** Using the existing `extractPrePhaseToken` idiom (git-extracted
       pre-change values, `execSync`, anchored on an EXPLICIT SHA, never `HEAD~1` — a concurrent
       session can move `HEAD`), record the pre-123 painted colour of `text-muted-foreground/80`
       and `text-primary/60` on `--card` for all four themes into the same JSON artifact under
       `pass: "isolation-before"`. Capture the pre-123 SHA by running `git rev-parse HEAD` ONCE at
       implementation time and hard-coding the resulting 40-character SHA as a named constant with
       a comment saying what it anchors — do not resolve it dynamically at test time.
