dotenv, then **throws** if `CLERK_SECRET_KEY` is unset, then calls `clerkSetup(...)`. The skip-log
truncation must run BEFORE that throw, or a machine without `.env.local` never truncates the log.

`playwright.config.ts` already carries `globalSetup: './e2e/global-setup.ts'` and
`fullyParallel: true`, `workers: undefined` outside CI. `globalTeardown` is not present.

Playwright JSON reporter shape used by the self-test's assertions:
  { stats: { expected, unexpected, skipped, flaky },
    suites: [ { specs: [ { tests: [ { annotations: [{type,description}],
                                       results: [{ status }] } ] } ] } ] }
`--reporter=json` writes to stdout unless `PLAYWRIGHT_JSON_OUTPUT_NAME` is set; prefer setting
that env var to a file path so stdout noise cannot corrupt the parse.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test runner → local filesystem | The skip-log and the self-test fixture directory are files this repo's own test process writes and reads, under `e2e/`. No external input crosses this boundary. |
| CI/dev shell → Playwright process | Environment variables (`PW_BASE_URL`, `A11Y_SKIP_LOG`, `PLAYWRIGHT_JSON_OUTPUT_NAME`) are developer-supplied, not attacker-supplied. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-123-01 | Tampering | `e2e/.a11y-skip-log.txt` | mitigate | Truncated at run start in `global-setup.ts` so a stale or hand-edited log cannot silently fail a clean run or mask a dirty one; gitignored so it can never be committed as fixture state. |
| T-123-02 | Repudiation | fail-on-skip verdict | mitigate | The teardown's thrown error names the count AND each `theme__Page` identifier, so a red run states which cells were skipped rather than asserting an unattributable failure. |
| T-123-03 | Information disclosure | self-test child process env | accept | The child Playwright run inherits the parent env, which on a developer machine holds `CLERK_SECRET_KEY`. It is not logged, not written to the fixture, and not echoed in any assertion message. Same exposure the existing suite already has. |
| T-123-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this plan adds **zero** packages. `123-RESEARCH.md` § Package Legitimacy Audit records the same. No install task exists, so no legitimacy checkpoint is required. |

**Concurrence with `123-RESEARCH.md` § Security Domain:** confirmed after reading the files under
change. This plan touches only Playwright lifecycle hooks and a local log file. It introduces no
authentication, authorization, input-validation or cryptography surface, changes no network-facing
route, and adds no dependency. `AuthGuard.tsx` is **read** as a text file for a string assertion and
is not modified. The threats above are recorded for completeness, not because a new attack surface
was found.
