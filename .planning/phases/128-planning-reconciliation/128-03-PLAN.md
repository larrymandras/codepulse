<objective>
Bring the nine seed files and the dissolved carried-forward list into agreement with what the
repository actually contains.

Two mechanisms depend on this. `/gsd-new-milestone` scans seeds to propose work; a seed that still
reads `dormant` after its content became a scoped v16.0 requirement will be re-proposed as new
work, which is how the same idea gets planned twice. And RECON-03 requires that no item from the
old carried-forward list survives as an unowned note — an item owned by nobody is an item nobody
re-derives.

D-08 introduces `status: absorbed` with an `absorbed_by:` field precisely so that "already on a
roadmap" is distinguishable from "built" and from "still just an idea". D-09 supplies a mapping —
which per D-04 is a hypothesis to re-verify, not a patch to apply.

Purpose: after this plan, the seed corpus and the requirements file answer "what is still an
unscoped idea?" truthfully.

Output: `128-SEED-RECONCILIATION.md`, nine updated seed files, any corrections to REQUIREMENTS.md's
carried-forward disposition table, and `checks/seed-status.mjs`.
</objective>
