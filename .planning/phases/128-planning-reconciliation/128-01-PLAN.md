<objective>
Re-derive, against the code, the five "this is already fixed" claims that RECON-01 rests on, and
move each todo to the disposition the CODE supports — not the disposition the scoping sweep filed.

Four of these carry `resolves_phase: 128` (the folded todos). The fifth,
`unbounded-analytics-scans-timeout.md`, is here because REQUIREMENTS.md contains an internal
contradiction that must be settled by this phase rather than inherited:

- RECON-01's prose lists "unbounded analytics scans" among the eight known-already-fixed items.
- The same file's FIX-01 records a LIVE unbounded read at `convex/metrics.ts:19` and assigns it to
  Phase 129, and the todo itself is tagged `resolves_phase: 129`.

Both cannot be true. Per D-05 the disagreement is a FINDING to record with evidence, not an error
to quietly fix in passing.

Purpose: todos get CLOSED on these five claims. If a claim is wrong, a live defect disappears from
the tracker — which is the exact failure mode Phase 128 exists to end.

Output: `128-TODO-CLOSURES.md` (the adjudication ledger), the five todo files at their re-derived
dispositions, and `checks/closed-todos.mjs` (a structural guard on closure frontmatter).
</objective>
