## Design decisions, made here so the executor does not relitigate them

**1. The completion commit is THE COMMIT THAT FLIPPED THE ROADMAP PROGRESS ROW TO `Complete`.**

D-03a leaves this open and requires the pick to be justified and named in the failure message. The
pick and its reasons:

- It is the event the property is actually about. "Since the phase shipped" means since the repo
  DECLARED it shipped, and that declaration is the ROADMAP row. It is also the exact predicate the
  sibling Pending-on-Complete check already keys on — two checks in one file keying on two
  different notions of "complete" is precisely the drift this file exists to prevent.
- The alternative, the phase's last `*-SUMMARY.md` commit, is both gameable and ill-defined. Any
  later commit touching the phase directory — a typo fix, an evidence document, a gap-closure
  summary — moves the anchor and re-reds a Partial that is genuinely fresh. And a phase with no
  summaries on disk has no anchor at all, which is not hypothetical here: this repo's own notes
  record that 117 of 119 phases carry phase-level summaries and that a naive `*SUMMARY.md` count
  reads 62 against a correct plan-level count of 60.

**State the trade-off honestly in the header, do not hide it:** neither candidate catches staleness
introduced by work in a DIFFERENT phase, which is the shape v15.0 actually suffered. This check's
scope is "nobody has looked at this cell since its own phase closed". Say that; do not let the
header imply more coverage than the mechanism has.

**2. Resolution is a bisect over ROADMAP.md's own history, not a pickaxe.**

`git log -S` needs an exact string, and the Progress row's text changes with plan counts and notes,
so a pickaxe is brittle. Instead: list ROADMAP.md's revisions oldest-first with
`git log --format=%H --reverse --follow -- .planning/ROADMAP.md`, and binary-search on the
predicate "in `git show <rev>:.planning/ROADMAP.md`, phase N's Progress row reads `Complete`". The
predicate is monotonic once true, which is what makes the bisect valid — and that assumption must
be CHECKED, not assumed: if the OLDEST revision already satisfies it, the flip predates ROADMAP.md's
recorded history and the resolver must return unresolvable, not a guess. About ten `git show` calls
per phase, and only for phases that actually carry an in-range `Partial` — today, none.

**3. The ancestry comparison closes all three branches, not two.**

STALE iff the stamp is NOT the completion commit AND `git merge-base --is-ancestor <stamp>
<completion>` exits 0. Fresh iff the stamp equals the completion commit (a re-derivation recorded
IN the closing commit does not predate it) or `is-ancestor <completion> <stamp>` exits 0, i.e. the
stamp is a descendant. If NEITHER direction holds, the two commits are on unrelated history —
a stamp copied from another repo, or history that has been rewritten — and that is an OFFENDER, not
a pass. A two-way comparison where only one direction is tested silently defaults its residue to
green.

**4. Everything indeterminate is loud.** Missing stamp, unresolvable stamp SHA, unresolvable
completion commit, shallow repository, unrelated history — each is its own offender with its own
message naming the specific remedy. A check that cannot establish freshness must never report
freshness.

**5. Grandfathering: decided in Task 1 from a re-measured population.** If the in-range `Partial`
count is zero, no allowlist is added and that fact goes in the header. If it is non-zero, add one
following `convex/boundedReads.ratchet.test.ts:152`'s shape, which asserts each entry still has a
real hit so a stale allowance fails rather than decaying into a rubber stamp.

**6. Stamp syntax in the cell:** the `Partial` status cell carries `re-derived <sha>`, with at
least 7 hex characters, e.g. `| FOO-01 | Phase 123 | Partial — X shipped, Y deferred (re-derived
a1b2c3d) |`.
