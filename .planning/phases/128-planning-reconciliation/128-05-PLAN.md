<objective>
Make the RECON-04 mechanism actually reachable where it matters, and prove it fires against the real
files.

Plan 128-04 built the check and its controls. Two things remain, and both are the difference between
a mechanism and a mechanism-shaped object:

**The CI job cannot run it as configured.** `.github/workflows/ci.yml:12` uses
`actions/checkout@v7` with no `fetch-depth`, which defaults to 1 — a shallow clone with no history.
`git merge-base --is-ancestor` cannot answer there. 128-04's shallow-repository branch means this
fails loudly rather than silently passing, which is correct behaviour but is not a working check.
The sibling `.github/workflows/gitleaks-scan.yml:22` already sets `fetch-depth: 0`, so the repo
knows the flag; the ratchet's job simply never needed history before.

**The in-file controls cannot prove the parsers reach the real documents.** Fixtures prove the
FUNCTION discriminates. Only a mutation of the actual `.planning` files proves the row formats are
matched, the collectors join, and the failure surfaces. ROADMAP criterion 4 asks for exactly that:
"a mutation that sets exactly that state and watching the test go red, then reverting".

Purpose: close the gap between "the logic is right" and "the guard fires in the places it is
supposed to guard".

Output: the CI workflow change and `128-RATCHET-EVIDENCE.md`.
</objective>
