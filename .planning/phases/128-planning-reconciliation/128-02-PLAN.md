<objective>
Re-derive the thirteen pending todos that plan 128-01 does not own, and give each the disposition
the code supports.

This is the half of RECON-01 that is easy to fake and therefore easy to get wrong. Closing a todo
takes evidence and everyone knows it. KEEPING one open takes no effort at all — which is exactly
how a fixed defect sits in `pending/` for months. D-06 sets the SAME bar in both directions: a todo
that stays open cites the `file:line` proving the defect is still there.

Five of these thirteen describe visual or timing behaviour that reading code cannot settle. Per
D-07 those get an explicit `requires live measurement — deferred to Phase NNN` line naming the
owning phase. An honest recorded gap. Do NOT invent a static proxy for a visual defect — a
plausible-looking grep that stands in for a screenshot is worse than an admitted gap, because it
reads as evidence.

Purpose: after this plan, `.planning/todos/pending/` is a list of things that are actually still
wrong, each with proof, and the reader can tell which entries were settled by reading and which
are waiting on a measurement.

Output: `128-TODO-OPEN-EVIDENCE.md`, thirteen updated todo files, and `checks/open-todos.mjs`.
</objective>
