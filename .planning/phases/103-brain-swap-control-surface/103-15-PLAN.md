<objective>
Close the regression that 103-14 introduced, found during the 103-13-T1 live re-verification
(2026-07-29).

103-14 correctly changed "Revert global swap" from *clear the override* to *restore the override
that preceded this swap*. But `priorOverrideRef` is null only when no override was in force at
swap time, so once ANY global override exists every revert lands on another override. Combined
with `BrainControl.dispatchSelection(value, restore = false)` — whose `restore` parameter exists
but which no UI entry ever passes `true` — there is now NO user-reachable path back to Auto.

Evidence: during the live checkpoint the operator-driver had to bypass the UI entirely (sending
`swap.set restore:true` over the app's own socket) to return the stack to its
`model_override: null` baseline. Before 103-14 the path existed: swap → revert → cleared.

This plan restores that capability as an explicit affordance rather than as a side effect of
revert, so both behaviors can coexist: revert means "undo my last swap", clear means "stop
overriding".
</objective>
