**Two-axis global swap — read this before writing any code.**

CONTEXT.md's 2026-07-28 correction makes `All profiles` dispatch the LIVE, shipped
`swap.set { target: "brain" }` (a process-wide runtime override at router rung 1b). D-11 and D-12,
which were NOT superseded, describe per-profile persisted defaults being overwritten, recorded,
and partially failing per row. Both are true at once, so a global swap has TWO effects and this
modal fires both:

1. **Live global runtime override** — one `swap.set` command over the existing WS transport. This
   is the shipped, live path. It is NOT stubbed and carries NO stub indicator.
2. **Per-profile pinned-default fan-out** — N `gateway.model.set` commands with `mode: "default"`,
   one per profile, through the `brainsApi` seam, aggregated with `Promise.allSettled`. This is
   the stub-backed per-profile axis and its result rows DO carry the stub indicator.

Effect 1 without effect 2 would leave every profile's persisted default untouched, so a restart
would silently undo the "global" swap — and D-11's pinned-default warning would be factually
wrong. Effect 2 without effect 1 would contradict the binding D-08 amendment. Fire both.

Copy consequence: the pinned-default warning must describe what actually happens. Use the
UI-SPEC's copy for the overwrite case, since effect 2 genuinely overwrites the persisted default.
</planner_reconciliation>

with an `AlertTriangle` icon: the pinned-default count line, and — when the target's `costTier` is

**Snapshot before dispatch (D-10/D-11).** Capture, in component state, each profile's prior model
AND its prior mode. Pin status is part of the snapshot, not an afterthought — a revert that
restores the model but not the pin status is indistinguishable from a naive "restore last known
model", which is exactly what D-11 exists to prevent.

**Dispatch — both axes (see `<planner_reconciliation>` above).** Fire the live global
`swap.set { target: "brain", value: entry.id, restore: false }` through the WS sender, and in
parallel fan out `brainsApi.dispatchSwap({ scope: "profile", profile_id, model: entry.id,
mode: "default" })` per profile aggregated with `Promise.allSettled`. Do NOT build or call a
server-side batch command — the contract explicitly forbids one. Do NOT pass a `successMsg` to
`useCommandDispatch().dispatch` — an "ok" ack means accepted, not switched (D-14).

**Result state, in place (D-12).** The same Dialog shell transitions rather than closing: each row
resolves to a `Check` in `--status-ok` with the new engine, or an `X` in `--status-error` with the
inline failure reason AND its real, unchanged engine still displayed. Never render the attempted
target on a failed row. No all-or-nothing rollback — a rollback that itself fails produces a worse
state. Footer becomes a single `Done`.

**Dismiss and revert (D-10).** On dismiss, fire a `sonner` summary toast per the Copywriting
Contract with an action button labelled "Revert global swap". Revert dispatches
`swap.set { target: "brain", restore: true }` (the shipped restore idiom) plus a per-profile
fan-out restoring each snapshot entry's model with its snapshot mode. A revert that itself
partially fails reuses this same result-state row list. The revert offer persists until superseded
by the next swap.

**Stub honesty (D-16).** The per-profile result rows carry the dashed `STUB` chip when
`BRAINS_STUB_ACTIVE` is true. The global `swap.set` outcome is live and must NOT be marked stub —
labelling live data as stub is its own honesty failure.

Styling: every color from CSS vars (`--status-ok` / `--status-warn` / `--status-error` /
`--destructive` / `--primary`), Lucide icons only, no hardcoded hex, no `text-[10px]`.
