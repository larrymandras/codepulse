<objective>
Close code-review finding WR-01 (2026-07-29, `103-REVIEW.md`), confirmed still present by
`103-VERIFICATION.md`.

103-12's CR-03 fix made the `GlobalSwapModal` instance survive "Done" so a later "Revert global
swap" toast click reopens a live instance. But that guarantee only holds for the lifetime of the
**hosting `BrainPicker`**. There are two hosts:

  - `BrainHeaderBadge` → mounted in `DashboardLayout.tsx:583`, which wraps every route — survives
    navigation.
  - the Chat composer pill → `Chat.tsx:155`, which is **page-scoped** and unmounts on route change.

So: start a global swap from the Chat composer pill, click Done, navigate away from `/chat`, then
click "Revert global swap" in the still-visible sonner toast. The toast action fires a real
`swap.set` — a genuine, process-wide mutation of the running Ástríðr — with **zero UI feedback**,
which is a narrower reproduction of exactly the symptom CR-03 closed.

The fix is ownership, not another guard: hoist the modal (and therefore the revert closure) above
the router outlet so it cannot be unmounted by navigation.
</objective>
