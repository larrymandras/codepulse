<objective>
Close gap Group B (defect #5 + CR-03, BSC-04): `GlobalSwapModal` reports failure for a global swap
that actually succeeded, and its revert affordance fires real commands into an unmounted component.

Purpose: two defects in one component and one result-reporting code path.

  1. `GlobalSwapModal.tsx:154` fires the real, live, working `swap.set` and throws its result away
     with `.catch(() => {})`. The result rows are populated exclusively from a `Promise.allSettled`
     fan-out of N `gateway.model.set` calls (159-169) — the astridr-Phase-184.1-deferred per-profile
     command, which on a real live swap fails with `union_tag_invalid` for every profile, every
     time. Net effect on the live stack: the modal reported 0/N failure for a swap the operator
     independently confirmed had landed. This directly violates `103-CONTRACT.md` §8: "'All
     profiles' scope in the Phase 103 UI dispatches the existing live `swap.set` (global axis), not
     N `gateway.model.set` calls."

  2. `handleDismiss()` (behind "Done", the NORMAL completion path) builds the "Revert global swap"
     toast action closing over `runRevert()`, then calls `onOpenChange(false)`. `BrainPicker`
     responds by `setGlobalTarget(null)`, which unmounts the modal on the next render via its
     `{globalTarget && (...)}` guard. A later Revert click runs `runRevert()` against a dead fiber:
     every `setPhase`/`setResults` is a no-op, `onOpenChange(true)` does nothing because
     `BrainPicker` only reacts to `false`, and the modal never remounts — yet
     `dispatch({type:"swap.set", restore:true})` DOES fire for real, with no dialog, no rows, and
     (no `successMsg` passed) no toast at all.

Also folds in WR-02, which lives in the same `BrainPicker.tsx` lines this plan already edits.

Output: a modal that reports the outcome of the command it actually sent, and a revert that renders.
</objective>

<planner_reconciliation>
Two locked decisions need explicit reconciliation, recorded here so the executor does not think it
is quietly dropping them.

**D-12 (honest per-profile partial-failure rows).** D-12 was written for a world where a global
swap is N per-profile commands. Contract §8 — the D-17 deliverable, and the authority
`103-VERIFICATION.md` cites — settles that "All profiles" scope sends exactly ONE command. One
command has one outcome; there is no partial state to misreport. Reporting that one outcome
honestly IS D-12 applied correctly to this axis. D-12's N-row surface remains the right design for
the per-profile axis when astridr Phase 184.1 ships; the code for it is not being deleted from the
codebase's history, it is being removed from the path where it produces a guaranteed lie.

**D-11's confirm-modal copy.** D-11 says the modal flags "N profiles have pinned defaults that will
be overwritten." Once the fan-out is removed, a global swap no longer overwrites any pinned default
— it SHADOWS them, because the global override resolves at rung 2 and a per-profile default at
rung 4 (`103-CONTRACT.md` §9). Keeping the word "overwritten" would make the confirm modal state a
falsehood, which is the exact failure class BSC-04 exists to prevent. The count and the `Pin` icons
stay (D-11's "recorded" half is untouched); only the verb changes to describe what actually
happens. This copy change is flagged to the developer in the planning return — if the intent was
literally to overwrite pinned defaults, that requires the per-profile axis to be live and belongs
in a post-184.1 phase, not here.
</planner_reconciliation>
