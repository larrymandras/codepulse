## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet device → Convex public function surface | Any device that can route to the self-hosted host can call any **public** Convex function with no credential (measured 2026-08-11). Nothing in this plan adds a public function. |
| operator CLI → `internalMutation` | `backfillTokenSplit` is an `internalMutation`; it is reachable only via `npx convex run` with an admin key, not from the browser or an anonymous HTTP caller. |
| cron scheduler → `computeHourly` | Unattended, once hourly. A throw here fails the whole cron and triggers a retry storm. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-121-01 | Tampering | `insertTokenSplitBuckets` `calls` accumulator | mitigate | Own per-dimension-key idempotency guard via a separate `insertMissing("calls", …)` call; insert-only (never patch/delete); proven by a twice-run test plus a reverted shared-guard mutation. |
| T-121-02 | Denial of Service | `backfillTokenSplit` after de-latching | mitigate | `maxHours` default stays 6; per-hour `llmMetrics` read stays capped at `LLM_WINDOW_READ_CAP = 4000` with truncation reported; NOT registered in `convex/crons.ts`; operator-driven with an explicit `done` stop condition. | T-121-03 | Denial of Service | live `aggregates` table growth | accept | `calls` adds roughly one row per active dimension key per hour, the same magnitude as the existing `tokens` metric. `convex/retention.ts` already prunes `period: "hourly"` at 90 days and keeps `period: "daily"` forever; no new retention rule is needed. |
| T-121-04 | Tampering | mass mutation of a large live table | mitigate | Every write in this plan is a single-row `ctx.db.insert`. No bulk delete, no bulk patch — the harness throws on `db.patch`/`db.delete`, which is asserted rather than assumed. |
