<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| working tree → live production backend | `npx convex deploy` pushes code that will delete rows from a live single-node SQLite instance on tonight's cron. Irreversible in the direction that matters. |
| live production instance → committed evidence file | CLI and deploy transcripts are pasted verbatim into a git-tracked file. |
| operator authorization → outward action | The deploy is the one genuinely outward-facing step in this phase. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-110-04-01 | Denial of Service | live `convex-backend` under baseline probing | mitigate | A `>30d` `aggregates` probe at `take(5001)` returned `SystemTimeoutError` on 2026-08-10; unbounded reads on this table are already near the edge, and per upstream `#495` this backend materializes the whole matched range before truncating. Mitigated by capping every probe at `take(1000)`, using the index-served `by_period_bucket` with the first component pinned, and forbidding a retry at a larger `take` when a probe times out. |
| T-110-04-02 | Tampering | production data via deploy | mitigate | The deployed change makes a previously-unpruned table prunable, so a defect deletes cost history irreversibly. Mitigated by the blocking operator checkpoint before the deploy, by the pre-deploy oldest-daily baseline that makes any such deletion detectable in plan 110-06, and by the mutation-tested predicate guard from plan 110-03. The `--dry-run` in the checkpoint is a required read of what is actually being pushed, not a formality. |
| T-110-04-03 | Spoofing | wrong deployment target | mitigate | The retired cloud deployment is still reachable by name, and an empty or successful result from it is a convincing false reading — this exact confusion has cost days on this project before. Mitigated by requiring the printed target URL `127.0.0.1:3210` in both the checkpoint and the deploy transcript. |
| T-110-04-04 | Information Disclosure | `110-DUR-EVIDENCE.md` | mitigate | `npx convex` invocations carry an admin key and `npx convex env list` prints full `NAME=VALUE` against this self-hosted backend. Mitigated by the redaction preamble, by eliding credential arguments in every pasted command, by forbidding `env list` by name, and by a credential-shape scan before commit. |
| T-110-04-05 | Repudiation | deploy provenance | mitigate | The evidence file records the git SHA in its header and the acceptance criteria require it to match `git log -1 --format=%H` at deploy time, so a later reader can tell exactly which code produced the observations rather than inferring it from dates. |
| T-110-04-SC | Tampering | npm/pip/cargo installs | accept | No packages installed. `npx convex` resolves the version already pinned in this repo's lockfile, which is unchanged. |
</threat_model>
